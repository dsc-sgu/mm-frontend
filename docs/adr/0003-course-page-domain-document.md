# Course Page хранится как собственный доменный документ, а не как Plate JSON

Содержимое Course Page хранится как документ, которым владеет проект. Документ не зависит от редактора: это плоская последовательность блоков в канонической форме, у каждого блока есть `BlockId` и версионированный `data`. Plate value существует только внутри editor adapter (`toPlate`/`fromPlate`), а read-only строит из документа собственное render tree. Так формат, который лежит в базе backend, не меняется при обновлении Plate. Каноническая форма даёт `planDraftSync` детерминированное сравнение. Семантическое дерево списков в read-mode выводится из того же документа, что и плоское представление редактора.

## Considered Options

- **Plate-native JSON, как `ReviewTextDocument` для review-текста (#109).** Без adapter, и редактор и readonly используют один профиль. Отвергнуто:
  - у review-текста один компактный blob без поблочной синхронизации, а у Course Page есть блоки, которые синхронизируются по одному;
  - обновление Plate — самый рискованный cohort зависимостей, и с этим вариантом оно меняло бы persisted-формат;
  - ссылки на Task, картинки и файлы — доменные понятия, а не узлы Plate.
- **Группирующий list-блок `{ items[] }` со скрытым id списка.** Отвергнуто: id списка не влияет ни на что видимое пользователю (#74), но сериализация режет по нему списки, создаёт дубли id и расхождения нумерации между editor и read-only. Каждый list item поэтому стал отдельным блоком, а группировка и нумерация выводятся по соседству.

## Consequences

- Редактор может создавать только те состояния, которые документ способен сохранить. Профиль Plate ограничен, и сериализация ничего не «исправляет» молча.
- Inline-текст хранится без id: соседние фрагменты с одинаковыми marks слиты, тип ссылки выводится из URL. Поэтому равенство документов — обычное структурное сравнение.
- Порядок задаётся массивом. Позиции (LexoRank) и отображение на `(blockType, data)` backend остаются заботой transport/sync.
- Неизвестный тип или неизвестная версия блока: read-only показывает заглушку, редактор не открывается. Блоки, которые редактор не понимает, никогда не перезаписываются.

Решение принято в [«Спроектировать structured-document seam Course Page»](https://github.com/dsc-sgu/mm-frontend/issues/119).
