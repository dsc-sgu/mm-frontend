# Страница курса хранится как собственный доменный документ, а не как Plate JSON

Содержимое страницы курса хранится как документ, которым владеет проект. Документ не зависит от редактора: это плоская последовательность блоков в канонической форме, у каждого блока есть `BlockId` и версионированный `data`. Значение Plate существует только внутри адаптера редактора (`toPlate`/`fromPlate`), а режим чтения строит из документа собственное дерево рендера. Так формат, который лежит в базе бэкенда, не меняется при обновлении Plate. Каноническая форма даёт `planDraftSync` детерминированное сравнение. Семантическое дерево списков в режиме чтения выводится из того же документа, что и плоское представление редактора.

## Рассмотренные варианты

- **Нативный JSON Plate, как `ReviewTextDocument` для текста проверки (#109).** Без адаптера, редактор и режим чтения используют один профиль. Отвергнуто:
  - текст проверки — один компактный объект без поблочной синхронизации, а у страницы курса есть блоки, которые синхронизируются по одному;
  - обновление Plate — самая рискованная группа зависимостей, и с этим вариантом оно меняло бы хранимый формат;
  - блоки заданий, картинки и файлы — доменные понятия, а не узлы Plate.
- **Группирующий блок списка `{ items[] }` со скрытым id списка.** Отвергнуто: id списка не влияет ни на что видимое пользователю (#74), но сериализация режет по нему списки, создаёт дубли id и расхождения нумерации между редактором и режимом чтения. Поэтому каждый пункт списка стал отдельным блоком, а группировка и нумерация выводятся по соседству.

## Последствия

- Редактор может создавать только те состояния, которые документ способен сохранить. Профиль Plate ограничен, и сериализация ничего не «исправляет» молча.
- Строчный текст хранится без id: соседние фрагменты с одинаковыми marks слиты, тип ссылки выводится из URL. Поэтому равенство документов — обычное структурное сравнение.
- Порядок задаётся массивом. Позиции (LexoRank) и отображение на `(blockType, data)` бэкенда остаются заботой транспорта и синхронизации.
- Неизвестный тип или неизвестная версия блока: режим чтения показывает заглушку, редактор не открывается. Блоки, которые редактор не понимает, никогда не перезаписываются.
