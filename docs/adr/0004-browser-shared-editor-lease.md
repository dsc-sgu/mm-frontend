# Lease принадлежит браузеру, вкладки делят редактор локально

Review Lease и Course Editing Lease принадлежат auth session, то есть браузеру, а не вкладке. Клиентского `leaseId` нет. Вкладки одного браузера договариваются между собой. Пишет одна вкладка, остальные показывают живую копию Working Copy только для чтения. «Продолжить здесь» передаёт Working Copy локально, без сервера: добровольно, если пишущая вкладка отвечает, или силой, если она молчит 3 с. Кто пишет, определяет запись `{epoch, writer}` в localStorage. Каждая смена увеличивает счётчик, и пишущая вкладка синхронно сверяет его перед каждой записью на сервер. Web Lock выбирает следующую пишущую вкладку и сообщает, что прежняя закрылась. Живая копия получает полную Working Copy после каждого изменения, поэтому силовая смена не теряет правок, сделанных в браузере.

## Considered Options

- **Lease на вкладку с клиентским `leaseId`.** Так было в [«Спроектировать Review → Grade → Student result vertical»](https://github.com/dsc-sgu/mm-frontend/issues/116) и [«Спроектировать lifecycle Course Page Working Copy»](https://github.com/dsc-sgu/mm-frontend/issues/118): вторая вкладка открывалась только для чтения, а «Продолжить здесь» перехватывало lease на сервере. Смене была нужна сеть, а несинхронизированная Working Copy оставалась в старой вкладке. Отвергнуто в [«Спроектировать матрицу тестовых контрактов критических вертикалей»](https://github.com/dsc-sgu/mm-frontend/issues/120).
- **Живая копия получает изменения, а не полную Working Copy.** Меньше данных, но понадобились бы обнаружение пропусков и второй формат помимо состояния. Отвергнуто.
- **После закрытия пишущей вкладки копии только предлагают «Продолжить здесь».** Пока Teacher не выбрал, heartbeat никто не шлёт, а правки лежат в памяти копий без защиты от ухода. Отвергнуто: копия продолжает сама.

## Consequences

- Сервер не различает вкладки одного браузера. Запрос, отправленный замороженной вкладкой до силовой смены, может прийти после записей новой пишущей вкладки. Для Course Page это закрывает проверка revision черновика на backend (`409`). Без неё на силовом пути остаётся узкое окно молчаливой перезаписи (см. [«Реестр frontend-вопросов к backend API»](https://github.com/dsc-sgu/mm-frontend/issues/113)). Публикации Review это не грозит: повтор с тем же ключом идемпотентен.
- Сразу после разморозки вкладки счётчик должен читаться синхронно и в актуальном значении. Это допущение о браузерных движках; его проверяет real-browser контракт TAB-08 в Chromium, Firefox и WebKit.
- `423` с holder, который совпадает с самим User, всегда означает другую сессию: другое устройство или приватное окно. Свою вкладку этого браузера видно локально, без сервера.
- Канал, lock и запись привязаны к `UserId` и ресурсу. Выход из аккаунта в любой вкладке останавливает запись во всех вкладках браузера.

Решение принято в [«Спроектировать смену пишущей вкладки редактора»](https://github.com/dsc-sgu/mm-frontend/issues/132).
