# PROTOTYPE #181: настройка Task и дедлайнов

Throwaway-код на ветке `prototype/task-and-deadline-settings`. В `main` не вливается. Отвечает на вопрос [#181](https://github.com/dsc-sgu/mm-frontend/issues/181): где Teacher правит свойства Task и все дедлайны Course, как применяются правки и как выглядит массовый сдвиг.

Это первая ступень общей песочницы. [#190](https://github.com/dsc-sgu/mm-frontend/issues/190) (Task Groups) и [#191](https://github.com/dsc-sgu/mm-frontend/issues/191) (маски путей) достраивают её на той же ветке.

## Запуск

```bash
VITE_MOCK_BACKEND=true bun run dev
```

Вход выполнен заранее под `mit-teacher`. Курс — «Современные информационные технологии». Состояние живёт в памяти, перезагрузка страницы возвращает fixture.

## Варианты

Плавающая панель внизу переключает варианты стрелками или клавишами ←/→ и переходит между маршрутами.

| `?variant` | Маршрут                                                        | Что это                                                                                                                          |
| ---------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `overlay`  | `/courses/modern-information-technologies?variant=overlay`     | Панель Task поверх Course Page: ширина документа не меняется; разделы карточками (`cards`) — как Details у Jira и Fields у Asana |
| `dock`     | `/courses/modern-information-technologies?variant=dock`        | Панель рядом: документ перестраивается                                                                                           |
| `A`        | `/courses/modern-information-technologies/deadlines?variant=A` | Раздел «Дедлайны»: матрица «Task × Student Group»                                                                                |
| `B`        | `/courses/modern-information-technologies/tasks?variant=B`     | Список Task и боковая панель дедлайнов                                                                                           |
| `C`        | `/courses/modern-information-technologies/edit?variant=C`      | Чипы дедлайнов на Task Reference в редакторе, правка в popover                                                                   |
| `D`        | `/courses/modern-information-technologies/deadlines?variant=D` | Таймлайн, сдвиг перетаскиванием                                                                                                  |

Маршруты `/deadlines` и `/tasks` без `?variant` не существуют.

## Переключатели «Песочницы»

- `?apply=instant|batch` — каждое значение сохраняется сразу (статус рядом с кнопками страницы) или копится: полоса «Не применено: N», затем «Проверить и применить» с таблицей «было → стало», где отдельные строки можно оставить неприменёнными.
- `?taskApply=course|task|contract` — правка Task идёт через Course Draft Snapshot (A), отдельной публикацией Task с проверкой версии (D) или по контракту из [#129](https://github.com/dsc-sgu/mm-frontend/issues/129) (`contract`, раздел ниже).
- `?deadlineField=full|counter` — в панели под свойствами блок со всеми переопределениями Task и ссылкой на страницу дедлайнов (по умолчанию), или только общий Deadline и «Переопределений: N».
- `?statement=panel|inline|expanded` — условие правится в панели, в документе или в развёрнутой панели.
- `?picker=split|stack` — окно даты в ячейке, панели и чипе: `split` (по умолчанию, выбран) — календарь слева, время, сдвиги и «Без дедлайна» справа, шириной 544 px и примерно на треть ниже; `stack` — всё в столбик шириной 288 px. В обоих: задание мелко над названием уровня, месяц слева и стрелки справа, сегодня — точкой, каждый месяц в шесть строк, чтобы окно не меняло высоту; время — текстовое поле 24 ч («1830» и «18.30» тоже понимаются), пояс рядом с ним; у сдвигов видно, на какой день они ведут; календарь переходит к месяцу новой даты. «Сбросить» в шапке появляется у неприменённого значения и возвращает применённое.
- `?panelLook=list|cards` — разделы панели Task: `list` (по умолчанию, выбран) — через линии во всю ширину, `cards` — карточками с заголовком, как у Jira и Asana. В обоих: название сверху, подписи свойств одной ширины, строки одной высоты; «Открытие» и «Общий дедлайн» — в разделе «Дедлайны» вместе с подгруппами и личными (при `?deadlineField=counter` остаются в свойствах); «Подгруппы» и «Личные переопределения» — мелкие подзаголовки; у наследующей подгруппы «↳ как общий» вместо повтора даты; корзина личного — при наведении; у балла нет стрелок, у группы один шеврон и «О группе» отдельной кнопкой; статус — плашкой в шапке.
- Course Access State `open`/`draft` (по умолчанию `open`) и сценарии 3–6 из таблицы #181: свой черновик с правками страницы, lease у другого Teacher, параллельная правка той же Task, устаревший черновик. В `contract` есть сценарий 7: другой Teacher публикует курс без Task, которую вы правите. Отдельно можно включить сбой следующего сохранения дедлайнов.
- Журнал операций показывает, что именно применилось и чем.

## Контракт #129 (`?taskApply=contract`)

Поведение, как если бы backend реализовал контракт из #129. Модель данных backend здесь не важна, прототип показывает только поведение.

- **Опубликованная Task** правится как в D: отдельная публикация с проверкой версии, без Course Editing Lease. Черновик курса она не трогает. В редакторе панель говорит, что правка уходит сразу, а правки страницы ждут «Применить».
- **Новая Task** — часть черновика курса, то есть рабочей копии редактора. Её свойства сохраняются в черновик сами, без кнопки, и дедлайны тоже: в полосу «Не применено» они не попадают. На карточке плашка «новое, в черновике курса». На страницах дедлайнов (A, B, D) новой Task нет, пока её не опубликуют.
- **«Применить» редактора** публикует страницу и одной операцией создаёт новые Tasks и их Task Groups, а также удаляет Tasks, чьи блоки убраны, вместе с опустевшими группами. В журнале «Песочницы» это одна запись. Над документом полоса «Задания в черновике: создадутся N, удалятся M», подробности по клику.
- **Публикация останавливается**, если:
  - новой Task не хватает названия, ключа или балла (в черновике Task может быть незаконченной, опубликовать её нельзя);
  - курс открыт, а блок задания удалён (после открытия блок задания можно только перемещать);
  - одна Task стоит на странице дважды;
  - на странице блок уже удалённой Task.
- **Ctrl+Z** до публикации возвращает удалённый блок с той же Task.
- **Сценарий 7** («Песочница», только пока курс в подготовке): Архипов публикует курс без Task, которую вы правите. Ваша публикация Task получает исход «Задание удалено»: панель только для чтения, рядом «Скопировать условие», на карточке в просмотре плашка «Удалено публикацией курса».

Что проверить: `C` с `taskApply=contract`, курс «в подготовке». Вставить `/задание`, заполнить панель и задать дедлайн. Удалить блок «Дополнительно: Kubernetes» через меню блока и нажать «Применить». Затем открыть `dock` и увидеть новое задание. Для сценария 7: `dock`, курс «в подготовке», включить сценарий 7, исправить условие и опубликовать.

## Продление студентам

Сдвиг меняет расписание для всех, продление — исключение для отдельных людей. Поэтому это отдельное окно «Продлить дедлайны», собранное из тех же частей, что «Вопрос».

- **Студенты** — поле того же размера, что выбор Task: «Иванов А. А., Смирнова Д. И. и ещё 2». Под ним поиск по началу слов фамилии, имени или группы, отмечать можно нескольких подряд. Чипы попробовали и убрали: с каждым студентом кнопка поиска уезжала, а вместе с ней и список.
- **Task** — тот же выпадающий список или «все Task с дедлайном студента с … по …». Период проверяется по Effective Deadline выбранных студентов, так учитель описывает болезнь или сборы. Очистили период — найденные Task остаются выбранными.
- **На сколько** — «+1 … +14 дней», «или своё» и «или до даты»: продление часто называют датой. Назад продлить нельзя.
- **Причина** — одна на всех. Её увидят эти студенты. Если оставить пустой, у уже продлённых сохранится прежняя.
- **Что изменится** — строка на каждого студента и Task: от чего считается (общий, группа, личное) и новая дата; «без дедлайна» и «уже позже» не меняются. Блок фиксированной высоты, окно не скачет.
- Внизу — сколько сдач перестанут быть опоздавшими; здесь это ожидаемый результат, поэтому зелёным.

Логика выбора везде одна: выбранные Task × выбранные подгруппы или студенты. Галочек на столбцах матрицы нет: заголовок столбца открывает окно, где пересечение видно явно.

## Вердикты по ходу просмотра

Предварительные, их можно пересмотреть на сквозном просмотре в конце #191. В «Решение» #181 переносятся после просмотра всех вариантов.

- **Панель Task встаёт рядом и сдвигает документ, а не перекрывает его** — и в просмотре Course, и в редакторе Course Page (13.10.2026). Поэтому в C панель тоже сдвигает редактор, а нижние плашки (кнопка «Применить» редактора, переключатель вариантов) центрируются в оставшемся месте. `overlay` оставлен в переключателе только для сравнения.
- **Экран дедлайнов: A и C** (13.10.2026). A — отдельная страница-матрица: после сдвига жёлтая подсветка сразу показывает, какие дедлайны поменялись. C — дедлайны прямо в редакторе Course Page — тоже оставить. B не нужен: то же самое делается со страницы курса через панель Task. D интересен, но не для MVP: возможно, позже как второй способ показа, сначала его нужно доработать. Из прототипа B и D не убираются.
- **Подсветка неприменённого** (13.10.2026): жёлтая отметка изменённых, но не применённых дедлайнов на странице — то, что нужно.
- **Окно сдвига — «Вопрос», доработанный** (13.10.2026): несколько галочек вместо одного ответа, подгруппы — кнопками в окне, дни — кнопками из «Сразу» и ячейкой «или своё» в том же ряду. Итоговую фразу из «Фразы» попробовали и убрали: из-за неё окно всё время меняло высоту. Список Task внутри окна оказался слишком большим, вернули выпадающий; осталась подсказка у заблокированной кнопки «Выберите хотя бы одну Task».
- **Страница дедлайнов без подписи и легенды** (13.10.2026): подпись про часовой пояс и легенда значений убраны; «Дедлайны студента» — в одном ряду с «Продлить студентам» и «Сдвинуть дедлайны».
- **Весь текст интерфейса — по-русски** (13.10.2026): задание, студент, подгруппа, курс вместо Task, Student, Student Group, Course. В README и коде термины глоссария остаются английскими.
- **Дата в окне клетки — календарём** (13.10.2026): календарь shadcn и поле времени, как в примере «Date and Time Picker». День применяется сразу, время — по Enter или когда поле теряет фокус. Затем окно прибрано и сравнивается в двух раскладках (`?picker=`); поле времени стало текстовым, потому что системное в Firefox выглядело чужим.
- **Панель Task — разделы через линии** (13.10.2026): `list` выбран, `cards` оставлен в переключателе для сравнения. Вместе с ним приняты общая сетка свойств и раздел «Дедлайны», куда переехали «Открытие» и «Общий дедлайн».
- **Окно даты — в две колонки** (13.10.2026): `split` намного аккуратнее столбика, поэтому стал поведением по умолчанию. `stack` оставлен в переключателе для сравнения.
- **Переопределения одной Task видны и в её панели** (13.10.2026): блок «Переопределения дедлайнов» под свойствами, со ссылкой на страницу дедлайнов. Поэтому `?deadlineField=full` стал поведением по умолчанию.

- **При открытом курсе создание задания заблокировано на месте, а не плашкой в блоке** (13.10.2026). Пункт «Задание» в меню «/» неактивен, вместо описания в нём причина. «Создать ещё» в панели не пропадает, а становится неактивной, причину показывает подсказка при наведении. Раньше блок вставлялся и показывал «Курс открыт, новые задания не создаются»; эта плашка осталась только на случай, когда такой блок вернёт отмена или вставка.

## Упрощения

- Task Group и маски — упрощённые поля по объёму настоящих. Их полноценный UI делают #190 и #191.
- Панель не открывается со страницы Task: id задач fixture не совпадают с моком страницы Task.
- В C «Опубликовать курс» для правок Task в черновике — отдельная полоска. В продукте это общая кнопка «Применить» редактора.
- Часы прототипа заморожены: 13.10.2026 12:00 (UTC+4).
- Пока песочница существует, Course Page этого курса подменена fixture: 14 Task Reference.

## Замечено при сборке

- **Возврат сдвига не восстанавливает наследование.** Сдвиг группы, которая наследует общий дедлайн, создаёт ей явное переопределение (#42). Обратный сдвиг возвращает дату, но переопределение остаётся явным. Правило «+N, затем −N возвращает исходную конфигурацию» из #42 так не выполняется. Предпросмотр показывает это пометкой «совпадёт с общим дедлайном, но останется явным переопределением».
