# Прототип создания курса

Одноразовый прототип для тикета `mm-277`: какая компоновка помогает преподавателю быстро создать курс с понятным адресом? Три варианта на существующей главной странице, переключаемые через `/?variant=A`, `/?variant=B`, `/?variant=C` и нижнюю панель.

Запуск: `bun run dev:prototype`. Прототип доступен только в режиме разработки. Данные и результат создания живут в памяти; запросов на создание курса нет. После перезагрузки результат исчезает.

## Компоновки

- **A — «Короткая форма».** Компактное окно, два привычных поля и пояснение про подготовку. Минимум нового для пользователя; опора — [Bonsai](https://mobbin.com/screens/7aff0ea0-4001-4c46-ab6a-83375db02e2c).
- **B — «Сначала название».** Название получает главный визуальный акцент, ниже видны адрес и то, что появится после создания. Фиксированный префикс отделён от редактируемого адреса; опора — [Plane](https://mobbin.com/screens/8f90e5c2-c6f0-4115-9c19-0e6296bafba2).
- **C — «С предпросмотром».** Слева живая карточка курса, справа форма: вид результата помогает связать название с будущим списком. На узком экране карточка размещается сверху; опора — [Behance](https://mobbin.com/screens/a75aabb3-2166-44f7-aeca-374f2b6438b9).

## Что проверять

В нижней панели доступны успешное создание, конфликт адреса, недоступная предварительная проверка, потерянный ответ и поздний успех. Раздел «Состояние» показывает поля, режим предложения адреса и этап запроса. При неопределённом результате поля сохраняются и заморожены, повторная проверка использует ту же команду. В результате открывается локальный черновик страницы созданного курса с «Подгруппа 1».

## Пока не подтверждено

Победитель среди компоновок не выбран. Требуется обратная связь: полезен ли предпросмотр настолько, чтобы оправдать более широкое окно? Автоматическое предложение адреса и возможность ручной правки одинаковы во всех вариантах. Цвет и типографика сохраняют нейтральный язык существующего приложения.

Это источник для обсуждения, а не готовая реализация: перенос выбранного решения в основной код требует отдельной реализации и проверки контракта с бэкендом.
