# Определить доступ студентов к журналу и аналитике курса

## Question

Какая role/access policy должна действовать для журнала и аналитики курса: должны ли студенты видеть ссылки на `/courses/:courseSlug/journal` и `/courses/:courseSlug/stats` и иметь прямой доступ к этим маршрутам, либо разделы должны быть доступны только преподавателям? Решение должно явно определить navigation visibility и route authorization для каждого раздела; сейчас teacher navigation показывает обе ссылки только преподавателю, но route files не содержат teacher-only guard и допускают прямой доступ студента-участника курса.

## Comments

### 2026-09-13T19:27:48Z · t3m8ch

## Решение: персональный журнал для Student, аналитика только для Teacher

### Журнал

- Ссылка **«Журнал»** видима и Teacher, и Student; прямой маршрут `/courses/:courseSlug/journal` доступен любому Course Member.
- Teacher получает общий журнал Course.
- Student получает только персональное представление: собственные опубликованные Grades по всем Tasks и простую сумму полученных Grades.
- Student никогда не видит Grades других Students — ни всего Course, ни своей Student Group, ни в обезличенном виде.
- В MVP не вводятся настройки видимости журнала, проценты, рейтинг или сравнение с другими Students.

### Аналитика

- Ссылка **«Аналитика»** видима только Teacher.
- `/courses/:courseSlug/stats` требует course-local роль Teacher.
- Прямой переход Student на этот маршрут пока молча перенаправляет на Course Page. Это признано временным поведением, а не целевым UX.
- Целевой UX отказа будет выбран отдельно в [«Выбрать явный UX для отказа в course-local доступе»](https://github.com/dsc-sgu/mm-frontend/issues/111).

Журнал и аналитика не являются первостепенными частями MVP; решение фиксирует минимальный access contract и не расширяет их функциональность.
