# Спроектировать paved road для соблюдения remote-data contract

## Question

Какая минимальная форма transport module, feature operation и статических guardrails должна сделать требования `docs/agents/remote-data.md` соблюдаемыми по умолчанию с минимальными усилиями: централизовать Fetch, `AbortSignal`, runtime validation, typed failures, retry defaults и MSW path, но не вводить endpoint DSL, DI interfaces или generic client сложнее самих операций?

Нужно сравнить как минимум две конкретные TypeScript-формы на реализованных операциях session check, save Course Page и save Attempt Review, оценить их по depth, locality, расширяемости и стоимости нестандартных endpoints, а затем выбрать минимальный interface и границы статического enforcement. Production/source code в рамках тикета не менять; результатом является design decision и связанный prototype-артефакт.

## Решение: малое транспортное ядро с декодером внутри операции

Владелец выбрал вариант **B — малое транспортное ядро**.

### Интерфейс и seam

- Общий модуль предоставляет минимальный интерфейс: `runHttpOperation`, проверяющий JSON helper `readJson`, helper формирования JSON-body и конструкторы типизированных отказов.
- `runHttpOperation<T>(request, decode)` единолично вызывает Fetch и передаёт сырой `Response` в callback конкретной операции. `Response` не выходит в UI или доменную модель.
- Каждая feature operation сама владеет URL, HTTP method, классификацией status → объявленный исход, схемами ответов, DTO → domain mapping и именем операции.
- Endpoint DSL, таблица outcomes, универсальный generic client и DI interface не вводятся.

### Исходы, отказы и отмена

- Корректный ожидаемый ответ завершается operation-specific discriminated union. Например, `401` проверки session остаётся `not-authorized`; документированный stale-write conflict сохранения остаётся `conflict`.
- Если объявленный исход получить нельзя, Promise отклоняется `OperationFailure` с машиночитаемым видом: network, unexpected HTTP, unreadable body или invalid response.
- Transport нормализует только сбой самого Fetch. `readJson` отдельно нормализует чтение/декодирование тела и нарушение Valibot schema.
- `AbortError` сохраняется как отмена и не превращается в `OperationFailure`, включая отмену во время чтения тела.
- Ошибки программирования не захватываются широким `catch`.

### TanStack Query, retries и cache

- QueryClient задаёт безопасное умолчание: автоматические retries выключены и для queries, и для mutations.
- Idempotent query включает retry явно на уровне своего operation contract, с явными limit и delay; `queryFn` передаёт `AbortSignal`.
- Mutation retries остаются выключенными без документированной backend idempotency.
- Feature query/mutation orchestration владеет key factories, authoritative `setQueryData` и targeted invalidation; transport module про cache не знает.

### MSW и статические ограничения

- MSW перехватывает те же URL, которые вызывают production Fetch-операции. Feature-код не содержит mock/real ветки и не импортирует in-process mock implementation.
- ESLint запрещает Axios, прямой Fetch вне единственного transport module и production-imports из mock API.
- TypeScript и `readJson` делают обязательным переход `unknown → Valibot → DTO`; unchecked generic response type не предоставляется.
- Полнота status classification, cache scope и retryability остаётся поведенческим контрактом. Custom ESLint plugin или endpoint DSL ради ложной статической полноты не вводится.

### Проверенные формы

Решение проверено на session check, save Course Page и save Attempt Review. Pressure test с `204`, text/stream, multipart и header-driven outcome показал основное преимущество выбранной формы: нестандартная операция использует обычный `Response` внутри decoder и не расширяет общий transport interface.

Артефакт: [«Удобный путь для удалённых данных»](https://github.com/dsc-sgu/mm-frontend/blob/prototype/remote-data-paved-road/docs/prototypes/remote-data-paved-road.html). Контекстная ветка: [`prototype/remote-data-paved-road`](https://github.com/dsc-sgu/mm-frontend/tree/prototype/remote-data-paved-road), последний проверенный commit `a98033d`.

## Дополнение: исполняемый прототип реализации малого ядра

Добавлен [исполняемый TypeScript-прототип](https://github.com/dsc-sgu/mm-frontend/blob/prototype/remote-data-paved-road/docs/prototypes/remote-data-kernel.prototype.ts) на контекстной ветке [`prototype/remote-data-paved-road`](https://github.com/dsc-sgu/mm-frontend/tree/prototype/remote-data-paved-road), commit `8b5dcce`.

Запуск без сервера и дополнительных зависимостей:

```sh
bun docs/prototypes/remote-data-kernel.prototype.ts
```

Прототип содержит реальную реализацию:

- `runHttpOperation` — единственный вызов Fetch, передача `AbortSignal`, нормализация сетевого отказа;
- `HttpResponseContext` — `Response` вместе с именем операции, чтобы helpers формировали диагностируемые отказы без повторения имени в каждом вызове;
- `readJson` — `unknown → Valibot → DTO`, отдельные `unreadable-body` и `invalid-response`;
- `unexpectedHttp`, `invalidResponse`, `jsonBody`;
- `OperationFailure` с машиночитаемым discriminant;
- безопасные QueryClient defaults и явная retry policy для session check;
- operation-specific реализации `checkSession`, `saveCoursePage` и `saveAttemptReview`.

Исполняемый стенд поднимает локальный HTTP-сервер на случайном порту и подтверждает: authorized session; `401 → not-authorized`; invalid DTO → rejected `OperationFailure`; успешное сохранение Course Page и Attempt Review; `409 → conflict`; отмену как `AbortError`; недоступный сервер как network failure; retries по умолчанию выключены.

Проверено:

```sh
bunx tsc --noEmit --strict --target ES2022 --module ESNext --moduleResolution bundler --types node docs/prototypes/remote-data-kernel.prototype.ts
bun docs/prototypes/remote-data-kernel.prototype.ts
```

HTML-прототип теперь ссылается на реализацию и показывает тот же `HttpResponseContext` interface. Production/source code и тесты не изменялись.
