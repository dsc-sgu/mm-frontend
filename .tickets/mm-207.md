# Спроектировать управление Teachers Course

## Source

- Страница AnyType «Фронтенд MergeMinds», «Что нужно уметь редактировать в курсе»: «Преподаватели — Добавление новых преподавателей, Удаление преподавателей, Изменение прав преподавателям».
- Страница AnyType «Обсуждение MergeMinds 30.01.2026»: «Теме больше нравится мандатная модель, где прям будет "он может оценить работу, он может создать блок и тд"».

## Проблема

В редакторе Course список Teachers только для чтения (`src/features/course/features/page-edit/ui/hero-editor.tsx`). Добавить, удалить Teacher или ограничить его права нельзя. [#176](https://github.com/dsc-sgu/mm-frontend/issues/176) лишь упоминает invite-ссылку с ролью Teacher.

## Что решить

- **Добавление:** invite-ссылка с ролью Teacher (#176) или поиск User по username.
- **Удаление:**
  - что происходит с его Review Lease, Course Editing Lease и Course Draft Snapshot;
  - его Reviews остаются с его авторством;
  - последнего Teacher удалить нельзя, и сам он выйти не может.
- **Права.** По `CONTEXT.md` у Course Membership ровно одна роль: Student или Teacher. Права Teacher'а — это возможности внутри роли: редактировать Course, проверять Attempts, открывать Course, управлять Teachers. Нужны новые термины в `CONTEXT.md`, и надо решить, как frontend узнаёт, что можно текущему User (встреча 30.01).
- **Кто управляет Teachers.**
- Вопросы к backend добавить в [«Реестр frontend-вопросов к backend API»](https://github.com/dsc-sgu/mm-frontend/issues/113).
