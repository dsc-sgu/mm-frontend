# Прогнать Knip и разобрать неиспользуемый код

## Задача

В проект добавлены Knip и команда `bun run knip`. Нужно выполнить проверку на актуальном `main`, разобрать все находки и исправить подтверждённые проблемы. Этот тикет — последующая работа; при добавлении инструмента код не удалялся.

## Исходное состояние

Первый запуск Knip 6.44.0 выявил 69 неиспользуемых экспортов значений и 34 экспорта типов. Неиспользуемых файлов, зависимостей и неразрешённых импортов не найдено. Числа могут измениться к началу работы.

Конфигурация находится в `knip.json`. Точки входа включают приложение и `*.type-test.ts`; конфигурации Vite, Vitest и Playwright обнаруживаются плагинами Knip. Перед анализом чистой копии репозитория выполнить `bun run build`, чтобы появился `src/routeTree.gen.ts`.

## Что сделать

- Запустить `bun run knip` и проверить достижимость маршрутов, Web Workers, моков и тестов.
- Разобрать каждую находку: удалить действительно неиспользуемый код либо снять лишний `export`, если объявление используется внутри файла.
- Отдельно оценить штатные экспорты shadcn: не удалять механически предусмотренные библиотекой части компонентов.
- Если находка вызвана неполной конфигурацией анализа, исправить конфигурацию; узкие исключения допустимы только с объяснением причины. Не скрывать целые категории ошибок ради зелёного результата.
- После разбора включить проверку Knip в CI, если оставшиеся обоснованные исключения позволяют сделать её обязательной.

## Критерии готовности

- `bun run knip` завершается успешно; оставшиеся исключения точечные и документированные.
- `bun run lint`, `bun run build` и затронутые тесты проходят.
- Удаление кода не меняет поведение приложения.
- В тикете описаны исправления, обоснованные исключения и решение о включении проверки в CI.
