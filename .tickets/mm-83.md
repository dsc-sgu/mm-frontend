# Удалить прямые RAM-моки и проверить переключение на реальный backend

## Parent

[Перевести frontend с RAM-моков на fetch и MSW](https://github.com/dsc-sgu/mm-frontend/issues/73)

## What to build

Завершить миграцию: удалить старые feature-local stateful RAM-моки и доказать, что один и тот же feature data layer работает с MSW mock backend и с настроенным реальным backend без переписывания query/mutation modules.

## Acceptance criteria

- [ ] Feature query/mutation modules используют только transport clients и не импортируют RAM-моки.
- [ ] Старые feature-local stateful mock stores и недостижимые compatibility paths удалены.
- [ ] MSW можно включить для development/test и отключить для обращения к настроенному backend.
- [ ] Переключение adapter не требует изменений в consumers data layer.
- [ ] Request/response parsing и HTTP error handling находятся на transport seam.
- [ ] Stateful изменения остаются согласованными между course page, access, task history, attempts list и attempt review.
- [ ] Документирован способ выбрать scenario, запустить mock-режим и переключиться на backend.
- [ ] Lint и build проходят.
