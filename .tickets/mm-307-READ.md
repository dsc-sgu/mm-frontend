# READ: Читать опубликованную страницу курса через API версий блоков

## Цель

Общие операции чтения опубликованного документа живут в page-document/api. Возвращать последние неудалённые опубликованные версии блоков с version, стабильными id и порядком; чужие черновики не видны. Страница и редактор используют общую модель документа. DTO валидируются на границе, невалидное содержимое отдельного блока обрабатывает DOC1.

## Удаляет или заменяет

fetchCoursePage и COURSE_PAGE_STORE в RAM-моке на пути чтения, courseId со slug вместо CourseId, id активного снапшота в проекции.

## Принятое решение и границы

Владелец подтвердил frontend-first подход: существующий API-слой бэкенда заменяется контрактами, определёнными потребностями фронтенда. Модель черновиков блоков, публикации со слиянием и чекпоинтов согласована. Ожидание старого API не блокирует этап. HTTP-формы и исходы операции закрепляются в схемах, MSW и тестах; вопросы о реализации и оставшиеся ограничения фиксируются в mm-113.

Перед реализацией прочитать `docs/agents/remote-data.md`, актуальный `CONTEXT.md` и связанные ADR. Устаревшие положения ADR 0002 и ADR 0004 о брони редактирования курса заменяются решением mm-286; бронь проверки сохраняется. Изменения доменной документации учитывает mm-286.

Новая архитектура не требует переименования каталогов из mm-292 заранее: использовать текущие пути с теми же владельцами поведения. Не выделять отдельное «чистое ядро». Этап выполняется заменой за один шаг без второго временного пути данных.

## Проверяемое поведение

Контракт `DRF-22` переписан ниже под опубликованные версии блоков; проверять его через границу API и доступ к странице.

Актуальный DRF-22: студент и другой преподаватель не получают чужие черновики. Нет брони редактирования курса и активного снапшота курса.

## Готово, когда

- [ ] Реализовано описанное поведение и удалён прежний путь в затронутой зоне.
- [ ] Схемы, моки и тесты используют один контракт; отказ, отмена и неизвестный исход не изображаются успехом.
- [ ] Проходят `bun run lint`, `bun run build` и проверки уровня владельца контракта; браузерные сценарии — в Chromium, Firefox и WebKit.
- [ ] Сохранены применимые общие контракты доступности `A11Y-01` и `A11Y-02`.

## Дополнение критериев приёмки: саммари заданий с учётом участника

В mm-301 оставлено временное преобразование в `page/ui/page.tsx`: UI заменяет статус доступного саммари на `teacher`, исходя из роли в курсе. Удалить его в рамках READ, вместе с переходом от RAM-мока к операциям чтения.

Обязательные критерии приёмки:

- Операция чтения возвращает авторитетную проекцию саммари задания для текущего участника курса. Для студента это `open`, `locked { prerequisite }` или `unavailable`; преподаватель получает доступное саммари без состояния доступа студента. Недоступное задание остаётся `unavailable` для любого участника.
- Успешный ответ и его DTO-схема различают представления студента и преподавателя. Выбор состояния доступа принадлежит контракту чтения; UI не превращает `locked` или `open` в `teacher` по локальной проверке роли.
- Удалено преобразование `course.taskSummaries.map(...)` из `page/ui/page.tsx`. Режим чтения получает готовые саммари через интерфейс операции, без исправления статусов в компонентах.
- Данные и ключи кэша учитывают участника, для которого получена проекция: саммари с доступом одного пользователя не переиспользуется для другого. Изменение подтверждённой роли в курсе приводит к перепроверке соответствующей проекции.
- MSW и контрактные тесты операции проверяют открытое, закрытое и недоступное задание студента, представление преподавателя и отсутствие переноса состояния доступа между участниками. Закрытое задание раскрывает только саммари и предварительное условие, без содержимого задания.

Это обязательная часть mm-307, а не отложенная очистка в FINAL. Имена DTO и точное разбиение чтений определить при реализации с соблюдением `docs/agents/remote-data.md`.
