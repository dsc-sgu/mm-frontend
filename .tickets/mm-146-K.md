# K: Транспортное ядро на Fetch, MSW и Vitest; auth — первый потребитель

Перед началом прочитать [`docs/agents/remote-data.md`](https://github.com/dsc-sgu/mm-frontend/blob/main/docs/agents/remote-data.md) (обязательно по `AGENTS.md`). Интерфейс ядра — из [#112](https://github.com/dsc-sgu/mm-frontend/issues/112); пример `requestJson` в `remote-data.md` только иллюстрирует правило.

### Делает

**Транспортное ядро.** Форма — по [исполняемому прототипу](https://github.com/dsc-sgu/mm-frontend/blob/dde9e21/docs/prototypes/remote-data-kernel.prototype.ts) (ветка `prototype/remote-data-paved-road`, `dde9e21`).

- `runHttpOperation(request, decode)` — единственный вызов Fetch в приложении. `HttpOperationRequest = RequestInit & { name; url }`. Сырой `Response` получает только decoder операции через `HttpResponseContext`.
- `readJson` проводит тело по пути `unknown → Valibot → DTO`. Helpers: `jsonBody`, `unexpectedHttp`, `invalidResponse`.
- `OperationFailure` с `kind`: `network | unexpected-http | unreadable-body | invalid-response`.
  - `operation` — стабильный внутренний id операции (`check-session`, …).
  - `message` — диагностический текст на английском для DevTools и логов. UI его не показывает.
- `AbortError` остаётся отменой, в том числе во время чтения тела. Ошибки программирования не ловятся широким `catch`.
- Endpoint DSL, таблица исходов, generic client и DI не вводятся.

**QueryClient.** Автоматические retries выключены для queries и mutations. Query с retry задаёт limit и delay в своём operation contract.

**Auth — первый потребитель.**
- Session check, login, register и logout — операции на ядре.
- `401` проверки session остаётся данными: `not-authorized`, а не отказом.
- Session несёт `userId`, проверенный Valibot.
- Роль в session остаётся до ACC1, а branded `UserId` и остальные identity-типы вводит ACC1.

**MSW.**
- Browser worker в dev стартует по явному флагу до первого render и заменяет `VITE_MOCK_AUTH`. Без флага запросы уходят настроенному backend через proxy Vite. В production MSW не включается.
- `msw/node` — для Vitest.
- Handlers обслуживают те же URL, что production-операции. В feature-коде нет веток mock/real.

**Состояние mock backend.**
- Один сбрасываемый stateful instance из детерминированного seed; handlers feature-local.
- Повторный запуск воспроизводит те же identities и данные. Сброс — между тестами и вручную.
- Миры (`world:*`) и профили отказов из матрицы приходят со slices, которые их используют. Test-only канал управления миром для E2E появится с первым E2E.

**Тестовый слой.** Vitest (Node и jsdom), React Testing Library и `user-event`; job в CI.

**ESLint.**
- Запрещены: импорт `axios`, прямой `fetch` вне transport module, production-import из mock API.
- Список исключений — текущие RAM-моки. Каждый следующий slice сокращает его, FINAL удаляет.

### Удаляет

- `axios` из кода и manifest.
- `VITE_MOCK_AUTH` и прямые вызовы `features/auth/api/mock.ts` из auth client: auth mock становится MSW handlers.
