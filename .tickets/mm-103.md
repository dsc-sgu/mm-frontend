# Возвращать преподавателя в рабочую очередь после ревью

## Parent

#100

## What to build

Сделать путь «рабочая очередь → ревью попытки → рабочая очередь» непрерывным. Преподаватель, открывший ревью из применённой выборки, должен вернуться к тем же фильтрам и подходящей позиции списка, не собирая рабочий контекст заново. Обычный переход в раздел «Попытки» должен оставаться предсказуемым и не зависеть от случайно сохранённой старой позиции.

## Acceptance criteria

- [ ] Применённые фильтры очереди по-прежнему представлены в URL и восстанавливаются после reload.
- [ ] Попытка, открытая из отфильтрованной очереди, получает достаточный контекст для продолжения этого сценария.
- [ ] Возврат из ревью по пути продолжения работы открывает ту же применённую выборку.
- [ ] После возврата преподаватель видит исходную попытку или ближайшую устойчивую позицию, даже при виртуализированном списке.
- [ ] Если состав списка изменился и исходная попытка исчезла, используется понятный безопасный fallback, а не ошибочная абсолютная прокрутка.
- [ ] Обычный переход во вкладку «Попытки» не обязан восстанавливать старую рабочую позицию и остаётся отличимым от продолжения очереди.
- [ ] Прямое открытие ревью без контекста очереди продолжает работать.
- [ ] Поведение проверено в реальном маршрутизируемом приложении с teacher mock-сценарием.
- [ ] Нетривиальная сериализация или восстановление контекста покрыта сфокусированным model-тестом только при появлении соответствующего чистого interface.
