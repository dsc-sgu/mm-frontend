# Попробовать кодогенерацию контракта API на двух операциях

## Зачем

Около 25 удалённых операций в `features/*/api/` и их обработчики MSW написаны вручную. Каждая операция объявляет Valibot-схему DTO и разбирает статусы в `runHttpOperation`. Обработчик MSW собирает ответ отдельно, и его форма никак не связана со схемой: например, `toReviewDto` в `review/api/mock.ts` может разойтись с `ReviewResultSchema`, и ни компилятор, ни тесты этого не заметят. Договорённости о форме ответа живут в комментариях `pending backend confirmation #113` и в README, а не в машиночитаемом виде.

API-слой бэкенда, скорее всего, будет переписан под нужды фронтенда, поэтому контракт задаёт фронтенд. Если описывать его в одном машиночитаемом источнике, из него можно генерировать и код фронтенда, и спецификацию для нового API бэкенда. Это закрыло бы два открытых вопроса mm-113: «Источник контракта API» и «Проверка соответствия контракту».

Тикет — пилот: проверить на двух операциях, сколько ручного кода уходит и можно ли при этом соблюсти правила `AGENTS.md`. Решение о внедрении принимается по его итогам.

## Операции пилота

1. **`loadCourse`** (`features/course/features/access/api/load-course.ts`, обработчик в `access/api/mock.ts`). Простая форма ответа, но в ней есть:
   - брендированный `CourseId`;
   - `CourseIconNameSchema` на `v.custom`;
   - `404` без тела как ожидаемый исход «не найден» (ADR 0006);
   - `401` как отказ операции.
2. **`loadReview`** (`features/course/features/review/api/load-review.ts`, обработчик в `review/api/mock.ts`). Вложенная форма, на которой видно, переиспользует ли генератор доменные схемы:
   - `v.variant('status', …)`;
   - `UserRefSchema`, `GradeSchema`, `ReviewRevisionSchema`;
   - ISO-время;
   - отказ в доступе через `readResourceDenial`.

## Что сравнить

- **A1. TypeSpec → OpenAPI 3.1 → [hey-api/openapi-ts](https://heyapi.dev/docs/openapi/typescript/plugins/valibot)**: плагины `valibot` и [`msw`](https://heyapi.dev/docs/openapi/typescript/plugins/msw). Сначала проверить, вошёл ли MSW-плагин в стабильный релиз. Сгенерированные схемы будут «сетевыми», поэтому перевод в доменные типы придётся писать вручную.
- **A2. TypeSpec → свой эмиттер Valibot**. Готового эмиттера нет; образец — [typespec-zod-emitter](https://github.com/kattebak/typespec-zod-emitter). Эмиттер знает соглашения проекта:
  - подставляет импорт доменной схемы вместо копии, например декоратором вида `@valibot("@/features/auth/model/user-ref#UserRefSchema")`;
  - раскладывает `api/*.gen.ts` по фичам по namespace;
  - строит разбор статусов из списка ответов;
  - строит типизированную фабрику обработчика MSW, чтобы мок не мог вернуть ответ, которого нет в контракте.
- **B (по желанию). Valibot → OpenAPI** через `@valibot/to-json-schema`, без TypeSpec. Нужен, если A1 и A2 окажутся слишком тяжёлыми.

Для каждого варианта ответить:

- Сколько строк ручного кода осталось в операции и обработчике, и какой это код.
- Нет ли копий ограничений доменных схем, которые запрещает `AGENTS.md`, раздел «Valibot schemas».
- Как генерация встраивается в правило ESLint о прямых импортах `valibot` (только `api/`, `model/`, `routing/`) и в Knip.
- Как выглядит изменение контракта: правка `.tsp` → регенерация → какие ошибки покажет `tsc`.
- Где лежат `.tsp` и сгенерированные файлы, коммитятся ли сгенерированные файлы (как `routeTree.gen.ts`) и как CI ловит несвежую генерацию.
- Насколько полученный OpenAPI пригоден как документ для бэкенда.

## Результат

- Ветка с пилотом: обе операции работают через выбранный вариант, существующие тесты `access/api` и `review/api` проходят без изменения ожиданий.
- Комментарий в тикете со сравнением вариантов по вопросам выше и рекомендацией: внедрять или нет, каким вариантом и как переводить остальные операции.
- Пункт «Источник контракта API» в mm-113 обновлён ссылкой на итог.

## Вне рамок

- Перевод остальных операций.
- Генерация Go-кода для бэкенда. Достаточно показать, что OpenAPI получается.
- Кодогенерация не для API: JSON Schema документа страницы курса, заготовки тестов по id сценариев из тикетов, генераторы fast-check из схем. При необходимости — отдельные тикеты.
