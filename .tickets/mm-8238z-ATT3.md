# ATT3: Показывать загрузку, перепроверку и устаревший список попыток явно

## Цель

CourseAttemptsListState: loading/ready/refreshing/stale/failed. Последний полный список виден при перепроверке; после ошибки — «Данные могут быть устаревшими» и Retry. При первой ошибке — ошибка, не пустой список. Перепроверять при входе, известных записях, focus/reconnect и явном обновлении, без polling. Переход к попытке из stale разрешён, быстрое оценивание запрещено.

## Удаляет или заменяет

Параллельные флаги жизненного цикла, частичный правдоподобный список и показ отмены как ошибки сети.

## Принятое решение и границы

Владелец подтвердил frontend-first подход: существующий API-слой бэкенда заменяется контрактами, определёнными потребностями фронтенда. Модель черновиков блоков, публикации со слиянием и чекпоинтов согласована. Ожидание старого API не блокирует этап. HTTP-формы и исходы операции закрепляются в схемах, MSW и тестах; вопросы о реализации и оставшиеся ограничения фиксируются в mm-113.

Перед реализацией прочитать `docs/agents/remote-data.md`, актуальный `CONTEXT.md` и связанные ADR. Устаревшие положения ADR 0002 и ADR 0004 о брони редактирования курса заменяются решением mm-286; бронь проверки сохраняется. Изменения доменной документации учитывает mm-286.

Новая архитектура не требует переименования каталогов из mm-292 заранее: использовать текущие пути с теми же владельцами поведения. Не выделять отдельное «чистое ядро». Этап выполняется заменой за один шаг без второго временного пути данных.

## Проверяемое поведение

- `ATT-08`: `CourseAttemptsListState` `loading | ready | refreshing | stale | failed`: переходы; отмена не даёт `failed` или `stale`.
- `ATT-09`: Отказ первой загрузки → ошибка + «Повторить», но никогда не пустой список; отказ перепроверки → последний полный список + «Данные могут быть устаревшими» + «Повторить».
- `ATT-10`: Перепроверка при входе, возврате фокуса, восстановлении сети и после известных мутаций; периодического опроса нет (10 мин на fake clock → 0 запросов). Исключение: во время быстрого оценивания перепроверка отложена до выхода из режима (QG-10).
- `ATT-12`: Список в `stale` (не подтверждён последней перепроверкой): переход к отдельной попытке разрешён; быстрое оценивание заблокировано до успешной перепроверки.

В режиме быстрого оценивания перепроверка откладывается до явного выхода; после выхода один refetch. Приоритета P1 у этапа недостаточно для обхода ATT2: перед стартом при необходимости выделить минимальный контрактный фильтр без переработки панели отдельным решением, не теряя UI-работу.
