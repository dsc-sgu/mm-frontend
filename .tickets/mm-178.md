# Спроектировать создание курса

## Решение

Итог проектирования подтверждён пользователем 2026-10-31. Актуальный результат — раздел «Итоговая спецификация создания курса» ниже. Реализация — mm-277, требования к API переданы в mm-113. Промежуточные предложения в истории обсуждения заменены итоговой спецификацией.

## Исходный вопрос

Как пользователь создаёт курс? Нужно решить:

- кто может создавать курс;
- где находится вход;
- какие поля нужны при создании, а какие настраиваются позже;
- что курс получает по умолчанию;
- нужен ли сразу следующий шаг: подгруппы, ссылки-приглашения, другие преподаватели.

## Контекст

- На фронтенде нет страницы создания курса. Панель управления показывает только «Мои курсы».
- Уже решено в mm-42 (спецификация дедлайнов): в каждом курсе есть хотя бы одна подгруппа, новый курс создаётся с одной подгруппой по умолчанию (`CONTEXT.md`, Student Group). Управление подгруппами и ссылками-приглашениями — mm-176.
- Состояние доступа к курсу начинается с `draft`. Студенты получают доступ только после открытия курса (`CONTEXT.md`).
- Карточка курса на фронтенде показывает полное название, цвет и иконку; короткое название есть в модели, но карточка его не выводит. Маршрут использует изменяемый slug, а не идентичность курса.

## Факты бэкенда

_Проверено на `mm-backend@ddd9849` (`main`)._

- `POST /courses` ([`internal/api.go` L107-L111](https://github.com/dsc-sgu/mm-backend/blob/ddd98496d1293a3cf9844201e70376b3364fdcc3/internal/api.go#L107-L111)) принимает `name` (обязательно) и `disciplineID` (необязательно) ([`internal/courses/repo.go` L23-L26](https://github.com/dsc-sgu/mm-backend/blob/ddd98496d1293a3cf9844201e70376b3364fdcc3/internal/courses/repo.go#L23-L26)). Глобальную роль бэкенд не проверяет: курс создаёт любой вошедший пользователь.
- Создатель становится `owner_id` и сразу получает участие в курсе с ролью преподавателя. В той же транзакции создаётся и публикуется начальный снапшот курса ([`internal/pg/courses.go` L89-L202](https://github.com/dsc-sgu/mm-backend/blob/ddd98496d1293a3cf9844201e70376b3364fdcc3/internal/pg/courses.go#L89-L202)).
- В открытом [mm-backend PR #187](https://github.com/dsc-sgu/mm-backend/pull/187) (`14a6abb`, не влит) снапшотов нет: курс создаётся без блоков и без чекпоинта, первый чекпоинт появится с первой публикацией. `PATCH /courses` меняет `name` и `displayName` сразу; описания, цвета, иконки и ресурсов на бэкенде нет ни в одной ветке.
- Есть CRUD дисциплин (`/disciplines`). Название курса уникально в пределах дисциплины.
- Подгруппа по умолчанию при создании не появляется: `groups` и `course_users_groups` код не использует.

## Исходные вопросы интервью (разрешены)

- Кто создаёт курс: любой пользователь, как сейчас на бэкенде, или только отдельная роль.
- Вход: кнопка на панели управления, отдельный маршрут, пустое состояние «Мои курсы».
- Минимальные поля: название, короткое название, цвет, slug, дисциплина. Какие из них можно оставить на потом.
- Название подгруппы по умолчанию и можно ли переименовать её сразу.
- Одна форма или мастер с шагами (подгруппы, ссылки-приглашения, преподаватели).
- Создание курса копией прошлогоднего курса той же дисциплины: в этом же сценарии или отдельно.
- Новые вопросы к бэкенду добавить в mm-113 — реестр вопросов фронтенда к API бэкенда.

## Интеграционные предпосылки и образцы

API проектирует фронтенд; отсутствие операции в прежнем API бэкенда не блокирует этот тикет. Перед реализацией прочитать `docs/agents/remote-data.md`. Образцы ниже проверены в `origin/main` на `045ea6d`; брать свежий `origin/main`, а не старый локальный checkout. Новые операции — Fetch через `runHttpOperation`, URL через `apiPath`, DTO проверяются до кэша; MSW хранит данные в общем `mockBackend`, а не в новом RAM-хранилище.

**Блокеры рефакторинга не нужны:** это проектирование сценария, его результат не требует готового редактора или API подгрупп. При решении о создании использовать согласованную модель: курс создаётся в `draft`, с подгруппой по умолчанию; создатель — преподаватель, slug изменяем, `CourseId` стабилен.

**Готовые образцы:** `src/features/course/api/load-courses.ts`, `src/features/course/api/queries.ts`, `src/features/course/features/access/api/load-course.ts` показывают уже существующие вход/выход «Мои курсы» и контекст курса; `src/routes/_authenticated/index.tsx` — место входа в сценарий. Это образцы HTTP-пути и идентичности, а не готовая операция создания: её сейчас нет.

**Не копировать:** сохранение метаданных через `saveCoursePage` в `page/api/mock.ts`, роль из глобальной сессии, данные преподавателя без `id` из старой формы списка курсов. Не возвращать создание снапшота курса или бронь курса: черновики блоков согласованы. Минимум формы и её итоговый переход согласовать здесь для mm-277; не заставлять этот дизайн ждать DOC1/DRF2.

Проверено по `origin/main` (`045ea6d`). Наличие решения в спецификации или рабочей ветке не означает, что его реализация уже доступна в `main`. Перед реализацией перечитать `docs/agents/remote-data.md` и проверить актуальность указанных путей.

## Итоговая спецификация создания курса

Ниже собраны ответы Q1–Q24. Пользователь подтвердил итог 2026-10-31. Это цельная актуальная версия для mm-277; она заменяет прежние рабочие допущения и промежуточные решения в обсуждении. Уточнение пользователя от 2026-10-31: короткое название и описание обязательны уже при создании. Интервью завершено; прототип не заменяет реализацию.

### Вход и границы

- Создавать курс может любой вошедший пользователь, независимо от роли в других курсах.
- Кнопка «Создать курс» находится в «Моих курсах» и доступна также в пустом состоянии. Открывает диалог поверх списка.
- Только создание с нуля, без выбора дисциплины. Копирование другого курса — отдельный сценарий.
- Подгруппы, приглашения и другие преподаватели настраиваются после создания, без обязательного мастера.

### Поля и адрес

- В диалоге четыре поля: название (`title`), короткое название (`shortTitle`), адрес (`slug`) и описание (`description`). Короткое название и описание обязательны: после удаления крайних пробелов каждое должно оставаться непустым. Значения сохраняются такими, какими их ввёл пользователь после удаления крайних пробелов; короткое название не генерируется автоматически. Название допускает любой текст, непустой после удаления крайних пробелов, включая один эмодзи или знаки. Одинаковые названия разрешены, в том числе у одного создателя.
- Адрес — изменяемый локатор, а не идентичность курса. Для создания необходим допустимый непустой адрес: строчные латинские буквы, цифры и разделительные дефисы; действующий запрет UUID в качестве slug сохраняется.
- Автоматическое предложение — транслитерация названия: «Алгоритмы 2026» → `algoritmy-2026`. Если предложение сформировать нельзя, поле адреса пустое; случайный адрес не генерируется.
- Предложение обновляется при изменении названия до первой ручной правки адреса. Затем адрес не меняется от правок названия. Действие «Сформировать из названия» возвращает автоматическое предложение.
- Доступность адреса проверяется при вводе с дебаунсом. Предварительная проверка не резервирует адрес; бэкенд повторно проверяет уникальность при создании. Ответ старой проверки не должен описывать уже изменённый адрес.
- Если предварительная проверка не отвечает или завершается ошибкой, состояние проверки показывается, но валидную форму разрешено отправить.
- Конфликт адреса — ожидаемый отдельный исход: сообщение «Адрес недоступен» у поля, введённые данные остаются. Занятость не является секретом; сведения о чужом курсе не раскрываются. Граница гарантии уточнена в ADR 0006, включая предварительную проверку.

### Результат создания

- Атомарно создаются курс в подготовке (`draft`), участие создателя с ролью преподавателя и одна подгруппа «Подгруппа 1». Частичный результат пользователю не представляется успешным.
- Короткое название и описание берутся из обязательных полей формы; цвет `blue`, иконка `book-open`. Название, короткое название, описание, цвет и иконка — мгновенные метаданные, без ожидания публикации.
- Операция возвращает стабильный `CourseId` и подтверждённый `slug`. Список «Мои курсы» и необходимый контекст согласуются с результатом перед переходом.
- При обычном успехе диалог закрывается, пользователь попадает в редактор страницы курса. Открытие курса для студентов остаётся отдельным действием mm-188.
- Создание снапшота курса или брони редактирования курса в этот сценарий не возвращать: применяется согласованная модель черновиков блоков.

### Время ожидания и неизвестный результат

- Во время отправки поля, повторная отправка и закрытие диалога заблокированы, но не дольше 15 секунд ожидания подтверждения.
- После 15 секунд без результата показывается «Не удалось подтвердить создание курса», разрешается закрытие. Данные сохраняются. Тайм-аут не означает отмену или отсутствие созданного курса.
- Пока исход неизвестен, поля команды заблокированы и новое создание не предлагается. Можно закрыть диалог или по кнопке безопасно повторить ту же команду с теми же данными и ключом идемпотентности. После подтверждённого отказа поля снова доступны.
- API обязан гарантировать, что повтор той же команды с тем же ключом не создаёт второй курс и возвращает тот же результат. Автоматических повторов нет. Гарантия должна быть частью контракта бэкенда, а не имитацией во фронтенде.
- Если успешное подтверждение приходит после закрытия диалога, показывается уведомление со ссылкой и обновляется «Мои курсы»; текущая страница не меняется.

### Время жизни данных

- Форма и отправленная команда с ключом живут только в памяти до перезагрузки. Обычное закрытие и повторное открытие возвращают данные и режим адреса; успешное создание очищает форму.
- Неизвестный исход после закрытия диалога не сбрасывает сохранённую команду. Открытие сценария возвращает её восстановление, а не новую независимую форму.
- Постоянное браузерное хранилище не вводится. После перезагрузки нет ключа, восстановления команды и автоматического повтора. Возможный результат пользователь ищет в «Моих курсах».
- mm-273 планирует отдельное восстановление рабочей копии проверки вместе с публикацией; зависимости от него у создания курса нет.

- Реализация — mm-277. Перед кодом прочитать `docs/agents/remote-data.md`; использовать актуальные операции Fetch через `runHttpOperation`, URL через `apiPath`, валидацию DTO до кэша и общий `mockBackend`.

Детали передачи и срока действия ключа должны явно обеспечивать согласованную гарантию отсутствия дублей; отсутствие такой гарантии не маскировать безопасным повтором на фронтенде.
- Метаданные и область названий задаются этой спецификацией, а не обязательностью полей старого редактора или уникальностью названия внутри дисциплины в прежнем API.
- Минимальная проверка реализации: эмодзи допустим/пробельное название нет; пустые или пробельные короткое название и описание блокируют создание; введённые короткое название и описание сохраняются, включая повтор той же команды; пустой результат транслитерации; ручной режим адреса и его сброс; дебаунс и устаревшие ответы проверки; сбой предварительной проверки; конфликт при создании после успешной проверки; атомарные значения по умолчанию; тайм-аут 15 секунд; повтор с прежним ключом без дубля; поздний успех без смены страницы; потеря формы и команды после перезагрузки.
