# Восстановить понимание frontend и подготовить пакет решений для рефакторинга

## Destination

Единый пакет готовности к рефакторингу реализованной части MergeMinds frontend: согласованная карта системы и домена, приоритеты и целевые seams, спецификации критичных поведений, слоистая стратегия тестирования и последовательность будущих изменений. Пакет должен быть достаточен, чтобы последующую реализацию разложить на независимые задачи без повторного восстановления контекста.

## Notes

- Область: только уже реализованная frontend-система. Открытый продуктовый backlog учитывается лишь как проверка расширяемости решений, но не проектируется в рамках этой карты.
- Источник истины: фактическое поведение текущего кода плюс явные решения владельца продукта в HITL-тикетах; неясности не заполнять догадками.
- Только исследование и планирование. Не менять production/source code, не выполнять рефакторинг и не добавлять тесты в рамках этой карты; допустимы planning/research-артефакты на отдельных ветках.
- Каждая сессия сверяется с `AGENTS.md` и применяет `domain-modeling`; при проектировании seams и интерфейсов — `codebase-design`; внешние факты исследуются через `research` по первичным источникам.
- Текущий baseline: React 19 + Vite + TypeScript + TanStack Router/Query; основная масса кода находится в `course`, особенно `page-edit`, `attempt-review` и `attempts`; тестового runner и тестов нет; `bun run lint` и `bun run build` проходят, build предупреждает о крупных chunks.
- Резолюции разделяют три вида утверждений: решения frontend в границах карты; рабочие допущения до ответа backend — со ссылкой на пункт mm-113 «Реестр frontend-вопросов к backend API» и последствием другого ответа; проверенные факты backend — с commit `mm-backend`. Писать «противоречит решению X» можно только после сверки с оговорками X и с реестром.

## Decisions so far

- mm-66 «Исследовать тестовые практики для текущего frontend-стека»: первичные источники подтверждают слоистый подход с быстрыми model-тестами, DOM integration и узкими real-browser/E2E проверками; shortlist и ограничения зафиксированы в research-артефакте.
- mm-63 «Согласовать карту реализованной frontend-системы»: зафиксированы runtime/routes/features/state/mocks и граница реализованного ядра Git-oriented LMS; placeholders отделены от готовых flows, а противоречия — от подтверждённого продуктового контекста.
- mm-71 «Провести аудит зависимостей и конкурирующих библиотек»: выбраны Valibot, единая Radix packaging-конвенция и Plate как единственный editor framework; зафиксированы безопасные удаления, unlisted imports и риски TipTap cutover.
- mm-65 «Зафиксировать канонический доменный язык и состояния»: согласованы identities, course-local roles, Course/Task/Attempt/Review vocabulary, access и editing lifecycles; будущий Task Group completion rule явно оставлен за границей реализованного ядра.
- mm-72 «Разобрать низкоуровневые browser- и scheduling-механизмы»: зафиксированы modern SPA/mobile contracts, обязательный route-local diff Worker с явным failure state, focused seams для editor/keyboard/clipboard и outcome-based timing с Reduce Motion.
- mm-74 «Зафиксировать контракт нумерации списков редактора»: read-mode закреплён как семантическое дерево, editor может использовать плоский Plate/start; определены границы numbered-серий, normalizing и single/multi-block structural operations, а также обязательные model и real-browser regression scenarios.
- mm-99 «Определить доступ студентов к журналу и аналитике курса»: Student получает персональный журнал только со своими Grades и их суммой, а аналитика остаётся teacher-only; текущий молчаливый redirect признан временным.
- mm-108 «Выбрать frontend transport/API seam и правила cache invalidation»: выбран единый Fetch/MSW path без mock-DI, operation-specific outcomes и typed rejected failures, Valibot trust boundary, feature-owned key factories и targeted/authoritative cache consistency.
- mm-64 «Выбрать критические пользовательские пути и гарантии»: все реализованные пути признаны бизнес-критичными; зафиксированы fail-closed integrity/access guarantees, порядок `risk → stability → frequency`, обязательное individual review и отложенные auth, bulk/quick-grading и local-draft детали.
- mm-109 «Выбрать persisted contract review-текста при переходе на Plate»: выбран versioned project-owned Plate-native JSON contract, строгая Valibot trust seam, единый компактный профиль без images и structured readonly без HTML.
- mm-67 «Ранжировать зоны рефакторинга по риску и отдаче»: после ограниченной Wave 0 рефакторинг идёт сквозными пользовательскими путями — Course access, Review/Grade/Student result, Course Attempts и двухчастный Course editing; горизонтальный big-bang и feature-local rewrites отвергнуты.
- mm-68 «Выбрать слоистую стратегию тестирования»: принята risk-weighted contract matrix с Vitest/Testing Library/MSW/Playwright, selective characterization, равноправным Chromium/Firefox/WebKit gate перед каждым merge и строгой flaky-политикой.

- mm-111 «Выбрать явный UX для отказа в course-local доступе»: course/resource invisibility сведена к generic `404`, role mismatch — к явному `403`; fail-closed loading, technical error и user-invoked recovery заменяют молчаливые redirects.

- mm-112 «Спроектировать paved road для соблюдения remote-data contract»: выбрано малое транспортное ядро; функциональные операции явно классифицируют HTTP-статусы и проверяют ответы, линтер запрещает обходы, автоматические повторы по умолчанию выключены.
- mm-114 «Определить роль bulk selection и quick grading в teacher workflow»: quick grading сохранён для публикации первых Reviews по 10–30 очно проверенным Attempts; bulk selection и изменение существующих Grades удаляются, а частичные конфликты получают per-Attempt outcomes и панель отклонённых оценок.
- mm-115 «Спроектировать Course access vertical и identity seam»: access-aware Course lookup разрешает slug в стабильный CourseId и course-local role; единая section policy и backend-authoritative resource operations заменяют redirects, username checks и отдельный access path одним clean cutover.
- mm-117 «Спроектировать individual Course Attempts vertical»: выбран полный атомарный список всех Attempts с URL-owned draft/applied filters, честными loading/stale/error states, revalidation без polling и детерминированной editable-intent навигацией без bulk selection.
- mm-116 «Спроектировать Review → Grade → Student result vertical»: Review публикуется атомарными Review Revisions с idempotent-повтором при неизвестном исходе; lease на сессию Review editor, manifest-gated полнота материала, `observeReviewRevision` с номерами revision для согласованности экранов и восемь slices от типа Grade до Read State.
- mm-118 «Спроектировать lifecycle Course Page Working Copy»: Course Draft Snapshot — личный черновик Teacher'а под Course Editing Lease по протоколу Review; фоновая синхронизация по состоянию с перечитыванием при неизвестном исходе, сверка публикации по активному snapshot, slug вне черновика и четыре slices от адреса курса до полного протокола lease.
- mm-119 «Спроектировать structured-document seam Course Page»: содержимое Course Page — собственный канонический документ с плоскими List Item-блоками, версионированным `data` и Task Reference; Plate живёт только в lossless adapter, read-only строит своё render tree с общими presentation-views; структурные операции — `BlockCommands` с одним шагом undo и `FocusIntent`; пять slices, первый идёт раньше сессии черновика из mm-118.
- mm-120 «Спроектировать матрицу тестовых контрактов критических вертикалей»: 156 контрактов по 9 вертикалям, у каждого один слой-владелец и именованные fixtures; инварианты I1–I8 доказаны независимо на нескольких слоях и в браузере, 16 E2E-путей в трёх движках; characterization только для списков mm-74 и фокуса; в стек добавлен fast-check, E2E идёт против MSW в браузере; вкладки одного браузера делят редактор локально при lease по auth session.
- mm-121 «Выбрать размещение Overall Feedback в compact quick grading»: Overall Feedback вводится полем прямо в строке quick grading; строка Course Attempts — три раскладки фиксированной высоты, diff в зоне задания, без кнопки «Ревью»; закреплённый top bar на всю страницу заменяет сайдбар фильтров (общий черновик и «Применить») и нижний бар; ⌥G, Mod+S и Esc с диалогом «Остаться».
- mm-132 «Спроектировать смену пишущей вкладки редактора»: lease общий на браузер, пишет одна вкладка, живые копии получают полную Working Copy после каждого изменения; смена идёт локально — добровольно после завершения запроса в полёте или силой через 3 с и только от живой копии; закрытая пишущая вкладка передаёт роль копии; выход скрывает Working Copy до входа того же User.
- mm-69 «Определить последовательность подготовки и выполнения рефакторинга»: рефакторинг идёт DAG из 44 slices — Wave 0 и основа (CI, транспортное ядро, characterization), Course access тремя PR, затем параллельные дорожки Review, Course Attempts и Course editing; шаг — один PR с собственными контрактами в трёх движках, вопросы к backend не блокируют, каждый из 162 контрактов матрицы привязан к одному slice; старая цепочка RAM-моков → MSW закрыта как заменённая.
