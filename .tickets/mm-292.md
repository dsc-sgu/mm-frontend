# Переименовать модули экранов попытки и страницы курса

## Решение

- `attempt-review` → `attempt-screen`.
- `page` → `page-view`.
- `page-edit` → `page-editor`.
- `review` сохраняет имя и владеет моделью проверки и её жизненным циклом.
- `page-document` — уже запланированный общий владелец документа для просмотра и редактора.

## Границы

Механическая замена путей и идентификаторов, где они описывают переименованный экран. Не менять адреса маршрутов и контракты API ради переименования каталогов. Названия доменных сущностей не заменяются названиями экранов. Ссылки в действующих планах должны указывать на новые пути.

## Проверка

Сборка, линтер и затронутые проверки маршрутов проходят. Изменений пользовательского поведения нет.

## Согласование с остальными планами

Это отдельная механическая задача, не условие вводить новые продуктовые правила. При параллельных ветках согласовать момент замены путей с работой по mm-227 и mm-228. Обновить актуальные инструкции, плановую раскладку модулей и ссылки в затронутых тестах; исторические имена в описании уже сделанных изменений не переписывать без необходимости.

Внешние маршруты и сериализованные ключи кэша не переименовываются только из-за нового имени каталога. Имя `review` не заменяется именем экрана.
