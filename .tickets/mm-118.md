# Спроектировать lifecycle Course Page Working Copy

## Question

Какие состояния, события, modules и interfaces должны описывать lifecycle редактирования Course Page: открытие или восстановление Course Draft Snapshot, synchronized Working Copy, unsynchronized local changes, mutation acknowledgements, lease loss, snapshot conflict, publish и cancel без ложного success или потери данных? Решение должно отделить authoritative server snapshot от локальной Working Copy, определить seam между editor model и transport/cache orchestration, использовать уже известные backend outcomes только как входные факты и не фиксировать окончательный backend API. Итогом должна быть последовательность будущих vertical slices; production/source code и тесты не менять.

## Решение: lifecycle Course Page Working Copy — личный черновик, синхронизация по состоянию, lease по протоколу Review

Решение задаёт целевую форму части 4A пути «Teacher редактирует и публикует Course Page» из [«Ранжировать зоны рефакторинга по риску и отдаче»](https://github.com/dsc-sgu/mm-frontend/issues/67). Известные исходы backend (`main` на `ddd9849`) использованы только как входные факты: `lock` возвращает `new | restored | stale_conflict`, черновик ищется по паре Course + User, публикация — compare-and-swap по версии Course с `409`, `cancel-edit` удаляет черновик, блоки создаются и перемещаются «после `afterBlockID`», id и LexoRank назначает сервер. Окончательный backend API не проектируется: зависимости внесены в [«Реестр frontend-вопросов к backend API»](https://github.com/dsc-sgu/mm-frontend/issues/113). Production/source code и тесты не изменялись.

### Термины

- **Course Draft Snapshot** — личный неопубликованный snapshot Teacher'а, основанный на одном опубликованном Course Snapshot. У Teacher'а не больше одного черновика на Course. Черновик становится stale, если раньше опубликован другой snapshot. Общего черновика всех Teachers нет.
- **Course Editing Lease** — исключительное истекающее право одного Teacher'а в одной сессии редактирования менять и публиковать свой черновик. Одновременно Course редактирует один Teacher. При снятии lease черновик сохраняется.
- Slug не входит в Course Snapshot.

Glossary обновлён, архитектурное решение записано в ADR [`docs/adr/0002-state-based-course-draft-sync.md`](https://github.com/dsc-sgu/mm-frontend/blob/docs/course-page-working-copy/docs/adr/0002-state-based-course-draft-sync.md); оба изменения — в PR [«docs: record course draft glossary and ADR»](https://github.com/dsc-sgu/mm-frontend/pull/127).

### Состав Working Copy

- Presentation metadata (title, shortTitle, description, color, icon), resources, content и ссылки на Task входят в черновик и публикуются вместе с ним.
- Свойства Task (название, условие, дедлайн, максимальная Grade) в Working Copy не входят. Их редактирование — [«Редактировать существующее задание в боковой панели»](https://github.com/dsc-sgu/mm-frontend/issues/41) и [«Согласовать task-only apply с существующим course draft»](https://github.com/dsc-sgu/mm-frontend/issues/107), вне этой карты. Расширяемость проверена: если свойства Task войдут в черновик, планировщик получит новый тип операции. Если task-only apply опубликует snapshot сам, черновик станет stale по уже описанному пути.
  - _Рабочее допущение до ответа backend._ Открыты в [«Реестр frontend-вопросов к backend API»](https://github.com/dsc-sgu/mm-frontend/issues/113): является ли Task подтипом блока Course Snapshot или отдельной сущностью Course, сохраняется ли identity Task между snapshots, входят ли дедлайны и другие свойства Task в Course Snapshot и публикуются ли они вместе с Course Draft Snapshot. Если backend ответит, что свойства Task публикуются вместе со snapshot, они войдут в Working Copy, а `planDraftSync` получит новый тип операции; lifecycle сессии не меняется.
- **Slug** остаётся в hero, но как текст `/{slug}` с действием «Изменить». Inline-поле сохраняется отдельной мгновенной операцией Course («Сохранить адрес» / «Отмена», подпись «Адрес меняется сразу, без публикации»). Route заменяется на новый slug. Сессия редактора привязана к `CourseId`, поэтому не перемонтируется. Живого поля нет: при автосохранении оно переименовывало бы курс во время набора.

### Синхронизация

- **Автоматическая и фоновая.** После ~1 с бездействия, не реже раза в 5 с при непрерывном наборе, сразу при уходе или публикации. Индикатор: «Сохранено» / «Сохранение…» / «Не сохранено · Повторить». Явного «Сохранить черновик» нет.
- **По состоянию** (ADR 0002). Чистая функция `planDraftSync(base, workingCopy) → DraftOperation[]` сравнивает Working Copy с `base`, последним подтверждённым состоянием черновика. Она строит create/patch/move/delete блоков и изменения metadata и resources. В полёте один batch, правки тем временем копятся локально. `base` обновляется по каждому acknowledgement. Редактор отдаёт только новый документ, а не операции.
- **Неизвестный исход** операции (сеть, `5xx`, невалидный ответ): черновик перечитывается, становится новой `base`, план строится заново. Это безопасно, потому что в черновик пишет только сессия с lease. Idempotency keys операциям черновика не нужны.
- Пока сервер назначает id блоков, сопоставление локальных и серверных id живёт внутри модуля синхронизации. Клиентские UUID убрали бы его.
- **Валидация.** В черновике допустимы значения, невалидные для публикации. Валидация — часть publish gate. Если backend отклоняет операцию черновика (ожидаемый отрицательный исход), batch останавливается, `sync` → `sync-rejected { reason }`, Working Copy не теряется, следующая правка строит новый план.

### Course Editing Lease

Протокол Review Lease из [«Спроектировать Review → Grade → Student result vertical»](https://github.com/dsc-sgu/mm-frontend/issues/116) целиком:

- клиент генерирует `leaseId` на сессию редактора;
- lease берётся автоматически при входе в `/edit`; read-only Course Page его не берёт;
- heartbeat ~20 с и при возврате на вкладку; незаметно истёкший lease берётся снова;
- при уходе lease снимается, черновик остаётся;
- вторая вкладка того же User открывается только для чтения с «Продолжить здесь»;
- занятый другим Teacher'ом lease даёт «Редактирует X · Попробовать снова».

`interrupted` наступает только при явном ответе backend, что lease не мой. Сетевой сбой heartbeat — это `sync-failed`, правки продолжаются локально, lease после восстановления связи берётся снова без участия Teacher'а.

Когда дойдёт до slice 4, lease выносится в общий module уровня course с двумя адаптерами: Review и черновик Course.

### Состояния сессии

```txt
opening
unavailable        { reason: 'not-found' | 'forbidden' | 'failed' }
lease-unavailable  { holder: { kind: 'teacher'; teacher } | { kind: 'own-session' } }
stale
editing            { base, workingCopy, sync }
publishing         { status: 'in-flight' | 'unconfirmed' }
discarding         { status: 'in-flight' | 'unconfirmed' }
interrupted        { holder, base, workingCopy }

sync: synchronized | pending | syncing | sync-failed | sync-rejected
```

| Состояние | Когда | Working Copy | Что видит Teacher |
|---|---|---|---|
| `unavailable` | Редактор не открылся | нет | `404`/`403` по [«Выбрать явный UX для отказа в course-local доступе»](https://github.com/dsc-sgu/mm-frontend/issues/111) или «Не удалось открыть редактор · Повторить» |
| `lease-unavailable` | При входе lease занят | нет | Опубликованная версия только для чтения, «Редактирует X · Попробовать снова» или «Открыт в другой вкладке · Продолжить здесь» |
| `stale` | `stale_conflict` при входе, повторном взятии или `409` при публикации | только для чтения до подтверждения | MVP: «Удалить черновик и начать заново» после подтверждения |
| `editing` | Lease мой | редактируется | Индикатор синхронизации |
| `publishing` / `discarding` | Команда в полёте или её исход не подтверждён | заморожена | Индикатор; при `unconfirmed` — «Повторить» |
| `interrupted` | Сессия работала, backend сообщил, что lease не мой | только для чтения | «Продолжить здесь» / «Попробовать снова», предупреждение при уходе |

После успешной публикации или удаления — переход на Course Page, отдельного состояния нет. Переходы — чистая `transitionCourseDraftSession(state, event)`: один union, вложенный `sync` есть только в `editing`, FSM-библиотека не нужна.

Основные события: `opened { new | restored }`, `open-stale`, `open-lease-unavailable`, `open-failed`, `edited`, `sync-started`, `sync-acknowledged`, `sync-rejected`, `sync-failed`, `draft-reread`, `lease-lost { holder }`, `lease-retaken`, `publish-requested`, `published`, `publication-unconfirmed`, `publication-reconciled`, `discard-requested`, `discarded`, `server-version-taken`, `own-version-kept`.

**Повторное взятие lease из `interrupted`:**

- `restored`, черновик равен `base` → `editing`, несинхронизированные правки целы, синхронизация продолжается;
- `restored`, черновик ≠ `base` (его изменила моя другая вкладка) → явный выбор: «Взять версию с сервера» (мои несинхронизированные правки отбрасываются после подтверждения) или «Перезаписать черновик моей версией» (новый план от новой `base`). Автоматического merge нет. Пока у черновика нет revision, отличие проверяется глубоким сравнением;
- `stale_conflict` → `stale`;
- `423` → `lease-unavailable`, Working Copy остаётся в памяти только для чтения, при уходе — предупреждение.

### Публикация, удаление, уход

- **Диалог публикации** один для кнопки «Опубликовать» и `Mod+S`: «Student'ы сразу увидят новую версию курса». Повторный `Mod+S` в диалоге подтверждает публикацию. Кнопка подтверждения и хоткей заблокированы ~0,5–1 с после открытия, `event.repeat` игнорируется. `Esc` закрывает диалог без публикации.
- **Publish gate** блокирует публикацию, если:
  - lease не мой;
  - есть ошибки валидации;
  - нет отличий от опубликованной версии (сравнение с загруженной read-проекцией);
  - есть `sync-rejected`;
  - публикация идёт или не подтверждена.

  При заблокированной публикации диалог не открывается: toast с причинами и фокус на первом невалидном поле. Несинхронизированные правки не блокируют: подтверждение сначала дожидается синхронизации.
- **Неизвестный исход публикации** → `publishing { unconfirmed }`, Working Copy заморожена. Сверка чтением активного snapshot Course:
  - он равен `draftSnapshotId` → опубликовано;
  - черновик жив и lease мой → «Публикация не прошла · Повторить»;
  - иначе → `interrupted`.

  Idempotency key не нужен: `draftSnapshotId` сам служит ключом сверки.
- **После публикации** — дождаться инвалидации Course Page, списка курсов и дедлайнов, затем перейти на Course Page с «Опубликовано».
- **«Удалить черновик»** заменяет «Сбросить»: подтверждение, если черновик отличается от опубликованной версии, затем `discarding` и переход на Course Page. Повтор при неизвестном исходе безопасен, если backend считает удаление отсутствующего черновика успехом. Сброса «к последнему сохранённому» нет.
- **Уход без публикации** сохраняет черновик. При следующем входе по `restored` — плашка «Открыт ваш неопубликованный черновик».
- **Защита от ухода** срабатывает только при несинхронизированных изменениях, в `publishing`/`discarding` с `unconfirmed` и в `interrupted`:
  - навигация внутри приложения → немедленная синхронизация с «Сохраняем…», ожидание до ~5 с; при неудаче — «Изменения не сохранены. Уйти и потерять их?»;
  - reload и закрытие вкладки → `beforeunload`;
  - lease снимается после подтверждённого ухода.
- **Stale в MVP** — только «Удалить черновик и начать заново» после подтверждения, Working Copy до этого видна для копирования. Полный read-only recovery остаётся в [«Восстанавливаться после lease loss и snapshot conflicts»](https://github.com/dsc-sgu/mm-frontend/issues/95).

### Modules и seam

```txt
features/course/features/
  course-draft/        ← lifecycle черновика
    api/               ← lock/init, heartbeat, чтение черновика, операции блоков,
                          metadata/resources, publish, discard; исходы по remote-data.md
    model/             ← transitionCourseDraftSession, planDraftSync, getPublishGate
    hooks/             ← useCourseDraftSession(courseId)
  page-edit/           ← UI редактора и структурированный документ (#119)
```

- `useCourseDraftSession(courseId)` отдаёт состояние и намерения: `edit`, `retrySync`, `publish`, `retryPublication`, `discardDraft`, `tryTakeLease`, `continueHere`, `startOver`, `takeServerVersion`, `overwriteWithMine`. Внутри скрыты lease и heartbeat, цикл синхронизации, acknowledgements, перечитывание, сверка публикации и эффекты на кэш.
- `base` и Working Copy живут в store сессии (vanilla Zustand, один на сессию, ключ — `CourseId`), а не в кэше TanStack Query. Query нужен только для опубликованных read-проекций и инвалидации после публикации. Оркестратор вызывает операции черновика напрямую, без `useMutation`.
- Seam с редактором: content передаётся заменой документа целиком, metadata и resources — обновлением полей. Состояние insert-panel уходит из store сессии в editor-scoped UI state.
- Working Copy — сериализуемые данные с пометкой `CourseId + draftSnapshotId + base`. Browser-local восстановление ([«Восстанавливать несинхронизированную Course Page Working Copy из браузера»](https://github.com/dsc-sgu/mm-frontend/issues/123)) добавится без изменения модели.

### Slices будущего рефакторинга

**Предпосылки:**
- `CourseId` и course-local role из [«Спроектировать Course access vertical и identity seam»](https://github.com/dsc-sgu/mm-frontend/issues/115);
- малое transport-ядро и MSW;
- общий prefix ключей `['course', courseId, …]`;
- read-side опубликованного Course Page поверх snapshots ([«Перевести course read-side на fetch и MSW поверх published snapshots»](https://github.com/dsc-sgu/mm-frontend/issues/89)) с id активного snapshot в проекции.

Каждый slice — clean cutover без compatibility layers; путь после него целостный и проверяется через interface своего module и наблюдаемый route outcome. Сценарии задаёт [«Спроектировать матрицу тестовых контрактов критических вертикалей»](https://github.com/dsc-sgu/mm-frontend/issues/120).

1. **Адрес курса вне черновика.**
   - Делает: inline «Изменить адрес» в hero, мгновенная операция смены slug, замена route, инвалидация lookup по slug и списка курсов; сессия редактора привязана к `CourseId`.
   - Удаляет: slug из Working Copy и из сохранения всего курса.
2. **Сессия черновика: открыть, править, опубликовать, удалить.**
   - Делает:
     - feature `course-draft`, `transitionCourseDraftSession`, store сессии без состояния insert-panel;
     - lock/init → `editing | stale | lease-unavailable | unavailable`;
     - базовый heartbeat и `interrupted` при явной потере lease;
     - `planDraftSync`, пока выполняемый перед публикацией;
     - `getPublishGate` и диалог публикации с `Mod+S`;
     - `publishing` со сверкой по активному snapshot;
     - «Удалить черновик» и `discarding`; MVP для `stale`;
     - плашка «Открыт ваш черновик»; переход на Course Page после инвалидации;
     - защита от ухода;
     - MSW: личные черновики, операции блоков, CAS publish, cancel.
   - Удаляет: `saveCoursePage`, «Применить», «Сбросить», `markWorkingCopySaved`, `isDirty`, вычисляемый сравнением всего курса.
3. **Фоновая синхронизация.**
   - Делает: планировщик 1 с / 5 с / сразу при уходе или публикации; `sync` и индикатор; ограниченный автоматический повтор и «Повторить»; перечитывание черновика при неизвестном исходе; `sync-rejected`; после reload `restored` возвращает всю синхронизированную работу.
   - Удаляет: синхронизацию только перед публикацией.
4. **Полный протокол Course Editing Lease.**
   - Делает: клиентский `leaseId`; heartbeat ~20 с и при возврате на вкладку; тихое повторное взятие; снятие при уходе с сохранением черновика; `lease-unavailable { own-session }` и «Продолжить здесь»; выбор «Взять версию с сервера» / «Перезаписать моей версией» в `interrupted`; общий lease module с адаптерами Review и черновика Course.
   - Удаляет: lease, общий для всех вкладок; ожидание TTL после ухода (зависит от backend).

## Уточнения из [«Спроектировать матрицу тестовых контрактов критических вертикалей»](https://github.com/dsc-sgu/mm-frontend/issues/120#issuecomment-6106418624)

- **Вкладки одного браузера.** Пишет одна вкладка, остальные показывают живую копию Working Copy только для чтения. «Продолжить здесь» меняет пишущую вкладку локально, без обращения к серверу: добровольно, если пишущая вкладка отвечает, или силой после таймаута. Lease привязан к браузеру — auth session, как Course lease на `mm-backend@ddd9849`; клиентского `leaseId` нет. Единственность пишущей вкладки обеспечивают Web Lock и счётчик смен в localStorage, который сверяется синхронно перед каждой записью. Перехват lease тем же User остаётся только для другой сессии: другого устройства или приватного окна. Протокол проектируется в [«Спроектировать смену пишущей вкладки редактора»](https://github.com/dsc-sgu/mm-frontend/issues/132). Это заменяет «вторая вкладка того же User открывается только для чтения с «Продолжить здесь»», `lease-unavailable { own-session }` для вкладок этого браузера и клиентский `leaseId` в slice 4.
- **`interrupted`** теперь возникает, только когда lease взяла другая сессия: другое устройство того же Teacher'а или другой Teacher.
- **Повторное взятие lease из `interrupted`.** `restored` и `new` обрабатываются одним правилом: черновик на сервере сравнивается с `base`; равен → `editing`, иначе выбор «Взять версию с сервера» (с подтверждением) или «Перезаписать черновик моей версией». `new` бывает, если другая сессия опубликовала или удалила черновик. `stale_conflict` → `stale`. `423` оставляет редактор в `interrupted` с новым holder: Working Copy остаётся только для чтения, предупреждение при уходе сохраняется.
- **Проверка revision черновика при записи** запрошена у backend: после силовой смены пишущей вкладки запрос, ушедший из замороженной вкладки до смены, иначе может дойти позже и молча перезаписать новые правки. Lease общий для вкладок браузера и этого не ловит.

Контракты: DRF-21, DRF-E3, TAB-01…TAB-09.

## Уточнения из [«Спроектировать смену пишущей вкладки редактора»](https://github.com/dsc-sgu/mm-frontend/issues/132#issuecomment-6108489305)

- **Вкладки редактора Course Page.**
  - Пишет одна вкладка браузера, остальные показывают живую копию: полную Working Copy вместе с `base` и статусом синхронизации после каждого изменения.
  - «Продолжить здесь» передаёт Working Copy и `base` локально.
  - Пакет синхронизации в полёте пишущая вкладка дожидается. `pending` и `sync-failed` передаются как есть.
  - Если исход пакета неизвестен, новая вкладка перечитывает черновик.
- **Силовая смена.**
  - Если пишущая вкладка молчит 3 с, продолжает только вкладка с живой копией.
  - Если перед заморозкой ушёл пакет, черновик перечитывается.
  - Запоздавший пакет замороженной вкладки закрывает проверка revision черновика на backend (TAB-07).
- **Закрытие пишущей вкладки.** Роль переходит первой копии в очереди. Предупреждение об уходе нужно, только если совместимой живой копии нет. Lease снимается с последней вкладкой.
- **`interrupted` и `lease-unavailable { own-session }`** теперь означают только другую сессию: другое устройство или приватное окно. Вкладки одного браузера видят друг друга локально.
- **Публикация и удаление черновика** при смене: запрос в полёте пишущая вкладка дожидается. Неподтверждённый исход передаётся новой вкладке, и та сверяет его по активному snapshot.
- В `useCourseDraftSession` намерение `continueHere` означает локальную смену вкладки.

ADR 0004 и правка ADR 0002 — в PR [«docs: record editor tab handoff glossary and ADR»](https://github.com/dsc-sgu/mm-frontend/pull/134).
