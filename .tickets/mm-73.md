# Перевести frontend с RAM-моков на fetch и MSW

## Цель

Перевести frontend с прямых вызовов stateful RAM-моков на настоящий transport boundary через `fetch`, временно обслуживая те же продуктовые сценарии с помощью MSW. Это должно позволить позже подключать backend без переписывания feature query/mutation modules.

## Контекст

- Текущий frontend — источник продуктовой истины и большой прототип; backend разрабатывается параллельно и затем будет адаптироваться к frontend с учётом сетевой эффективности.
- Текущие mock-данные одноразовые, frontend ещё не используется в production; обратную совместимость mock-форматов сохранять не нужно.
- Работа сознательно вынесена за пределы карты [«Восстановить понимание frontend и подготовить пакет решений для рефакторинга»](https://github.com/dsc-sgu/mm-frontend/issues/62), которая не меняет production code.

## Ожидаемый результат

- Query/mutation modules обращаются к явному transport/API seam, а не импортируют RAM-моки напрямую.
- В development/test сценариях запросы перехватываются MSW handlers, воспроизводящими нужные чтения, mutations и error cases.
- Domain/API contracts сохраняют удобную для frontend форму; отличия будущего backend изолируются adapters, если они понадобятся.
- MSW можно отключить или заменить реальным backend без переписывания потребителей data layer.
- Stateful mock behavior между связанными features (`page`, `access`, `attempts`, `attempt-review` и другими) остаётся согласованным.

## Не входит

- Реализация backend.
- Сохранение обратной совместимости текущих одноразовых mock-данных или их внутреннего формата.
- Автоматическое принятие текущей структуры RAM-моков как окончательного HTTP-контракта.
