# Восстанавливать несинхронизированную рабочую копию страницы курса из браузера

## Источники

- mm-118 — жизненный цикл рабочей копии страницы курса.

## Делает

После MVP добавляет восстановление неподтверждённой рабочей копии страницы курса из хранилища браузера — только для правок, которые сервер отклонил или не получил за долгий офлайн (раздел «Уже решено»). Черновики блоков на сервере остаются источником истины; локальная запись — только кандидат на восстановление изменений, которые сервер ещё не подтвердил.

## Готово, когда

- [ ] Правка блока, которую сервер отклонил (`sync-rejected`) или не получил, пока преподаватель был офлайн, сохраняется в браузере вместе с курсом, id блока и версией, от которой она сделана. Правки, которые сервер подтвердил, в браузере не хранятся.
- [ ] После перезагрузки страницы курса восстановление предлагается только после загрузки черновиков с сервера и только для блоков, чья версия на сервере не изменилась с момента правки.
- [ ] Восстановление не применяется само: преподаватель видит затронутые блоки и выбирает «Восстановить» или «Удалить». Запись по блоку, который на сервере уже изменился, можно только скопировать или удалить: слияния нет.
- [ ] Публикация, «Отменить все мои черновики» и успешная повторная отправка очищают запись.
- [ ] После выхода из аккаунта или входа другим пользователем чужую запись восстановить нельзя.
- [ ] Отказ хранилища браузера не мешает редактировать, а интерфейс не сообщает о ложном успехе восстановления.
- [ ] Отказ сервера, долгий офлайн с перезагрузкой, изменившийся на сервере блок, восстановление, удаление и смена пользователя проверены через наблюдаемое поведение.

## Уже решено

_Решено владельцем 2026-10-25:_ тикет остаётся в бэклоге с низким приоритетом и нужен только для отказов синхронизации: сервер отклонил правку (`sync-rejected`) или преподаватель долго был офлайн.

Почему так. В модели [mm-backend PR #187](https://github.com/dsc-sgu/mm-backend/pull/187) (mm-286) черновики блоков хранятся на сервере и переживают уход из редактора, а фоновая синхронизация пишет их через 1–5 с после правки. Правки последних секунд покрывает защита от ухода (DRF-12, DRF-13). Потерять можно только то, что сервер отклонил или так и не получил. Ещё одна причина держать тикет: черновики общие для всех устройств преподавателя, и версия черновика при записи не растёт (вопрос 5 комментария mm-113 про PR #187). Если правку перезапишут с другого устройства, локальная запись — единственная копия.

## Зависит от

- Стабильные идентичности черновика и семантика подтверждений и ревизий в согласованном контракте API фронтенда и бэкенда.
