# Github-style headerbar

# Что это такое?

Хедербар для страниц курса (возможно, не только курса), имеющий два уровня.

## Первый уровень

### Слева

- Инонка, при клике на которую происходит переход на dashboard
- breadcrumb

### Справа

- Кнопка для переключения темы
- Кнопка для просмотра уведомлений
- Кнопка для просмотра сообщений
- Кнопка профиля

### Поведение breadcrumb

#### Базовая модель

```
[Dashboard icon]  |  Context / Entity / Subentity / Action
```

Где:

- `Dashboard icon` — всегда ведёт на главную страницу пользователя;
- `Context` — обычно курс;
- `Entity` — задание, репозиторий, студент, попытка и т.п.;
- `Subentity` — коммит, конкретная попытка, конкретный репозиторий студента;
- `Action` — edit, review, deadlines, settings и т.д.

#### Иерархия breadcrumb на странице курса с точки зрения студента

| Страница | Breadcrumb |
|---|---|
| Корневая страница курса | `Операционные системы` |
| Репозиторий курса | `Операционные системы / Репозиторий` |
| Список коммитов репозитория курса | `Операционные системы / Репозиторий / Коммиты` |
| Конкретный коммит репозитория курса | `Операционные системы / Репозиторий / Коммиты / abc123` |
| Корневая страница задания | `Операционные системы / Лабораторная работа 1` |
| Diff попытки | `Операционные системы / Лабораторная работа 1 / Попытка #3` |

## Второй уровень

Навбар, содержащий подразделы страницы (например, для страницы курса, в котором пользователь является преподавателем, это может быть страница курса, попытки, репозиторий и так далее)

# Зачем это нужно?

Страница курса (во всяком случае для преподавателя) может помимо главной страницы или страницы задания содержать другие разделы. Их необходимо показывать таким образом, чтобы они были на видном месте, чтобы пользователь знал об их существовании. Мне кажется вариант с хедербаром в стиле гитхаба подходящим.

# Как реализовать?

Можно сделать компонент для этого хедербара, который бы располагался в layout'е приложения, а данные на каждой странице, чтобы как-то менять этот хедербар, можно хранить в static data.
