# Обновить React, Tailwind, React Virtual и Pierre Trees

## Source

- [«Провести аудит зависимостей и конкурирующих библиотек»](https://github.com/dsc-sgu/mm-frontend/issues/71), дополнение «Ревизия доступных версий»: cohort 8, React Virtual и Pierre Trees.
- [«Определить последовательность подготовки и выполнения рефакторинга»](https://github.com/dsc-sgu/mm-frontend/issues/69): эти обновления не попали ни в один slice последовательности.

## Что сделать

Каждый пункт — свой PR с проверкой `bun run lint`, `bun run build` и всех тестовых suites, которые к тому моменту есть в CI.

- [ ] React и React DOM 19.2 → 19.3 вместе с `@types/react` и `@types/react-dom`.
- [ ] Tailwind CSS и `@tailwindcss/vite` 4.1 → 4.3 вместе, затем `prettier-plugin-tailwindcss` 0.8.0 → 0.8.1.
- [ ] `@tanstack/react-virtual` 3.13 → 3.14. Используется в списке Course Attempts (`attempts/ui/virtualized-list.tsx`) и календаре дедлайнов (`deadlines-calendar/calendar.tsx`).
- [ ] `@pierre/trees` beta.4 → beta.6. Используется в дереве файлов Attempt review (`attempt-review/ui/file-tree.tsx`). Это beta: нужна smoke-проверка дерева файлов.

Версии указаны на момент аудита; перед началом проверить актуальные через `bun outdated`.

## Когда брать

Действует правило зон из #69. React Virtual и Pierre Trees задевают зоны Course Attempts и Review, поэтому их берут прямо перед slice своей зоны или после её slices. Подходящие slices: ATT4 (раскладки строки) или DEADLINES для React Virtual, REV3 (материал Attempt) для Pierre Trees.

React и Tailwind задевают всё приложение. Их лучше ставить после CH, когда Playwright в трёх движках уже в CI, и не параллельно со slices редактора Course Page.
