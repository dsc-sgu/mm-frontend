# Открывать и восстанавливать server-backed course draft

## Parent

[Перевести course dashboard и редактирование курса на общий mock backend](https://github.com/dsc-sgu/mm-frontend/issues/78)

## What to build

Открывать editor через server-backed lock/init lifecycle и восстанавливать persistent draft после reload. UI различает new, restored, stale_conflict и lock, удерживаемый другим преподавателем.

Использовать [backend research](https://github.com/dsc-sgu/mm-frontend/blob/a25a8ed9f8c485f5aaad5ba0beba4f7909a9cf63/docs/research/backend-snapshots.md).

## Acceptance criteria

- [ ] Только teacher текущего курса может начать editing session.
- [ ] Lock/init выполняется через fetch/MSW и возвращает согласованный draft identity.
- [ ] New draft открывается из active published snapshot.
- [ ] Restored draft повторно открывает server state после reload.
- [ ] Stale conflict не открывается как обычный редактируемый draft.
- [ ] 423 показывает доступную identity lock holder.
- [ ] Активная session поддерживает heartbeat и прекращает его после ухода.
- [ ] Lint и build проходят.

## Уточнения из [«Спроектировать lifecycle Course Page Working Copy»](https://github.com/dsc-sgu/mm-frontend/issues/118#issuecomment-6090347912)

Покрывается slice 2 «Сессия черновика»; вторая вкладка и перехват lease — slice 4.

- Исходы входа: `opening` → `editing` (`new` или `restored`, при `restored` плашка «Открыт ваш неопубликованный черновик»), `stale`, `lease-unavailable { holder: teacher | own-session }` или `unavailable { not-found | forbidden | failed }`.
- `stale` в MVP предлагает только «Удалить черновик и начать заново» после подтверждения (см. #95).
- `423` от другого Teacher'а показывает опубликованную версию только для чтения с «Редактирует X · Попробовать снова». Собственная другая сессия даёт «Продолжить здесь» и требует клиентского `leaseId` (вопрос в #113).
- Heartbeat ~20 с и при возврате на вкладку; незаметно истёкший lease берётся снова. Сетевой сбой heartbeat не прерывает редактирование.
- Сессия редактора привязана к `CourseId`, а не к slug.

Каноническим источником является решение по ссылке выше. Окончательную нарезку на implementation-тикеты определит [«Определить последовательность подготовки и выполнения рефакторинга»](https://github.com/dsc-sgu/mm-frontend/issues/69).
