# Epic: Review — атомарные Review Revisions, одна Grade на всех экранах и защищённая Working Copy

Epic группы «Review» из решения [«Определить последовательность подготовки и выполнения рефакторинга»](https://github.com/dsc-sgu/mm-frontend/issues/69#issuecomment-6108811160). Целевая форма — резолюции:

- [«Спроектировать Review → Grade → Student result vertical»](https://github.com/dsc-sgu/mm-frontend/issues/116);
- [«Выбрать persisted contract review-текста при переходе на Plate»](https://github.com/dsc-sgu/mm-frontend/issues/109);
- [«Спроектировать смену пишущей вкладки редактора»](https://github.com/dsc-sgu/mm-frontend/issues/132).

Уточнения взяты из [«Спроектировать матрицу тестовых контрактов критических вертикалей»](https://github.com/dsc-sgu/mm-frontend/issues/120). Решения закреплены в ADR 0001 «Review публикуется атомарными Review Revisions» и ADR 0004 «Lease принадлежит браузеру, вкладки делят редактор локально». Тикеты slices — sub-issues этого epic (таблица «Slices» в «Дополнительно»).

## Проблема

Преподаватель проверяет попытку, студент читает результат. Сейчас на этом пути не держится ни одна гарантия:

- **Сохранение затирает чужое.** «Сохранить» отправляет проверку полной заменой вместе с ответами. Ответ студента, пришедший, пока преподаватель правит проверку, пропадает. Версия не сверяется: два преподавателя молча перезаписывают друг друга. Бронь проверки существует только как мок-события в списке попыток курса.
- **Неизвестный исход не обрабатывается.** Сбой сети при сохранении неотличим от отказа. Повтор никак не связан с первой отправкой, поэтому возможен ложный успех или ложный провал.
- **Оценка — произвольное число.** `score` разбирается заменой первой `,` на `.`, без ограничения точности. Существующую оценку можно стереть, и попытка снова выглядит непроверенной.
- **Материал попытки собирается на клиенте.** Список изменённых файлов вычисляется из двух снимков репозитория, полноту никто не проверяет. Пул diff Workers живёт на всём `_authenticated`. Если Worker или WASM недоступны, страница бесконечно висит на загрузке.
- **Текст проверки — HTML из TipTap.** HTML лежит в модели и в моках. Ссылка и картинка вставляются через `window.prompt`. Это другой редактор, не Plate, на котором сделана страница курса.
- **Оценка на разных экранах берётся из разных источников.** Проверка, переключатель попыток, список попыток курса и история попыток на странице задания читают разные RAM-моки. История попыток захардкожена. Адаптер `resolveLegacyParams` переводит стабильные идентификаторы обратно в slug и username ради старого источника.
- **Результат студента зависит от diff.** Пока diff не загрузился, студент не видит ни оценки, ни общего отзыва. Отметка «просмотрено» (`TaskAttemptAttention`) не связана с тем, что студент действительно видел.
- **Работу легко потерять.** Уход из редактора проверки, переключение попытки, перезагрузка и закрытие вкладки не предупреждают о несохранённых изменениях. Две вкладки одного преподавателя правят одну проверку независимо.

## Решение

Проверка публикуется атомарными версиями. Оценка, общий отзыв и комментарии преподавателей копятся в рабочей копии проверки и становятся видны студенту одной публикацией — с одним `idempotencyKey` и сверкой `baseRevision`. Ответы — отдельные мгновенные операции вне рабочей копии и брони проверки.

- **Редактор проверки** («Проверка попытки #N») — глубокий модуль: чистая машина состояний `transitionReviewSession`, `getPublishGate` со всеми причинами блокировки публикации и хук `useReviewSession`. Бронь, повторы публикации и обновление проекций скрыты внутри.
- **Неизвестный исход публикации** — состояние `publication-unconfirmed`. Рабочая копия заморожена, повтор идёт с тем же ключом. `revision-conflict` и потеря брони переводят редактор в `interrupted` с панелью «Неопубликованные изменения».
- **Оценка** — проверенный тип с точностью до тысячных. Пустое поле невалидно, команды «снять оценку» нет.
- **Материал попытки** — атомарный манифест изменённых файлов от бэкенда и содержимое по записям манифеста. Полнота — чистая функция. Публикация разрешена только при полном материале и готовом diff Worker. Пул Workers живёт только на странице попытки и в редакторе проверки.
- **Текст проверки** — `ReviewTextDocument` на Plate, без HTML в модели. Единственная граница доверия для HTML — вставка из буфера обмена.
- **Одна оценка на всех экранах.** Каждая проекция с оценкой несёт номер версии проверки. `observeReviewRevision` монотонно пишет проверку в свой кэш и инвалидирует чужие проекции через их фабрики ключей.
- **Бронь проверки** принадлежит сессии входа. Вкладки одного браузера делят редактор локально: пишет одна, остальные показывают лайв-копию.
- **Страница попытки у студента** показывает оценку и общий отзыв независимо от diff. Отметка прочитанности передаёт то, что студент действительно видел.

Последовательность этапов из #69:

| Этап | Что делает | После |
|---|---|---|
| V-PIERRE | Pierre Diffs 1.4, dedupe Shiki, кэш Promise в Shiki | W0-1 |
| REV1 | Оценка | ACC3 |
| REV2 | Раздельные операции чтения, единое состояние MSW для попыток и проверок | REV1 |
| REV3 | Материал попытки и готовность diff | REV2, V-PIERRE |
| REV4 | Текст проверки на Plate | REV2, DOC1 |
| REV5 | Ответы вне рабочей копии | REV4 |
| REV6 | Ядро редактора проверки | REV3, REV5, KB |
| REV7 | Бронь проверки, общий модуль брони и протокол вкладок | REV6 |
| REV8 | Результат студента и прочитанность проверки | REV6 |

Порядок внутри вертикали:

- REV4 идёт до REV5 и REV6, чтобы ответы и рабочая копия сразу строились на `ReviewTextDocument`.
- REV7 идёт после REV6. Между ними публикацию защищает только `baseRevision`: целостность сохраняется, страдает лишь удобство совместной работы.

Этапы, которые не помещаются в один контекст агента, режутся на тикеты с дробными id (см. «Slices» в «Дополнительно»).

## User Stories

### Grade

1. As a Teacher, I want to enter a Grade with either `,` or `.` as the decimal separator, so that I type it the way I'm used to.
2. As a Teacher, I want a Grade with more than three decimal places to be rejected with an error at the field instead of rounded, so that the published Grade is exactly what I meant.
3. As a Teacher, I want a Grade above the Task's maximum grade to be rejected at the field, so that I can't publish an impossible Grade.
4. As a Teacher, I want an empty Grade field to block publication for both a first and an existing Review, so that a Review never appears without a Grade and an existing Grade can't be cleared.
5. As a Student, I want my Grade to be the same on the Attempt page, in the Task's attempt history and everywhere else, so that I'm never confused about which value counts.
6. As an assistive-technology user, I want the Grade field to announce its error and invalid state, so that I know why I can't publish.

### Материал Attempt

7. As a Teacher, I want to see what the Attempt is compared with («Сравнение с попыткой #N», a template or an empty tree), so that I interpret the diff correctly.
8. As a Teacher, I want the list of changed files to come from the backend, so that no file of the Attempt is silently missing from my review.
9. As a Teacher, I want files whose content failed to load to be listed by name with «Повторить», so that I can recover only what failed.
10. As a Teacher, I want publication blocked while any changed file is unloaded, with the count in the reason, so that I never grade an Attempt I haven't fully seen.
11. As a Teacher, I want binary, too-large and unsupported files marked «не отображается» without blocking publication, so that such files don't make an Attempt ungradable.
12. As a Teacher, I want a diff that can't be rendered (Worker or WASM unavailable) to show an error with «Повторить» instead of an endless loader, so that I know what happened.
13. As a Teacher, I want my Grade, Overall Feedback and comments to stay editable while the material is incomplete or the diff failed, so that a technical failure doesn't stop me from writing.
14. As a User on the Course Page or in Course Attempts, I want no diff Workers to start, so that pages that don't show a diff stay light.

### Review-текст

15. As a Teacher, I want Overall Feedback, root comments and replies to support paragraphs, bold, italic, strike, inline code, quotes, nested lists, code blocks and links, so that I can format feedback clearly.
16. As a Teacher, I want to insert a link through a dialog that validates the address and returns focus to the text, so that adding a link doesn't break my typing.
17. As a Teacher, I want links restricted to `http`, `https` and paths inside MergeMinds, so that feedback can't carry dangerous or broken links.
18. As a reader of a Review, I want internal links to open in the current tab and external ones in a new tab, so that navigation behaves predictably.
19. As a Teacher pasting formatted text, I want unsupported formatting, images, scripts and styles removed while the text is kept, so that pasted content is safe and nothing I wrote disappears.
20. As a Teacher, I want a cleared Overall Feedback to mean «no Overall Feedback» and empty comments or replies to be impossible to submit, so that a Review never shows empty messages.

### Replies

21. As a Student, I want to reply to a Teacher's root comment immediately, independently of whether a Teacher is editing the Review, so that I can ask a question at any time.
22. As a Student, I want my reply to survive a Teacher publishing a new Review Revision, so that my question doesn't disappear.
23. As a Teacher, I want to reply to a thread without taking the Review Lease, so that I can answer while another Teacher grades.
24. As an author, I want to edit and delete only my own messages, so that nobody changes what I wrote.
25. As a participant, I want a deleted root comment to leave «Комментарий удалён» with the other authors' replies kept, so that the discussion stays readable.

### Review editor и публикация

26. As a Teacher, I want to accumulate Grade, Overall Feedback and my root comments and publish them as one Review Revision, so that the Student never sees a half-updated Review.
27. As a Teacher, I want to select a line or a range in the diff of a file and side and attach a root comment to exactly that range, so that the Student sees the thread on the same lines.
28. As a Teacher, I want to see every current reason why publication is blocked, not only the first, so that I can fix them all at once.
29. As a Teacher, I want to change only the Grade, Overall Feedback and my own root comments while other Teachers' root comments stay read-only, so that I don't overwrite colleagues.
30. As a Teacher whose publication got no confirmation, I want «Публикация не подтверждена» with my Working Copy frozen and retries that can't create a second Review, so that a network failure never leads to a false success or a duplicate.
31. As a Teacher, I want «Повторить» after automatic retries are exhausted, so that I decide when to try again.
32. As a Teacher whose Review was changed by someone else or whose lease was lost, I want to see the latest Review Revision and my unpublished changes in «Неопубликованные изменения», each copyable and applicable after I take the lease again, so that I lose nothing and nothing is merged behind my back.
33. As a Teacher with unpublished changes, I want a confirmation before navigating away, switching Attempt in the selector, reloading or closing the tab, so that I don't lose work by accident.
34. As a Teacher whose publication isn't confirmed, I want leaving to warn «Публикация не подтверждена», so that I don't leave an unknown outcome behind.
35. As a Teacher viewing a Review without changes, I want to leave freely, so that the guard doesn't get in the way.
36. As a Teacher who just published, I want Course Attempts and the Task's attempt history to show the new Grade, so that I trust the publication went through.

### Review Lease

37. As a Teacher, I want the Review editor to take the Review Lease automatically when I open it, so that I can start reviewing immediately.
38. As a Teacher, I want the Attempt page to never take the lease, so that just looking at an Attempt doesn't block colleagues.
39. As a Teacher opening a Review another Teacher is editing, I want read-only mode with «Проверяет X» and «Попробовать взять на проверку», and no automatic takeover, so that we don't overwrite each other.
40. As a Teacher, I want the lease kept alive while the Review editor is open and taken again if it silently expired, so that background tab throttling doesn't cost me the lease.
41. As a Teacher, I want the lease released when I leave the Review editor or switch Attempt, and not released by publishing, so that colleagues can continue and I can keep editing after a publication.
42. As a Teacher whose own lease is held by another session (another device or private window), I want «Открыт в другой сессии» with «Вернуть сюда», so that I can move my work between devices.

### Вкладки одного браузера

43. As a Teacher who opens the same Review in a second tab, I want a live read-only copy of my Working Copy there, so that I see my latest changes everywhere.
44. As a Teacher, I want «Продолжить здесь» to move editing to this tab with all my changes and without contacting the server, so that switching tabs is instant and lossless.
45. As a Teacher whose publication is in flight or unconfirmed, I want a tab switch to keep the publication, its key and the frozen Working Copy together, so that no duplicate Review appears.
46. As a Teacher, I want the next tab to continue editing by itself when the editing tab closes, so that my work keeps being protected.
47. As a Teacher whose editing tab hangs, I want a live copy to continue after 3 s of silence, and the hung tab to send nothing when it wakes up, so that a frozen tab neither blocks nor overwrites me.
48. As a Teacher with tabs of different MergeMinds versions, I want an explanation instead of an unsafe handoff, so that an old tab can't corrupt my Working Copy.
49. As a User signing out in one tab, I want editing stopped in every tab with the Working Copy hidden and kept until the same User signs in again, so that a shared computer doesn't leak or lose work.
50. As a different User signing in on that browser, I want to never see or receive the previous User's Working Copy, so that reviews stay private.

### Результат Student'а

51. As a Student, I want to see my Grade and Overall Feedback even when the diff fails to load, so that a technical failure doesn't hide my result.
52. As a Student whose Attempt has no Review yet, I want the diff and «Ещё не проверено» without a read mark, so that I know the Attempt is waiting.
53. As a Student, I want a Review marked read only up to the revision and the last Teacher reply I actually saw, so that later changes still show as new.
54. As a Student, I want a new Review Revision or a Teacher's reply to make the Review unread again, while my own replies don't, so that I notice only what's new to me.
55. As a Student, I want «Идёт синхронизация» only when the backend says so, so that the page doesn't invent states.
56. As an assistive-technology user, I want the Attempt page and the Review editor (editing and interrupted) to pass automated accessibility checks, so that I can use them.

### Разработка

57. As a frontend developer, I want Review reads addressed only by `AttemptId` with one canonical MSW state for Attempts and Reviews, so that no adapter turns identities back into locators.
58. As a frontend developer, I want every projection with a Grade to carry its Review Revision number, so that each cache owner can reject stale data.
59. As a frontend developer, I want one `observeReviewRevision` called by publication, Review loading and later quick grading and SSE, so that cache consistency rules live in one place.
60. As a frontend developer, I want the lease and the tab protocol to be a course-level module with a Review adapter, so that Course editing (DRF4) reuses it instead of copying it.
61. As a test author, I want `world:review` to contain Attempts with and without Review, a revision with comments of two Teachers and a Student's reply, and a manifest with text, binary and too-large entries, so that every contract has a named fixture.
62. As an E2E test author, I want all pages of one browser context and every reload to share one mock backend state, so that multi-actor and two-tab scenarios run against one backend.

## Решения по реализации

### Термины и места

- **Attempt page** («Попытка #N», `…/$attemptNumber`) — immutable Attempt и её опубликованная Review. Здесь Student видит свой результат, а Teacher смотрит без lease. Replies доступны обоим.
- **Review editor** («Проверка попытки #N», `…/$attemptNumber/review`) — только Teacher: Review Lease, Review Working Copy, публикация.
- **review-text editor** — rich-text редактор, чтобы «Review editor» означал только страницу.
- **changed-files manifest** — инженерный термин (в UI «Изменённые файлы»): авторитетная опись записей Attempt относительно baseline.
- В коде `score`/`maxScore` заменяются на `grade: Grade` и `Task.maxGrade`. `publishedAt`/`publishedBy` — атрибуты Review Revision, а не Grade.

### Раскладка modules

Из резолюции #116 с уточнением #132 (lease и вкладки — общий module уровня course):

```txt
features/course/
  model/grade.ts
  ui/grade-field.tsx
  features/
    review/            ← Review Revision, Working Copy, публикация, сверка,
                          Read State, replies, observeReviewRevision, reviewKeys
    lease/             ← серверный lease и протокол вкладок; адаптер Review (REV7),
                          адаптер черновика Course (DRF4)
    attempt-review/    ← Attempt page и Review editor: manifest и полнота, diff,
                          file tree, UI threads, selector Attempts
    attempts/          ← Course Attempts и quick grading (переименование — в Course Attempts epic)
    task/              ← страница Task, история попыток Student'а
```

Feature `grading` исчезает в REV1.

### Grade (REV1)

- Тип `Grade` создаётся только проверенным разбором ввода (`,` и `.`). Больше трёх знаков после запятой — ошибка, а не округление. Сравнение и сложение — в целых тысячных. `maxGrade` подчиняется той же точности.
- Пустое поле Grade делает Working Copy невалидной и для первой, и для существующей Review. Команды «снять Grade» нет.
- Поле Grade — общий UI в `course`. Его используют Review editor и quick grading в Course Attempts.
- Точный десятичный тип и wire-формат Grade — вопрос к backend в #113 (`tasks.max_grade` сейчас `real`).

### Read operations и единое состояние (REV2)

- В состоянии mock backend появляются Reviews: Review Revision с номером, Grade, Overall Feedback, root comments с привязкой и автором, replies. Attempts получают время отправки и Task — `maxGrade`.
- **Раздельные операции вместо aggregate:**
  - Review по `AttemptId`;
  - сведения Attempt для шапки;
  - Attempts Student'а в Task для selector;
  - история попыток Student'а на странице Task.

  Все читают одно состояние. Каждая проекция с Grade несёт номер Review Revision.
- `reviewKeys` и ключи проекций расширяют общий prefix `['course', courseId, …]` через свои key factories.
- **Удаляется адаптер identity → locator** — уточнение REV2 в [#69](https://github.com/dsc-sgu/mm-frontend/issues/69#issuecomment-6162616027):
  - read operations Attempt/Review используют стабильные identities и каноническое состояние MSW, а не прежний stateful RAM-источник через route locators;
  - `LegacyParams` и `resolveLegacyParams()` удалены вместе с любым эквивалентом под другим именем;
  - временные mutations, HTTP cutover которых принадлежит REV5/REV6, адресуют каноническое состояние прямо по стабильным IDs и не удерживают адаптер;
  - второго независимого stateful-источника Attempt/Review нет. Генераторы deterministic fixtures остаются, но не становятся альтернативным источником server state.
- Разрешение route locators `Username + AttemptNumber → UserId / AttemptId` на входе в route остаётся частью ACC2.

### Материал Attempt и готовность diff (REV3)

- **Baseline** выбирает backend и описывает его в manifest: Attempt (возможно, другой Task той же Task Group), шаблон или пустое дерево. Frontend показывает «Сравнение с …» и адресует материал только `AttemptId`.
- **Загрузка.** Сначала атомарный manifest, затем содержимое по записям (transport может группировать). Содержимое immutable. Автоматический retry ограничен для каждой записи, ручной «Повторить» перезапрашивает только упавшие.
- **Полнота** — чистая функция от manifest и статусов записей: `complete` либо `incomplete { count }`. Будущий streaming заменит только способ доставки.
- **Нетекстовые записи** (`binary`, `too-large`, `unsupported`) получают пометку «не отображается» и полноту не блокируют.
- **Diff Worker pool** монтируется только на Attempt page и в Review editor и имеет состояния `loading | ready | failed` с «Повторить». `failed` блокирует публикацию, поля Working Copy остаются редактируемыми.
- **Фабрика Workers** передаётся module готовности diff как зависимость. Component-тесты подставляют управляемый фейк (см. «Решения по тестированию»).
- **Удаляются** вычисление changed files на клиенте, pool на `_authenticated` и бесконечный loader.
- **Лимиты Worker pool** — не slice: их подтверждают замером после REV3 (#69).

### Review-текст (REV4)

- Overall Feedback, root comment и reply используют один persisted contract `ReviewTextDocument`: versioned project-owned schema `{ version: 1, children: ReviewTextBlock[] }`.
- **Профиль v1:**
  - paragraph и hard break;
  - bold, italic, strike, inline code;
  - blockquote;
  - nested ordered и unordered lists без произвольного start;
  - plain code block;
  - links.

  Headings, horizontal rules и images в v1 нет.
- **Ссылки** проверяет общая политика из DOC1 (`course/model/links.ts`): `http`, `https` и root-relative допустимы, остальное отклоняется.
- **Schema строгая.** Неизвестные version, node, mark, field или запрещённый URL делают ответ invalid. Содержимое не урезается молча.
- **HTML не входит в модель.** Единственная trust seam — paste: DOMPurify → converter → normalizer. Plain-text paste остаётся plain. Edit и readonly используют один Plate profile, readonly строит React elements без `dangerouslySetInnerHTML`.
- **Пустота.** Очищенный Overall Feedback — `null`. Root comment и reply persist-ятся только непустыми после нормализации whitespace.
- Dialog ссылки заменяет `window.prompt`. Fixtures разово конвертируются: dual reader и HTML fallback не сохраняются.
- Общий rich-text UI и политика ссылок приходят из DOC1 (`course/ui/rich-text`, `course/model/links.ts`).

### Replies (REV5)

- Создание, правка и удаление reply — мгновенные HTTP-операции вне Working Copy, revision и Review Lease. Автор управляет только своими сообщениями.
- Save больше не несёт replies.
- Удалённый root comment оставляет «Комментарий удалён», replies других авторов сохраняются.
- Reply Teacher'а делает Review непрочитанной. Сам сигнал Read State показывает REV8.
- Какие сущности возвращают mutations reply — вопрос к backend в #113.

### Review editor и публикация (REV6)

- **Машина состояний.** Чистая функция `transitionReviewSession(state, event)` с состояниями `loading | unavailable | viewing | editing | publishing | publication-unconfirmed | interrupted`. Запрещённые переходы — явные no-op.
- **Hook.** `useReviewSession(attemptId, intent)` отдаёт состояние и намерения: `editGrade`, `editFeedback`, `editOwnComment`, `publish`, `retryPublication`, `tryTakeLease`, `continueHere`, `applyRecoveryItem`, `discardRecovery`. `continueHere` означает локальную смену вкладки (#132), «Вернуть сюда» — отдельный перехват lease тем же User.
- **Publish gate.** `getPublishGate(...)` возвращает `{ status: 'ready' }` либо `{ status: 'blocked'; reasons }`. Причины:
  - lease не мой;
  - revision не загружена;
  - материал неполон (число записей);
  - Worker `failed`;
  - Grade отсутствует, больше максимума или с лишними знаками;
  - нет изменений;
  - публикация идёт или не подтверждена.

  UI показывает все текущие причины.
- **Контракт публикации** — форма уровня домена из #116 с уточнением #120/#132: `leaseId` нет, lease принадлежит auth session.

  ```ts
  type PublishReviewInput = {
    attemptId: AttemptId;
    baseRevision: ReviewRevisionNumber | null; // null — первая Review
    idempotencyKey: IdempotencyKey;
    grade: Grade;
    overallFeedback: ReviewTextDocument | null;
    ownRootComments: readonly OwnRootComment[]; // полный набор своих, id новых генерирует клиент
  };

  type PublishReviewResult =
    | { status: 'published'; revision: ReviewRevision }
    | { status: 'revision-conflict'; latestRevision: ReviewRevisionNumber }
    | { status: 'lease-not-held'; holder: TeacherSummary | null }
    | { status: 'not-found' }
    | { status: 'forbidden' };
  ```

- **Неизвестный исход.** Отказ операции (сеть, `5xx`, невалидный ответ) — `publication-unconfirmed`. Working Copy заморожена: тот же ключ обязан нести то же содержимое. Сначала идёт ограниченный автоматический повтор с тем же `idempotencyKey`, затем «Повторить». Ответ на повтор — авторитетная сверка. Новый ключ появляется только после авторитетного исхода.
- **`interrupted`.** `revision-conflict` или потеря lease показывают авторитетную последнюю revision. Working Copy уходит в панель «Неопубликованные изменения»: Grade, Overall Feedback и каждый свой root comment с привязкой, всё можно скопировать. После повторного взятия lease элементы переносятся кнопкой «Применить». Автоматического слияния нет.
- **Привязка root comment** к файлу, стороне diff и диапазону строк — контракт целостности (REV-12). Хранение привязки — вопрос к backend в #113.
- **Права.** Держатель lease меняет Grade, Overall Feedback и свои root comments. Root comments других Teachers только для чтения.
- **Защита при уходе** — уточнения [#87](https://github.com/dsc-sgu/mm-frontend/issues/87):
  - несохранённой считается Working Copy, отличная от последней Review Revision;
  - подтверждение нужно при навигации по приложению, переключении Attempt через selector, reload и закрытии вкладки;
  - в `publication-unconfirmed` уход предупреждает «Публикация не подтверждена»;
  - Attempt page и Review editor без изменений уход не блокируют;
  - lease снимается только после подтверждённого ухода (REV7).
- **Удаляются** `useAttemptReviewDraft`, статусы `pending-*`, «очистка» Grade и ручная инвалидация в Save.

### Согласованность Grade (REV6)

- `observeReviewRevision(queryClient, { attemptId, courseId, taskId, studentId, revision })` живёт в `review`:
  - монотонно пишет авторитетную Review в свой cache, отменяя идущий запрос; старая revision не заменяет новую;
  - инвалидирует чужие проекции по prefix через их публичные key factories, не читая их данных.
- Её вызывают публикация и загрузка Review, позже — quick grading (ATT6) и SSE (#98). Это не шина событий.
- Сравнение revision происходит только внутри каждого владельца cache.
- Каждый ответ содержит одну целостную revision. «Идёт синхронизация» показывается только по явному сигналу backend.

### Review Lease (REV7)

- **Владелец.** Lease покрывает Review конкретной Attempt, включая первую публикацию. Он принадлежит auth session (ADR 0004), клиентского `leaseId` нет. В UI показывается имя Teacher'а.
- **Взятие.** Lease берётся автоматически при входе в Review editor. Attempt page lease никогда не берёт.
- **Heartbeat** — примерно каждые 20 с, пока Review editor открыт, и сразу при возвращении на вкладку. Незаметно истёкший свой lease берётся снова. Если его взял другой Teacher — `interrupted`.
- **Снятие** — при уходе из Review editor (после подтверждения) и при переключении Attempt. Публикация lease не снимает. Lease снимается, когда уходит последняя вкладка Review editor этой Attempt.
- **Lease занят при входе:**
  - чужой holder — только чтение, «Проверяет X» и «Попробовать взять на проверку», holder обновляется при focus, автоматического захвата нет;
  - holder — сам User из другой сессии — «Открыт в другой сессии — на другом устройстве или в другом окне · Вернуть сюда».
- **Механика** повторяет Course lease backend: TTL, heartbeat, `423` с holder. Обобщение до lease по id ресурса, перехват тем же User и снятие при logout — рабочие допущения #113, помеченные в handlers.
- **Удаляются** mock-события lease для Review.

### Протокол вкладок (REV7)

Протокол из #132 становится частью общего module `lease`. Имя ресурса — `mm:editor:{UserId}:review:{AttemptId}`.

- **Кто пишет.** Запись `{epoch, writer}` в localStorage. Каждая смена увеличивает `epoch`. Перед каждой записью на сервер, включая heartbeat, вкладка синхронно сверяет свой `epoch` и `UserId` сессии (`writeGuard`).
- **Web Lock** выбирает следующую пишущую вкладку и сообщает о закрытии прежней. **BroadcastChannel** доставляет живую копию и сообщения смены.
- **Живая копия** — полная Working Copy после каждого изменения вместе со статусами публикации и holder lease. Новая копия заменяет старую по `(epoch, seq)`.
- **Добровольная смена.** Пишущая вкладка дожидается публикации в полёте. `publication-unconfirmed` передаётся вместе с `idempotencyKey` и замороженной Working Copy. Вместе с ней переходят черновики полей ввода. История undo, выделение, курсор и scroll теряются.
- **Силовая смена.** Если пишущая вкладка молчит 3 с, продолжает только вкладка с живой копией. Порядок: сначала счётчик, потом `steal` lock'а. Проснувшаяся бывшая пишущая вкладка сверяет счётчик раньше, чем узнаёт о потере lock, и ничего не отправляет. Вкладка без живой копии говорит «Редактор открыт в другой вкладке, она не отвечает — перейдите в неё».
- **Закрытие пишущей вкладки.** Первая копия в очереди продолжает сама. Предупреждение об уходе нужно, только если совместимой копии нет.
- **Версии.** Одно `TAB_PROTOCOL_VERSION` покрывает сообщения и Working Copy. При несовпадении нет ни живой копии, ни смены.
- **Выход из аккаунта** останавливает запись во всех вкладках. Working Copy скрыта экраном «Вы вышли из аккаунта» и держится до входа тем же User. Вход другим User её удаляет.
- **bfcache.** `pagehide` — уход. При `pageshow` с `persisted` вкладка продолжает со своей Working Copy, только если запись о пишущей вкладке не менялась.
- **`interrupted`** видят все вкладки браузера, действовать можно из любой.

### Результат Student'а и Read State (REV8)

- Attempt page показывает Grade и Overall Feedback независимо от diff. При сбое diff threads появятся вместе с ним.
- Без Review — diff и «Ещё не проверено», без отметки прочитанности.
- `markReviewSeen` передаёт номер revision и последний показанный reply Teacher'а. Отметка `seen` optimistic. Более новая revision снова делает Review непрочитанной.
- Непрочитанность в истории попыток на странице Task читается из того же состояния.
- **Удаляется** `TaskAttemptAttention`.

### Mock backend и test-only канал

- **`world:review`** расширяется до мира из матрицы. Task «Сортировки» (`maxGrade` 10):
  - Саша, Attempt #1: Review revision 2 — Grade 7,5, Overall Feedback, root comments Анны и Бориса, reply Саши;
  - Саша, Attempt #2: без Review; manifest — 3 текстовые записи, binary и too-large; baseline — Attempt #1;
  - Петя, Attempt #1: без Review.

  Каждый slice добавляет в мир только то, что нужно его контрактам.
- **Рабочие допущения #113** помечены в handlers: idempotency key, `423` с holder, revision в проекциях, baseline и manifest. Ответ на отказ не несёт имени, файлов или Grade чужого Student'а.
- **Новые профили отказов:**
  - `fail:lost-response` — handler применяет изменение и возвращает сетевую ошибку;
  - `fail:entry` — содержимое записи manifest падает N раз или всегда;
  - `fail:worker` — только Playwright: скрипт Worker или WASM блокируется через route.
- **Test-only канал** расширяется по мере потребителей:
  - удержание и отказ названных операций (публикация, записи manifest, lease);
  - смена session без сброса мира.
- **Общее состояние для E2E.** Только в test build состояние mock backend пишется в localStorage после каждого ответа и читается перед каждым запросом. Все страницы одного BrowserContext и все перезагрузки видят один backend. Второй участник появляется сменой session через канал, а не вторым BrowserContext. Появляется в первом slice, которому это нужно. Обычный dev-режим по-прежнему сбрасывает состояние при каждой загрузке.
- **Write-through в Course Attempts.** До ATT1 список Course Attempts остаётся на своём RAM-моке. Публикация в MSW-состоянии пишет Grade и туда, как сейчас делает Save. ATT1 удаляет эту запись.
- **Список исключений ESLint** для импортёров RAM-моков сокращается на модули attempt-review и истории Task.

**Seams** (согласованы):

- **Model и Static.** Чистые функции через их interface:
  - разбор и арифметика Grade;
  - полнота материала;
  - schema `ReviewTextDocument` и политика ссылок;
  - проекция удалённого root comment;
  - Read State;
  - `transitionReviewSession` (полная таблица состояний × событий);
  - `getPublishGate` (каждая причина и комбинации);
  - чистые переходы протокола вкладок (`writeGuard`, `quietBlockers`, `hasUnsavedWork`, `isNewerState`, `adoptOrphanedWorkingCopy`).
- **Stateful** — оба варианта сразу:
  - `useReviewSession` через `renderHook` с настоящим QueryClient, MSW в Node и fake clock: неизвестный исход, повторы с тем же ключом, heartbeat и повторное взятие lease;
  - module вкладок получает localStorage, BroadcastChannel и Web Locks через interface. В Vitest работает пара фейковых вкладок с общими примитивами: тест замораживает вкладку и выпускает её запрос к серверу с задержкой (fixture `tabs`). Fake clock — только там, где время входит в контракт.
- **Boundary.** Операции и их query options с настоящим QueryClient против MSW в Node на `world:review`, включая `observeReviewRevision` и публикацию с `fail:lost-response`/`fail:network`. Образец — тесты операций Course access и их query options.
- **Component.** Настоящее дерево routes приложения (опция `appRoutes` harness рендеринга routes), настоящий Header, свежие Router и QueryClient, MSW в Node на `world:review`.
  - Module готовности diff из REV3 принимает фабрику Workers. В jsdom её заменяет управляемый фейк `ready`/`failed`, diff рендерится без подсветки.
  - Нынешняя подмена pool в harness, при которой страница review не рендерится, уходит вместе с переносом pool на routes review.
  - Образец — тесты routes Course access.
- **Real browser и E2E.** Playwright в Chromium, Firefox и WebKit, приложение целиком с MSW в браузере.
  - Мир, session, удержания и отказы задаёт test-only канал. Общее состояние mock backend в localStorage делает multi-actor сценарии (REV-E1, REV-E2) и сценарии двух страниц одного контекста (TAB-08, REV-E5) проходимыми.
  - `fail:worker` блокирует скрипт Worker или WASM через route.
  - `page.clock` — там, где время входит в контракт.
  - Образец — E2E страницы проверки Attempt и Course access.
  - Риск: в Firefox module Worker, чей скрипт отдал service worker, не запускается (mswjs/msw#2654). Существующий E2E это обходит, и REV3 сохраняет обход.
- **A11Y.** Axe на устойчивых состояниях Review editor (editing, interrupted) — в REV6, Attempt page Student'а — в REV8. Доступные role/name/state поля Grade — в REV1, «Повторить» — в REV3, причин publish gate — в REV6.

**Slice готов**, когда проходят lint и build, а все его контракты зелёные в трёх движках.

### Волны

Тикеты, которые правят одни и те же файлы и понятия, делаются волной: одна ветка, один PR и одно ревью итогового diff, без вычитки промежуточных состояний. Внутри PR коммиты остаются по тикетам и помечены номером тикета. PR закрывает все тикеты волны (`Closes #…` на отдельной строке для каждого), а в описании для каждого тикета перечислено, что проверить по его «Готово, когда». Ручные проверки `ready-for-human` выполняются один раз, по итоговому коду волны. Волна сливается целиком, поэтому в ней 2–3 тикета.

Волны идут по порядку номеров. Порядок внутри волны и между волнами по-прежнему задают нативные блокировки. Волны 1–3 по графу ждут только #221, но идут последовательно: волны 2 и 3 обе меняют модель комментария.

Отступления от графа #69, где кусок slice не зависит от всего предшественника:

- REV3.1 ждёт только V-PIERRE: перенос pool и готовность Worker не зависят от read operations.
- REV4 и REV3.2 ждут REV2.1, а не историю Task из REV2.2.
- REV2.1 забирает и selector Attempts: его данные шли из удаляемого aggregate.

**Решения, принятые этим spec** поверх резолюций, — их стоит перепроверить при нарезке тикетов:

1. **Общий module `lease` уровня course** появляется в REV7. Это уточнение #132, которое заменяет «lease остаётся внутренним module `review`» из #116.
2. **Общее состояние mock backend в localStorage для E2E** — только в test build. Второй участник — смена session через канал в том же BrowserContext.
3. **Module готовности diff принимает фабрику Workers** — это seam для component-тестов Attempt page и Review editor.
4. **До ATT1 публикация пишет Grade в RAM-мок Course Attempts.** Так REV-E1 проверяет Course Attempts, а ATT1 удаляет запись. Course Attempts в REV-04 доказывает ATT1, когда список переходит на MSW.
5. **Силовая смена и выход из аккаунта** реализуются в REV7 целиком. Контракты-кандидаты из #132 пишутся в REV7, хотя в матрице их ещё нет:
   - вкладка без живой копии не продолжает силой;
   - закрытие пишущей вкладки;
   - выход и повторный вход;
   - bfcache.

   TAB-03 остаётся за DRF4.
