# Моменты времени как IsoTimestamp, а не как произвольная строка

### Делает

Вводит брендированный тип `IsoTimestamp` для моментов времени и переводит на него все поля, которые сейчас хранят момент как `string`.

Сейчас время отправки попытки, срок задачи, публикация проверки, создание и правка комментария, истечение сессии — везде просто `string`. В 8 полях схемы проверяют формат через `v.pipe(v.string(), v.isoTimestamp())`, но тип об этом не знает: в `createdAt` можно положить что угодно, хоть `'вчера'` или `''`, и TypeScript промолчит. Гарантия держится только на схеме в `api/`, а моки, черновики и тесты собирают значения в обход неё.

### Модель

`IsoTimestamp` лежит в `model/` фичи, которая им владеет. Для такого общего значения — рядом с `UserId` и `Grade`, место выбрать при реализации. Устроен по образцу `UserIdSchema` (`auth/model/identity.ts`):

```ts
export const IsoTimestampSchema = v.pipe(
  v.string(),
  v.isoTimestamp(),
  v.transform((value) => new Date(value).toISOString()),
  v.brand('IsoTimestamp')
);
export type IsoTimestamp = v.InferOutput<typeof IsoTimestampSchema>;
```

**Канонический вид.** Схема приводит значение к одному виду, `toISOString()`: UTC, миллисекунды, суффикс `Z`. Без этого бренд ничего не нормализует: `v.isoTimestamp()` в valibot 1.5 принимает и пробел вместо `T`, и смещения `+03:00` / `+0300` / `+03`. А в коде моменты сравнивают как текст:
- `attempt-review/ui/comments/timestamp.tsx:12`: `createdAt !== updatedAt` решает, показывать ли «изменено»;
- `attempt-review/model/draft.ts:141-166`: сравнение `createdAt` и `updatedAt` комментариев и ответов.

Сейчас в моках смешаны форматы: в `task/api/mock.ts` смещения `+03:00`, в `page/api/mock.ts` и `quick-grade.test.ts` — `Z` без миллисекунд, в остальных — `.000Z`. Один и тот же момент в двух видах дал бы `!==`.

**Создание без разбора.** Моки создают время через `new Date().toISOString()`. Нужен один помощник рядом со схемой, например `toIsoTimestamp(date: Date): IsoTimestamp`, вместо `as` в каждом месте. Литералы в фикстурах и тестах — через `v.parse(IsoTimestampSchema, …)`, как сейчас делают с `GradeSchema` и `AttemptIdSchema`.

### Пустые строки в черновике

`attempt-review/model/line-comment.ts:168-169` создаёт черновик комментария с `createdAt: ''` и `updatedAt: ''`, потому что у несохранённого комментария времени ещё нет. Со строгим типом так нельзя.

Черновик не должен нести времени вообще: в состоянии `status: 'draft'` полей `createdAt` и `updatedAt` нет, они появляются после сохранения (ADT по `status`, как требует `AGENTS.md`). Не `IsoTimestamp | null` и не `''`. Так же — `lockedAt: ''` в `attempts/model/quick-grade.test.ts:61`.

### Удаляет

- `string` в полях моментов времени доменных типов и пропсов.
- `createdAt: ''` / `updatedAt: ''` у черновиков и `lockedAt: ''` в тестах.
- `// TODO: change to date object` в `check-session.ts`.

### Не входит

- **`deadlines-calendar`**: там локальные `Date` и ключи дней (`formatDateKey`), это другое понятие. Переводить его на `IsoTimestamp` — вместе с настоящим бэкендом календаря.
- **Повторяющиеся форматтеры дат.** Одинаковый `DATE_TIME_FORMAT` в `attempt-review/model/date-format.ts:1` и `attempts/ui/card.tsx:287`; три копии длинного формата (`task/model/deadline.ts:1`, `course/ui/content-block.tsx:20`, `page-edit/ui/plate/nodes.tsx:34`, две последние — одинаковые `formatDueDate`); дважды логика «до/после срока» (`task/model/deadline.ts`, `attempts/ui/card.tsx:311`). Это отдельная правка. Форматтеры здесь только меняют тип параметра на `IsoTimestamp`.
- Переименование `dueDate` во что-то вроде `dueAt`: меняется только тип.
- Библиотека для дат.
- Идентификаторы, собранные через `Date.now()` (`line-comment.ts:159`, `review/api/mock.ts:178`), и числа эпохи (`DEV_FIRST_SUBMISSION`): это не моменты в виде строки.

### Пересечения

- #263 трогает те же `line-comment.ts` и `draft.ts` (привязка треда к строкам). Порядок не важен, но второму придётся сливаться с первым.
- В `playwright/` моментов времени нет.

### Контракты

Новых контрактов в матрице нет. Добавить модульные тесты на `IsoTimestampSchema`:
- принимает `…Z`, `….000Z`, `+03:00` и приводит все к одному каноническому виду;
- один момент в разных видах после разбора равен по `===`;
- отклоняет `''`, `'вчера'` и календарную дату без времени (`'2026-05-20'`).

Существующие тесты на `invalid-response` с неверным временем (`attempt-review/api/read-operations.test.ts:73`, `'вчера'`) должны остаться зелёными.

- Ни один черновик не несёт пустую строку вместо времени.
- `bun run lint`, `bun run build` и `bun run test` проходят.
