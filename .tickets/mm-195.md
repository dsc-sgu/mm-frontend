# Показывать файл целиком в diff попытки

## Источники

- Страница AnyType «Разбор состояния фронтенда MergeMinds на 6.06.2026», №4: переключатель на полный файл нужен, в GitLab без него неудобно.

## Проблема

Diff попытки показывает только изменённые фрагменты с небольшим контекстом. Чтобы увидеть весь код вокруг изменения, преподавателю приходится открывать файл где-то ещё.

## Что известно

- `@pierre/diffs` умеет раскрывать неизменённые строки (`expandUnchanged`, раскрытие между фрагментами изменений), только если diff построен из полного содержимого файлов, а не из patch.
- Мок строит diff из полного старого и нового текста (`parseDiffFromFile` в `src/features/course/features/attempt-review/api/mock.ts`).
- По решению mm-116 (проектирование вертикали «проверка → оценка → результат студента») фронтенд получает полное старое и новое содержимое каждой записи манифеста изменённых файлов. В [mm-backend PR #172 «Ezhkin-Kot/fixes»](https://github.com/dsc-sgu/mm-backend/pull/172) `oldText`/`newText` содержат только удалённые и добавленные строки. Вопрос уже есть в реестре вопросов к бэкенду mm-113, в разделе про выдачу изменений попытки.

## Что делает

- В заголовке файла есть переключатель «Показать файл целиком». Включённый, он показывает весь файл с подсветкой изменений.
- Треды к строкам остаются на своих строках в обоих режимах.
- У записей манифеста `binary` и `too-large` переключателя нет.

## Что решить

- Переключатель только для отдельного файла или ещё общий на всю попытку.
- Запоминать ли выбор при переходе между файлами и попытками.

## Зависит от

Полного содержимого файлов от бэкенда: вопрос в mm-113.
