# Убрать глобальную роль из сессии и привязать permissions к курсу

## Проблема

`SessionScheme` содержит глобальное поле `role: string`, хотя роли `student` и `teacher` существуют только в контексте конкретного курса. Из-за этой ложной модели `attempt-review` определяет часть прав через `session.role`, в то время как маршруты и остальные course-сценарии используют корректный `courseAccess.role`.

Это не только создаёт ошибочную авторизацию, но и даёт разработчикам и ИИ ложную подсказку, что «преподавательность» является свойством аккаунта.

Обнаружено при работе над mm-63 «Согласовать карту реализованной frontend-системы».

## Доменный инвариант

- Сессия содержит состояние аутентификации и identity текущего пользователя, но не роль в курсе.
- `student` и `teacher` — роли пользователя в конкретном курсе; один пользователь может быть преподавателем в одном курсе и студентом в другом.
- На сохранённый комментарий к попытке может отвечать преподаватель этого курса или студент-владелец попытки.
- Редактировать review и выставлять оценку может только преподаватель этого курса.

## Изменения

- Удалить `role` из `SessionScheme` и auth mock в `src/features/auth`.
- Не заменять поле глобальным union-типом: глобальной course-роли в auth-модели быть не должно.
- Использовать `CourseAccessResult`/разрешённый course access как единственный источник course-роли.
- Передавать `courseAccess` из route context в `AttemptReviewPage` для readonly и editable маршрутов попытки.
- Вынести правило ответа на комментарии в чистую permission-функцию внутри `attempt-review/model` вместо inline-проверки `session.role`.
- Оставить session identity только для отображения и авторства текущего пользователя.
- Убрать из mocks глобально-ролевые подсказки вроде `mit-teacher`/`Текущий преподаватель`, где они обозначают текущего пользователя независимо от курса.
- Исправить mock сохранения replies: ответ студента не должен получать hard-coded авторство преподавателя.
- Зафиксировать в доменном словаре, что course role является отношением пользователя к конкретному курсу, а не свойством аккаунта.

## Критерии готовности

- В типе и runtime-схеме сессии отсутствует course role.
- В production-коде нет обращений к `session.role`.
- Права attempt review вычисляются из access пользователя к текущему курсу.
- Преподаватель текущего курса может отвечать на комментарии и редактировать review.
- Студент-владелец попытки может отвечать на сохранённые комментарии, но не может редактировать review.
- Пользователь, не являющийся преподавателем курса или владельцем попытки, не получает права ответа.
- Mock reply сохраняет identity фактического текущего пользователя, а не hard-coded преподавателя.
- Доменный инвариант о per-course ролях записан без реализации-зависимых деталей.
- `bun run lint` и `bun run build` проходят.

## Вне области

- Проектирование глобальных platform/admin ролей.
- Полная модель backend authorization и окончательный API course access.
- Общий рефакторинг всех permission-проверок приложения.
- Добавление тестового runner в рамках этой задачи.
