# REV7.2: Делить Review editor между вкладками — живая копия и «Продолжить здесь»

Часть epic mm-218 «Review».

Вкладки одного браузера делят Review editor. Пишет одна, остальные показывают живую копию Review Working Copy. «Продолжить здесь» переносит работу без сервера и без потерь. Закрытая пишущая вкладка передаёт работу следующей.

### Делает

Протокол из mm-132 в общем module `lease`. Ресурс — `mm:editor:{UserId}:review:{AttemptId}`.

**Кто пишет.**
- Запись `{epoch, writer}` в localStorage. Каждая смена увеличивает `epoch`.
- Перед каждой записью на сервер, включая heartbeat и публикацию, вкладка синхронно сверяет свой `epoch` и `UserId` сессии (`writeGuard`).
- Web Lock выбирает следующую пишущую вкладку. Копии стоят в очереди за ним.

**Живая копия.**
- BroadcastChannel доставляет полную Working Copy после каждого изменения, в той же задаче, вместе со статусами публикации и holder lease.
- Новая копия заменяет старую по `(epoch, seq)`. Открывшаяся вкладка спрашивает состояние сообщением `hello`.
- Копия не отправляет записей на сервер.
- Копия показывает «Редактирование идёт во вкладке N этого браузера · Продолжить здесь».

**Добровольная смена.**
- Пишущая вкладка отвечает сразу, перестаёт принимать правки и дожидается публикации в полёте.
- `publication-unconfirmed` передаётся вместе с `idempotencyKey` и замороженной Working Copy, повторы продолжает новая вкладка.
- Переходят Working Copy и черновики полей ввода: root comment, ещё не добавленный в Working Copy, и reply. История undo, выделение, курсор и scroll теряются.
- Обращений к lease на сервере нет.

**Закрытие пишущей вкладки.**
- Lock переходит к первой копии в очереди. Она продолжает сама и показывает «Вкладка N закрыта — редактирование продолжено здесь».
- Lease снимается, когда уходит последняя вкладка Review editor этой Attempt.

**Версии.** Одно `TAB_PROTOCOL_VERSION` покрывает сообщения и Working Copy; конверт `{kind, from, version, epoch}` не меняется. При несовпадении нет ни живой копии, ни смены: «Редактор открыт во вкладке с другой версией MergeMinds — закончите работу там и закройте её».

**User.** Канал и lock привязаны к `UserId`. Вкладка другого User не получает живую копию. Выход из аккаунта останавливает запись в пишущей вкладке.

**`interrupted`** видят все вкладки браузера, действовать можно из любой.

**Seams:**
- Чистые переходы (`writeGuard`, `isNewerState` и др.) — Model.
- Module получает localStorage, BroadcastChannel и Web Locks через interface. В Vitest — пара фейковых вкладок с общими примитивами, заморозкой и задержанным запросом к серверу (fixture `tabs`).
- Playwright — две страницы одного BrowserContext на общем состоянии mock backend из REV6.2.

### Не входит

- Силовая смена, вкладка без живой копии, полное поведение выхода и повторного входа, bfcache — REV7.3.
- Адаптер черновика Course — DRF4.
