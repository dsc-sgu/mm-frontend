# REV7.2: Делить редактор проверки между вкладками с безопасной передачей управления

Часть эпика mm-218.

Вкладки одного браузера делят редактор проверки. Пишет одна, остальные показывают лайв-копию рабочей копии проверки. «Продолжить здесь» переносит работу без сервера и без потерь. Закрытая пишущая вкладка передаёт работу следующей.

### Делает

Протокол из mm-132 в общем модуле `lease`. Ресурс — `mm:editor:{UserId}:review:{AttemptId}`.

**Кто пишет.**
- Запись `{epoch, writer}` в localStorage. Каждая смена увеличивает `epoch`.
- Перед каждой записью на сервер, включая heartbeat и публикацию, вкладка синхронно сверяет свой `epoch` и `UserId` сессии (`writeGuard`).
- Web Lock выбирает следующую пишущую вкладку. Копии стоят в очереди за ним.

**Лайв-копия.**
- BroadcastChannel доставляет полную рабочую копию после каждого изменения, в той же задаче, вместе со статусами публикации и держателем брони.
- Новая копия заменяет старую по `(epoch, seq)`. Открывшаяся вкладка спрашивает состояние сообщением `hello`.
- Копия не отправляет записей на сервер.
- Копия показывает «Редактирование идёт во вкладке N этого браузера · Продолжить здесь».

**Добровольная смена.**
- Пишущая вкладка отвечает сразу, перестаёт принимать правки и дожидается публикации в полёте.
- `publication-unconfirmed` передаётся вместе с `idempotencyKey` и замороженной рабочей копией, повторы продолжает новая вкладка.
- Переходят рабочая копия и черновики полей ввода: комментарий преподавателя, ещё не добавленный в рабочую копию, и ответ. История отмены, выделение, курсор и прокрутка теряются.
- Обращений к брони на сервере нет.

**Закрытие пишущей вкладки.**
- Web Lock переходит к первой копии в очереди. Она продолжает сама и показывает «Вкладка N закрыта — редактирование продолжено здесь».
- Бронь снимается, когда уходит последняя вкладка редактора проверки этой попытки.

**Версии.** Одно `TAB_PROTOCOL_VERSION` покрывает сообщения и рабочую копию; конверт `{kind, from, version, epoch}` не меняется. При несовпадении нет ни лайв-копии, ни смены: «Редактор открыт во вкладке с другой версией MergeMinds — закончите работу там и закройте её».

**Пользователь.** Канал и Web Lock привязаны к `UserId`. Вкладка другого пользователя не получает лайв-копию. Выход из аккаунта останавливает запись в пишущей вкладке.

**`interrupted`** видят все вкладки браузера, действовать можно из любой.

**Швы:**
- Чистые переходы (`writeGuard`, `isNewerState` и др.) — слой Model.
- Модуль получает localStorage, BroadcastChannel и Web Locks через интерфейс. В Vitest — пара фейковых вкладок с общими примитивами, заморозкой и задержанным запросом к серверу (фикстура `tabs`).
- Playwright — две страницы одного BrowserContext на общем состоянии мок-бэкенда из REV6.2.

### Зависание, выход и возврат вкладки

**Силовая смена.**
- Если пишущая вкладка молчит 3 с после «Продолжить здесь», копия продолжает сама, без второго нажатия.
- Если вкладка ответила `handoff-accepted` и ждёт свой запрос, срок — таймаут запроса плюс 3 с.
- Продолжить силой может только вкладка с лайв-копией.
- Порядок: сначала счётчик в localStorage, потом `steal` у Web Lock.

**Проснувшаяся бывшая пишущая вкладка.**
- Сверяет счётчик раньше, чем узнаёт о потере Web Lock. Её просроченные запросы heartbeat и повтор публикации ничего не отправляют.
- Первое нажатие в ней не применяется. Она становится копией.

**Вкладка без лайв-копии** (открыта, когда пишущая уже молчит) показывает «Редактор открыт в другой вкладке, она не отвечает — перейдите в неё» и становится копией, когда пишущая оживает.

**Добровольная смена.** Пишущая вкладка держит Web Lock, пока получатель не заберёт его через `steal`. Если получатель не забрал Web Lock за 1 с, роль возвращается.

**Уход.** Предупреждение об уходе с несохранённой рабочей копией нужно, только если совместимой лайв-копии нет.

**Выход из аккаунта.**
- Содержимое во всех вкладках скрыто экраном «Вы вышли из аккаунта». Рабочая копия держится в памяти, закрытие вкладки предупреждает.
- Вход тем же пользователем продолжает работу. Бронь прежней сессии берётся перехватом тем же пользователем.
- Вход другим пользователем удаляет рабочую копию прежнего.

**bfcache.**
- `pagehide` — уход: Web Lock и канал отпускаются, копия продолжает.
- При `pageshow` с `persisted` вкладка продолжает со своей рабочей копией, только если запись о пишущей вкладке не менялась. Иначе выбрасывает её и подключается заново.

**Непроверенные допущения о движках** из mm-132 проверяются здесь:
- читается ли счётчик в localStorage синхронно и в актуальном значении сразу после разморозки;
- замораживаются ли отдельные фоновые вкладки в Firefox и Safari;
- блокирует ли удерживаемый Web Lock попадание в bfcache.

Результаты записываются в комментарии этого тикета перед влитием.

### Не входит

- Адаптер редактора страницы курса, включая TAB-03 и ограничение TAB-07, — mm-311-DRF5. Бронь курса и старый TAB-09 не вводятся.
- Восстановление после закрытия всех вкладок через IndexedDB — mm-273.
