# Версия элемента CodeView в проверке: коллизии hashText, сериализация всех комментариев и отсутствие diff

## Контекст

`CodeView` из `@pierre/diffs` (1.4.3) перерисовывает элемент списка файлов только тогда, когда у него меняется `version` (`CodeViewItem.version`, `node_modules/@pierre/diffs/dist/types.d.ts:414-438`). Значение сравнивается строго, и при совпадении `CodeView` оставляет у себя прежний объект элемента целиком, вместе со старыми `fileDiff` и `annotations`:

```js
// node_modules/@pierre/diffs/dist/components/CodeView.js:1307-1313
syncItemRecord(item, nextItem) {
  if (item.version === nextItem.version) return false;
  item.item = nextItem;
  ...
}
```

Порталы React-обёртки тоже ключуются по `${item.id}:${item.version}:${item.type}` (`dist/react/CodeView.js:327`), а `areManagedSnapshotsEqual.js:13` сравнивает снимки по `version`.

Сейчас `version` считается в `src/features/course/features/attempt-review/model/code-view-item.ts`:

- `buildAttemptReviewCodeViewItemVersion` сериализует через `JSON.stringify` путь файла, `collapsed` и все треды к строкам этого файла: `html`, `replies` целиком, `isEditing`, `status`, даты и т. д.;
- `createRenderedMarkdownItem` делает то же для пути и `collapsed`;
- результат проходит через `hashText` — 32-битный хеш `hash * 31 + charCode` в духе `String.hashCode` из Java.

## Проблемы

### 1. Коллизия хеша оставляет на экране устаревший текст комментария

При совпадении `version` `CodeView` не берёт новый элемент (см. `syncItemRecord` выше), поэтому пользователь видит прежний текст комментария преподавателя или ответа. Это не косметический сбой: преподаватель может опубликовать версию проверки, глядя на текст, которого уже нет в рабочей копии.

Для случайных данных вероятность ничтожна, но у хеша есть тривиальные структурные коллизии: `"Aa"` и `"BB"` дают одно и то же значение (`2112`). Проверено: `hashText(JSON.stringify({ html: '<p>Aa</p>' }))` и `hashText(JSON.stringify({ html: '<p>BB</p>' }))` оба равны `-1997800242`. Любая правка, меняющая пару соседних символов так, что `31·Δa + Δb = 0`, не будет замечена, если вместе с ней не изменились другие поля (например, `updatedAt`).

### 2. Стоимость

`items` пересобираются в `useMemo` в `ui/diff.tsx` при любом изменении `comments`, `collapsedFilePaths`, `renderedFilePaths` или `files`. Каждый раз для **каждого** файла сериализуется весь HTML его комментариев вместе с ответами и посимвольно хешируется. Для попытки с большим числом тредов это работа, пропорциональная объёму всего текста проверки, на каждое изменение одного комментария.

### 3. `file.diff` не входит в `version`

`fileDiff` в `version` не учитывается. Судя по `syncItemRecord`, новая ссылка на `fileDiff` при той же `version` **не** приводит к перерисовке: `CodeView` оставит старый объект.

Сейчас это не проявляется: `AttemptReviewPageLoaded` смонтирован с `key={`${viewerId}:${attemptId}`}` (`src/features/course/features/attempt-review/page.tsx:145`), поэтому при переходе к другой попытке `CodeView` создаётся заново, а материал попытки неизменен для одного `AttemptId`. Но корректность держится на этом `key` неявно: если `CodeView` перестанет пересоздаваться при смене попытки (например, ради сохранения прокрутки или при чтении по `AttemptId` из общего состояния в рамках mm-221), то при совпадении пути, `collapsed` и комментариев (типично для файла без тредов: `comments: []`) у двух попыток будет показан diff прежней попытки.

## Возможные направления (не решение)

- Строить `version` из стабильных данных без сериализации HTML: `attemptId`, `id` и `updatedAt` (или номер ревизии) каждого треда и ответа, `isEditing`, `collapsed`. Прецедент — коммит 16e4722, где ключ кеша подсветки diff (`cacheKey`) перевели с хеша содержимого на `AttemptId`, потому что материал попытки неизменен для одного `AttemptId`. Нужно проверить, что у каждой правки рабочей копии действительно меняется `updatedAt` или иной маркер.
- Явный счётчик изменений в состоянии проверки: редьюсер рабочей копии увеличивает версию файла при каждом событии, касающемся его тредов; `version` = `attemptId` + этот счётчик + `collapsed`.

## Критерии приёмки

- [ ] `version` элемента `CodeView` меняется при любом видимом изменении треда к строкам или ответа (текст, статус, режим редактирования, добавление и удаление), без опоры на некриптографический хеш текста; коллизия вида `"Aa"`/`"BB"` не может оставить на экране устаревший текст.
- [ ] `version` зависит от попытки (`AttemptId`) или явно от `fileDiff`, так что смена попытки перерисовывает diff даже без пересоздания `CodeView`.
- [ ] HTML комментариев и ответов не сериализуется при каждой пересборке `items`.
- [ ] `hashText` удалён, если после изменений не осталось пользователей.
- [ ] Тест в `model/` на построение `version`: правка текста комментария, правка ответа, переключение `isEditing`, смена попытки при одинаковом пути и комментариях — каждая меняет `version`.
