# Синхронизировать редактирование существующего content block

## Parent

[Перевести course dashboard и редактирование курса на общий mock backend](https://github.com/dsc-sgu/mm-frontend/issues/78)

## What to build

Провести изменение существующего content block через полный local-first/server-snapshot путь: local working copy, observable sync lifecycle, HTTP/MSW mutation, acknowledgement и восстановление подтверждённого содержимого после reload.

## Acceptance criteria

- [ ] Изменение существующего блока сразу отражается в local working copy.
- [ ] Sync state различает dirty, syncing, synced и failed без невозможных комбинаций.
- [ ] Подтверждённая mutation сохраняется в persistent draft mock backend.
- [ ] Reload восстанавливает последнее подтверждённое server state.
- [ ] Failed mutation сохраняет локальную работу и позволяет retry.
- [ ] Navigation warning активен только для неподтверждённых изменений.
- [ ] Student-facing content не меняется до publish.
- [ ] Lint и build проходят.

## Уточнения из [«Спроектировать lifecycle Course Page Working Copy»](https://github.com/dsc-sgu/mm-frontend/issues/118#issuecomment-6090347912)

Синхронизация больше не делится по видам изменений: изменение существующего блока, добавление, перемещение и удаление блоков, а также metadata и resources обрабатывает один планировщик `planDraftSync(base, workingCopy)` (ADR 0002 в [PR #127](https://github.com/dsc-sgu/mm-frontend/pull/127)). Этот issue покрывается slice 2 «Сессия черновика» (планировщик выполняется перед публикацией) и slice 3 «Фоновая синхронизация».

- Синхронизация фоновая: после ~1 с бездействия, не реже раза в 5 с, сразу при уходе и публикации. Одновременно в полёте один batch.
- Состояние `sync`: `synchronized | pending | syncing | sync-failed | sync-rejected`; индикатор «Сохранено» / «Сохранение…» / «Не сохранено · Повторить».
- Неизвестный исход операции: черновик перечитывается, становится новой базой, план строится заново. Отказ backend по операции останавливает batch (`sync-rejected`), Working Copy не теряется.
- Пока сервер назначает id блоков, сопоставление локальных и серверных id живёт внутри модуля синхронизации.
- Явного «Сохранить черновик» и `Mod+S` для сохранения нет.

Каноническим источником является решение по ссылке выше. Окончательную нарезку на implementation-тикеты определит [«Определить последовательность подготовки и выполнения рефакторинга»](https://github.com/dsc-sgu/mm-frontend/issues/69).
