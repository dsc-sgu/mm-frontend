# Спроектировать individual Course Attempts vertical

## Question

Какая целевая форма individual Course Attempts должна гарантировать Teacher полный корректный список либо явный incomplete/error state, предсказуемые draft/applied filters и переход ровно к выбранной Attempt? Решение должно определить interfaces query identity, фильтрации, page modes, selection-free individual navigation, loading/error state и связи с Review vertical; отделить обязательное ядро от bulk selection и quick grading из [«Определить роль bulk selection и quick grading в teacher workflow»](https://github.com/dsc-sgu/mm-frontend/issues/114); разложить будущий refactoring на небольшие проверяемые slices без изменения production/source code или тестов.

_Термины обновлены в [«Спроектировать Review → Grade → Student result vertical»](https://github.com/dsc-sgu/mm-frontend/issues/116): workbench → Course Attempts, Review workspace → Review editor / Attempt page, review editor (rich-text) → review-text editor._

## Решение: полный individual Course Attempts с честной актуальностью

### Обязательное ядро и граница

Course Attempts — course-wide read projection для Teacher, позволяющая найти конкретную Attempt и открыть её в Review editor. Обязательное ядро не содержит bulk selection: selection state, checkboxes, «выбрать всё», selection page mode и массовая команда максимальной Grade удаляются clean cutover согласно решению «Определить роль bulk selection и quick grading в teacher workflow».

Quick grading остаётся отдельным productivity mode поверх того же Course Attempts по уже принятому контракту. Он не определяет interface individual navigation и не возвращает generic selection mechanism.

### Состав, порядок и полнота списка

- Course Attempts показывает все доступные Teacher Attempts Course: `submitted` и `graded`, включая исторические Attempts после повторной сдачи.
- Каждая строка представляет ровно одну immutable Attempt. Несколько Attempts никогда не объединяются в один diff.
- Канонический порядок: `submittedAt DESC`, затем стабильный opaque `AttemptId` как технический tie-breaker. Tie-breaker обеспечивает одинаковый порядок при совпавшем времени и не показывается пользователю.
- Первая реализация загружает весь отфильтрованный список одной атомарной operation без pagination. Ожидаемый объём не оправдывает cursor lifecycle; виртуализация остаётся UI-механизмом и не меняет семантику полноты.
- Partial payload не является частичным успехом. Нечитаемый или не прошедший Valibot validation snapshot отклоняет operation; UI не показывает правдоподобно неполный список.

### Глубокий read interface и query identity

Feature-owned operation имеет форму уровня домена, не фиксируя будущий wire DTO:

```ts
type LoadCourseAttemptsInput = {
  courseId: CourseId;
  filters: AppliedAttemptsFilters;
  signal?: AbortSignal | null;
};

type AppliedAttemptsFilters = {
  taskIds: readonly TaskId[];
  studentIds: readonly UserId[];
  status: 'any' | 'submitted' | 'graded';
};

type CourseAttemptsSnapshot = {
  attempts: readonly AttemptListItem[];
  tasks: readonly AttemptFilterTask[];
  students: readonly AttemptFilterStudent[];
  totalAttemptsCount: number;
};
```

`loadCourseAttempts` скрывает URL, HTTP statuses, parsing, validation и DTO mapping. Он использует `CourseId` из Course access vertical; route slug и username не входят в operation/cache identity. `AttemptListItem` содержит стабильные `AttemptId`, `TaskId`, `UserId`, отображаемые locators/labels, `AttemptNumber`, submission/deadline/diff summary и компактную Review/Grade/Lease projection — но не файлы, diff или Review Working Copy.

Feature-owned key factory нормализует фильтры, чтобы семантически одинаковые sets давали один key:

```ts
const courseAttemptsKeys = {
  all: (courseId: CourseId) => ['course-attempts', courseId] as const,
  list: (courseId: CourseId, filters: AppliedAttemptsFilters) =>
    [...courseAttemptsKeys.all(courseId), normalizeFilters(filters)] as const,
};
```

Отдельный generic repository/interface и DI seam ради одного Fetch/MSW path не вводятся. Реальный seam — operation плюс общий transport kernel; MSW обслуживает ту же operation через HTTP.

### Draft и applied filters

Сохраняется текущая удобная двухфазная модель:

- локальный `draft` меняется без смены списка и удалённых запросов;
- «Применить» атомарно записывает нормализованные фильтры в URL;
- URL является единственным владельцем `applied filters`, поэтому back/forward и shared link воспроизводят тот же запрос;
- внешняя смена URL сбрасывает незавершённый draft к новым applied filters;
- «Сбросить» очищает draft и applied filters;
- UI сохраняет три существующих измерения: Tasks, Students и состояние `any | submitted | graded`;
- filter catalogs относятся ко всему доступному Course, а не сужаются текущим отфильтрованным результатом.

Пустой Course и отсутствие совпадений различаются: `totalAttemptsCount === 0` означает отсутствие Attempts вообще; ненулевой total при пустом `attempts` означает «по применённым фильтрам ничего не найдено».

### Page modes и честные состояния

Remote snapshot моделируется явным ADT, а не сочетанием независимых booleans:

```ts
type CourseAttemptsSnapshotState =
  | { status: 'loading' }
  | { status: 'ready'; snapshot: CourseAttemptsSnapshot }
  | { status: 'refreshing'; snapshot: CourseAttemptsSnapshot }
  | { status: 'stale'; snapshot: CourseAttemptsSnapshot; failure: OperationFailure }
  | { status: 'failed'; failure: OperationFailure };
```

- initial failure без полного snapshot показывает error и Retry, а не empty state;
- revalidation сохраняет последний полный snapshot видимым;
- если revalidation завершилась ошибкой, snapshot получает заметную надпись «Данные могут быть устаревшими» и Retry;
- индивидуальный переход в Review editor из stale snapshot разрешён: Review operation заново разрешает identity, проверяет access и загружает authoritative Attempt;
- quick grading из stale snapshot заблокирован до успешной revalidation;
- cancellation не показывается как network failure.

### Когда список обновляется

Immutable Attempt не перезагружается как изменяемый документ. Повторно запрашивается только изменяемая projection коллекции, потому что могут появиться новые Attempts, Reviews, Grades и Review Leases.

Полный список revalidate-ится:

- при входе на route;
- после известных mutations, меняющих list projection;
- после возврата вкладки в focus;
- после восстановления соединения;
- по явному Retry/Refresh.

Interval polling не используется. Будущий realtime adapter может инвалидировать тот же query family, но Course Attempts не зависит от ещё не определённого WebSocket protocol.

### Selection-free переход ровно к выбранной Attempt

- Любая строка ведёт в Review editor с намерением редактировать — независимо от `submitted`/`graded`, filters или положения строки.
- Link строится только из identity выбранной строки. In-memory объект не передаётся как источник истины.
- Текущая URL-форма сохраняет route locators: Course slug + Task locator + Student username + `AttemptNumber`. Resource operation разрешает их в стабильные `CourseId + TaskId + UserId + AttemptId` и авторитетно проверяет доступ.
- Если редактирование невозможно из-за чужого Review Lease, неполной загрузки Attempt или operation failure, тот же Review editor остаётся открыт, но показывает явный readonly/blocked state. Намерение editable navigation не обходит fail-closed гарантии.
- Review editor и Attempt page сохраняют selector всех Attempts данного Student по данному Task. Selector меняет одну выбранную Attempt; diff всегда относится только к ней.
- Applied filters остаются в history URL Course Attempts, поэтому обычный Back возвращает к тому же представлению.

### Связь с Review vertical и cache

Course Attempts владеет только list projection и своим key family. Review vertical владеет authoritative Attempt load, completeness, Review Working Copy, lease, publication и reconciliation.

После авторитетного Review outcome:

- полное представление конкретной Review записывается в точный Review cache, если operation его вернула;
- Course Attempts list family инвалидируется, потому что Review может изменить membership фильтра `submitted | graded`, Grade и Lease projection;
- frontend не воспроизводит server filtering/sorting вручную ради patch нескольких filtered caches;
- navigation не зависит от предварительно прогретого Course Attempts cache, поэтому direct link остаётся полноценным путём.

Quick grading использует тот же `AttemptId` и после per-Attempt outcomes инвалидирует/reconcile-ит Course Attempts projection по контракту отдельного quick-grading решения.

### Будущие проверяемые refactoring slices

После Course access vertical и согласования interfaces Review vertical:

1. **Identity и read contract** — ввести стабильные types, `AppliedAttemptsFilters`, `AttemptListItem`, key factory и атомарную Fetch/Valibot/MSW operation; перевести существующую выдачу одним clean cutover.
2. **Предсказуемые filters** — отделить draft от URL-owned applied state, нормализовать keys, сохранить full-course catalogs и различить empty Course от no matches.
3. **Честный snapshot lifecycle** — ввести loading/ready/refreshing/stale/failed transitions, retry и focus/reconnect revalidation без polling и partial rendering.
4. **Selection-free individual navigation** — удалить selection model/UI/orchestration и детерминированно связать каждую строку с editable-intent Review editor; сохранить single-Attempt diff и Attempt selector внутри Review editor и Attempt page.
5. **Authoritative Review consistency** — подключить targeted Review cache update и invalidation Course Attempts family после publication/reconciliation, не перенося Review state в Course Attempts.
6. **Quick-grading cutover** — поверх готового individual core реализовать отдельный режим по решению quick grading: только первые Reviews, locked filters, per-Attempt outcomes и recovery; без восстановления bulk selection.

Каждый slice проверяется через interface соответствующего модуля и наблюдаемый route outcome; конкретная contract matrix будет задана отдельным ticket стратегии тестирования.

Production/source code и тесты в рамках решения не изменялись.
