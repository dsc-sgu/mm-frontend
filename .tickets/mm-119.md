## Решение: structured-document seam Course Page — собственный доменный документ, editor adapter и render tree

Решение задаёт целевую форму части 4B пути «Teacher редактирует и публикует Course Page» из [«Ранжировать зоны рефакторинга по риску и отдаче»](https://github.com/dsc-sgu/mm-frontend/issues/67). Опирается на:

- [«Зафиксировать контракт нумерации списков редактора»](https://github.com/dsc-sgu/mm-frontend/issues/74);
- [«Разобрать низкоуровневые browser- и scheduling-механизмы»](https://github.com/dsc-sgu/mm-frontend/issues/72);
- seam `edit(document)` из [«Спроектировать lifecycle Course Page Working Copy»](https://github.com/dsc-sgu/mm-frontend/issues/118).

Glossary пополнен терминами **Task Reference** и **Task Summary**. Архитектурное решение записано в ADR `docs/adr/0003-course-page-domain-document.md`. Оба изменения — в PR [«docs: record Course Page domain document glossary and ADR»](https://github.com/dsc-sgu/mm-frontend/pull/130). Production/source code и тесты не изменялись.

### Решения

#### Persisted-модель: собственный доменный документ

- Содержимое Course Page — документ проекта, не зависящий от редактора: плоская последовательность блоков в канонической форме. Plate value существует только внутри editor adapter (ADR 0003). Plate-native JSON, как у `ReviewTextDocument` в #109, отвергнут: у Course Page поблочная синхронизация, обновление Plate — самый рискованный cohort, а ссылки на Task, картинки и файлы — доменные понятия.
- **Списки.** `CourseListBlock` и `courseListId` удаляются. Каждый элемент списка — отдельный блок `list-item { variant, indent, text }`. Группировку в `<ol>/<ul>`, вложенность и номера выводит одна чистая функция по соседству (#74). Нормализация indent — тоже одна функция: для загрузки, для Plate `normalizeNode` и для renderer.
- **Inline.**
  - У inline-узлов нет id. Соседние фрагменты с одинаковыми marks слиты, пустые удалены, marks хранятся как упорядоченное множество, жёсткий перенос — `\n`. Равенство документов — обычное структурное сравнение, `dirty-compare.ts` уходит.
  - Ссылка — `{ href, фрагменты[] }`, у каждого фрагмента свои marks.
  - `linkType` не хранится, а выводится из `href` по политике URL из #109:
    - root-relative ссылки открываются в текущей вкладке через router;
    - `http`/`https` открываются в новой вкладке с `rel="noopener noreferrer"`;
    - остальные схемы отклоняются.
  - У Course Page marks bold, italic и code.
- **Identity и порядок.**
  - Порядок блоков — порядок массива, `rank` в доменной модели нет.
  - `BlockId` — непрозрачная строка, уникальная во всём документе, и совпадает с id Plate-узла.
  - Новый блок получает клиентский UUID. При split исходный id остаётся у части с исходным началом. Duplicate и paste выдают новые id.
- **Версионирование.** `data` каждого блока несёт `version: 1`. Миграции — явные чистые функции по типу блока.
- **Task Reference** хранит только `taskId`, без свойств Task. Блок `assignment` переименован, `resources.assignments` уходит из документа и Working Copy.
- **Spoiler.**
  - Заголовок — rich text, тело — блоки любых типов, кроме Spoiler и Task Reference. Глубина вложенности — 1.
  - Task Reference внутри Spoiler запрещён продуктовым решением, а не из-за ограничения backend.
  - Списки внутри тела нумеруются независимо.
  - `defaultOpen` не хранится: в read-only spoiler всегда свёрнут.
- **Image.** Caption и alt принадлежат блоку (месту на странице). Resource хранит только факты об asset.
- **Trust seam.** Строгая Valibot-схема проверяет каждый блок на transport seam (#108).
  - Read-only показывает невалидный или неизвестный блок, а также блок неизвестной версии, заглушкой «Блок не удалось показать», остальная страница видна.
  - Редактор с таким документом не открывается: typed failure `unsupported-content` с предложением обновить приложение.
  - Молчаливых конверсий и выбрасывания блоков нет. Исправимые отклонения (indent, пустые фрагменты) нормализуются молча и одинаково в reader и editor.

#### Editor adapter

- **Профиль Plate позволяет создать только то, что документ может сохранить.** `fromPlate` — тотальная функция без потерь:
  - списки и indent — только на paragraph, Tab вне списка ничего не делает;
  - цитата — один rich text с жёсткими переносами: Shift+Enter — перенос, Enter на пустой строке — выход в paragraph;
  - неподдерживаемое содержимое при paste проходит через DOMPurify → converter → normalizer и сохраняет текст.
- **Закон round-trip:** `fromPlate(toPlate(doc)) = doc` для любого нормализованного документа.
- **`edit(document)`** вызывается на каждое изменение Plate, без debounce: debounce есть в планировщике синхронизации course-draft. Конверсия дешёвая: неизменённые по ссылке узлы переиспользуются через memo.
- **UI-состояние редактора** — раскрытие spoiler, insert panel, hover, block selection, slash-меню — хранится по `BlockId` отдельно от Plate value, документа и undo. Новый spoiler в редакторе раскрыт.

#### Структурные операции

- `BlockCommands` по `BlockId`:
  - `insert(kind, anchor)`;
  - `move(ids, target)`;
  - `moveUp(id)` / `moveDown(id)`;
  - `remove(ids)`;
  - `duplicate(ids)`;
  - `transform(id, kind)`.
- Каждая команда — один batch Plate transforms, а не `setValue` документа, и ровно один шаг Mod+Z / Mod+Shift+Z в общей истории с текстом. После undo фокус возвращается к затронутому блоку. История ограничена сессией редактора и сбрасывается при перемонтировании: «Взять версию с сервера», «Перезаписать моей версией», reload.
- Команда возвращает `FocusIntent | null` (`{ blockId, edge }`) и сама фокус не ставит. Intent применяет focus-координатор из #72, ограниченный корнем редактора. Он заменяет `queueMicrotask` и `editor.meta._forceFocus`.
- Профиль Plate делится на headless-слой (base-плагины, `model`) и React-привязки (`ui`). Команды, нормализация и adapter тестируются в Node через `createSlateEditor`. Что base-плагины работают headless, подтверждается при реализации.
- dnd-kit и Block Selection только переводят жесты в команды. Multi-drag переносит явно выделенные блоки по #74. Selection area задаётся от корня редактора, а не через document-global selectors.
- В slices 3–4 применяются решения #72: общий keyboard-модуль (shortcut определяется по `KeyboardEvent`, platform detection — только для подписей) и clipboard auto-read только в Chromium.

#### Rendering и визуальная идентичность

- Read-only — собственный renderer: чистая проекция `документ → render tree` и React-компоненты, Plate на read-only route не загружается. На вход renderer получает документ, поэтому он же показывает Working Copy в `interrupted` и `stale`.
- **Task Summary** — часть Task, которую можно показать без доступа к её содержимому: title, дедлайн, максимальная Grade и необязательная аннотация Teacher'а. Seam `taskId → Task Summary + доступ | unavailable`:
  - Student видит `open` или `locked { prerequisite }` по Student Task Access;
  - Teacher видит карточку без состояния доступа;
  - если Task нет или он недоступен, показывается заглушка.
- **Parity:** содержимое (типографика, ритм отступов, вид блоков) совпадает. Отличается только chrome редактора: gutter, handles, toolbars, placeholders, элементы управления внутри непредактируемых блоков.
  - Сейчас идентичность держится на копиях Tailwind-классов, и они уже разошлись:
    - размер текста списков на desktop;
    - вес bold;
    - code block без подсветки в редакторе;
    - маркер spoiler;
    - карточка Task;
    - иконка files.
  - Механизм — общий presentation-модуль:
    - `cva`-рецепты типографики для текстовых блоков;
    - view-компоненты со slots для элементов управления редактора: `CodeBlockView`, `ImageFigure`, `FileList`, `TaskReferenceCard`, `SpoilerHeader`, `UnavailableContent`.
  - Проверка — real-browser тест computed styles на fixture-документе со всеми видами блоков, без screenshots.
  - Подсветка кода в редакторе в parity не входит: [«Подсветка синтаксиса в code block редактора Course Page»](https://github.com/dsc-sgu/mm-frontend/issues/131), вне карты.
- Отдельной валидации содержимого в publish gate нет: содержимое проверяет schema, ссылки — ввод. Hero и metadata в этот тикет не входят: их seam — обновление полей по #118.

### Рабочие допущения до ответа backend

- **Схема `data` блока принадлежит frontend, backend считает её непрозрачной.** Отображение документа на `(blockType, data)` живёт в transport mapping read-side и course-draft. Предпочтение: `blockType` — доменное имя типа. Если enum останется узким, mapping перейдёт на `text` + `data.kind`, а документ и редактор не изменятся. Открыто в [«Реестр frontend-вопросов к backend API»](https://github.com/dsc-sgu/mm-frontend/issues/113) («Остаётся ли `data` блока непрозрачным…»).
- **Тело spoiler хранится внутри `data` spoiler.** Если backend введёт superblocks ([backend #108](https://github.com/dsc-sgu/mm-backend/issues/108)), изменится только mapping.
- **Источник Task Summary — read-проекция Tasks курса.** Если свойства Task будут публиковаться вместе со snapshot, тот же seam начнёт брать их из snapshot или Working Copy. Документ и renderer при этом не изменятся. Будет ли у Task аннотация, решат [«Редактировать существующее задание в боковой панели»](https://github.com/dsc-sgu/mm-frontend/issues/41) и [«Согласовать, является ли Task подтипом блока Course Snapshot»](https://github.com/dsc-sgu/mm-frontend/issues/129); пока поля нет, карточка его не показывает.
- **Caption и alt в блоке Image, resource хранит только факты об asset.** Разделение content и resources открыто в #113.

### Факты backend

Проверено на `mm-backend@ddd9849` (`main`), ветки и PR пройдены целиком.

- Блоки плоские: `block_type TEXT`, `data jsonb` без проверки содержимого, `position varchar(64) COLLATE "C"`. Родителя и вложенности нет.
- Рядом объявлен неиспользуемый enum `block_type ('task','text')`. В открытом [#172](https://github.com/dsc-sgu/mm-backend/pull/172) колонка становится enum `('text','quiz','task')`, а Task — подтипом блока.
- Позиции целиком принадлежат серверу (самописный base-62 midpoint).
  - Create возвращает `{id}`, move — 200 без тела, списки сортируются `ORDER BY position`.
  - Фоновый ребаланс не меняет ни порядок, ни id.
  - **Поэтому `position` во frontend-модели не нужен.**
- Входные факты для sync в #118 (ADR 0002):
  - `afterBlockID: null` означает «в начало»;
  - move или create после удалённого блока даёт 400, различимый только по тексту;
  - create не идемпотентен;
  - новый черновик и `switch` копируют блоки с новыми id;
  - атомарного reorder нет;
  - мутации одного snapshot сериализуются.

  Вопросы по ним внесены в #113.

### Slices будущего рефакторинга

Каждый slice — clean cutover без compatibility layers.

## Уточнения из [«Спроектировать матрицу тестовых контрактов критических вертикалей»](https://github.com/dsc-sgu/mm-frontend/issues/120#issuecomment-6106418624)

- **Слои.** Заглушка невалидного блока, `unsupported-content` и семантический DOM списков проверяются в Component (jsdom): layout, selection и contenteditable в них не участвуют. Real browser остаётся для сценариев #74, parity, paste, фокуса и multi-drag.
- **Property-based тесты** — `fast-check` (devDependency, только Node-тесты слоя Model, через `@fast-check/vitest`): закон round-trip и идемпотентность канонизации. Shrinking сводит падение к минимальному документу, seed воспроизводит его.
- **Characterization до slice 1** на текущем редакторе: сценарии нумерации списков #74 (DOC-14) и фокус после команд (DOC-18). Оба проверяют видимый исход и после slice остаются целевыми контрактами.
- **Markdown при наборе** создаёт только узлы профиля, `3. ` остаётся текстом по #74, внутри code block ничего не преобразуется (DOC-23). Вставленный Markdown остаётся текстом; преобразование вынесено в backlog [«Преобразовывать вставленный Markdown в редакторе Course Page»](https://github.com/dsc-sgu/mm-frontend/issues/133).
