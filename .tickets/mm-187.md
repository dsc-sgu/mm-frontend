# Спроектировать, где Student видит свои репозитории

## Question

Где и как Student видит свои репозитории? У него отдельный репозиторий на каждую Task Group, и чтобы сдавать Attempts, ему нужны адрес каждого репозитория и Task Key каждой Task.

## Source

[«Спроектировать настройку Task и Task Groups»](https://github.com/dsc-sgu/mm-frontend/issues/180): на Course Page Task Group не видна, а Student без адреса её репозитория не начнёт работу. Вопрос вынесен из настройки Task.

## Что известно

- `CONTEXT.md`:
  - у Task Group один репозиторий на Student;
  - Task Group Key входит в адрес каждого такого репозитория;
  - Task Key — имя, которым Student называет Task, когда сдаёт Attempt через Git.
- После открытия Course Task Group Key и Task Key не меняются (решение #180).
- В приложении есть заглушки маршрутов:
  - `/courses/$courseSlug/repositories` — только для Teacher;
  - `/courses/$courseSlug/repositories/$studentUsername` — один репозиторий на Student, а не на пару (Student, Task Group).

## Что обсудить

- Где Student видит адреса: на Course Page, на странице Task, в отдельном разделе «Репозитории» или в нескольких местах сразу.
- Как показать Task Key и команду сдачи рядом с Task, чтобы их не надо было искать.
- Что Student видит до первого обращения к репозиторию и когда Task Group ещё пуста или заперта.
- Что видит Teacher: репозитории одного Student и репозитории всей Task Group. Как это связано с заглушками маршрутов выше.
- Совместимость с командными Task ([«Спроектировать командные Task»](https://github.com/dsc-sgu/mm-frontend/issues/185)): там репозиторий может принадлежать команде.

## Факты backend

_Проверено в открытом [«Ezhkin-Kot/fixes»](https://github.com/dsc-sgu/mm-backend/pull/172) (`dd05f5f`)._

- Репозиторий адресуется как `RepoID{CourseID, TaskGroupID, ParticipantID}` ([`pkg/git/models.go` L31-L35](https://github.com/dsc-sgu/mm-backend/blob/dd05f5fd05b152ecfda4f5ada378349a77716d24/pkg/git/models.go#L31-L35)).
- SSH-путь вида `<course>/<group>` сервер переводит в `RepoID` по SSH-ключу пользователя.
  - Код: `repoRename` ([`internal/attempts/service.go` L326-L341](https://github.com/dsc-sgu/mm-backend/blob/dd05f5fd05b152ecfda4f5ada378349a77716d24/internal/attempts/service.go#L326-L341)).
  - Каждый Student пишет один и тот же адрес, а попадает в свой репозиторий.
  - `<course>` — это `courses.name`, по смыслу slug Course. Он уникален только в пределах дисциплины, а смена slug меняет адрес у всех Students. `<group>` — сейчас `task_groups.name`, по решению #180 — Task Group Key. Подробности в #113, пункт «Ключ цепочки отдельно от названия и уникальность адреса репозитория» (уровень 1).
- Репозиторий создаётся при первом обращении по SSH.
- Сдача Attempt — push тега с опцией `-o submit=<Task Key>`.

Вопросы к backend добавить в [«Реестр вопросов фронтенда к API бэкенда»](https://github.com/dsc-sgu/mm-frontend/issues/113).

Вариант ответа на «Где Student видит адреса» (возник при разборе выхода Student из Course, #208):

- у каждого репозитория Student'а своя страница: один репозиторий — одна Task Group;
- страница открывается кнопкой в блоке Task Reference на Course Page, то есть от Task к репозиторию её Task Group.

Тогда заглушку `/courses/$courseSlug/repositories/$studentUsername` нужно перестроить под пару (Student, Task Group).
