# REV7.3: Продолжать работу редактора проверки при зависании и закрытии вкладки и при выходе из аккаунта

Часть эпика mm-218.

Редактор проверки продолжает работу, когда пишущая вкладка зависла, закрылась или пользователь вышел из аккаунта. Зависшая вкладка не перезаписывает правки после пробуждения, а рабочая копия не достаётся другому пользователю.

### Делает

**Силовая смена.**
- Если пишущая вкладка молчит 3 с после «Продолжить здесь», копия продолжает сама, без второго нажатия.
- Если вкладка ответила `handoff-accepted` и ждёт свой запрос, срок — таймаут запроса плюс 3 с.
- Продолжить силой может только вкладка с лайв-копией.
- Порядок: сначала счётчик в localStorage, потом `steal` у Web Lock.

**Проснувшаяся бывшая пишущая вкладка.**
- Сверяет счётчик раньше, чем узнаёт о потере Web Lock. Её просроченные запросы heartbeat и повтор публикации ничего не отправляют.
- Первое нажатие в ней не применяется. Она становится копией.

**Вкладка без лайв-копии** (открыта, когда пишущая уже молчит) показывает «Редактор открыт в другой вкладке, она не отвечает — перейдите в неё» и становится копией, когда пишущая оживает.

**Добровольная смена.** Пишущая вкладка держит Web Lock, пока получатель не заберёт его через `steal`. Если получатель не забрал Web Lock за 1 с, роль возвращается.

**Уход.** Предупреждение об уходе с несохранённой рабочей копией нужно, только если совместимой лайв-копии нет.

**Выход из аккаунта.**
- Содержимое во всех вкладках скрыто экраном «Вы вышли из аккаунта». Рабочая копия держится в памяти, закрытие вкладки предупреждает.
- Вход тем же пользователем продолжает работу. Бронь прежней сессии берётся перехватом тем же пользователем.
- Вход другим пользователем удаляет рабочую копию прежнего.

**bfcache.**
- `pagehide` — уход: Web Lock и канал отпускаются, копия продолжает.
- При `pageshow` с `persisted` вкладка продолжает со своей рабочей копией, только если запись о пишущей вкладке не менялась. Иначе выбрасывает её и подключается заново.

**Непроверенные допущения о движках** из mm-132 проверяются здесь:
- читается ли счётчик в localStorage синхронно и в актуальном значении сразу после разморозки;
- замораживаются ли отдельные фоновые вкладки в Firefox и Safari;
- блокирует ли удерживаемый Web Lock попадание в bfcache.

Результаты записываются в PR.

### Не входит

- TAB-03 (силовая смена с таймером автосохранения), TAB-07 и TAB-09 — DRF4.
- Восстановление рабочей копии из браузера после закрытия всех вкладок — mm-273.

### Контракты

Кандидаты из mm-132 («Вход для матрицы и следующих тикетов»), в матрице их ещё нет. Решение 5 эпика.

| id | Слой | Риск | Фикстуры | Контракт |
|---|---|---|---|---|
| кандидат | Stateful | Сохранность данных | `tabs`, `clock` | Силовая смена в проверке: пишущая вкладка заморожена дольше 3 с → копия продолжает от последней лайв-копии, счётчик +1; после разморозки heartbeat и повтор публикации бывшей пишущей вкладки ничего не отправляют, она становится копией. (I5) |
| кандидат | Stateful | Сохранность данных | `tabs` | Вкладка без лайв-копии не продолжает силой и становится копией, когда пишущая вкладка оживает. (I5) |
| кандидат | Stateful | Сохранность данных | `tabs` | Закрытие пишущей вкладки при лайв-копии: копия продолжает сама, предупреждения нет; без совместимой копии — предупреждение об уходе. (I5) |
| кандидат | Stateful | Доступ | `tabs` | Выход из аккаунта скрывает и держит рабочую копию; повторный вход тем же пользователем продолжает, вход другим пользователем удаляет рабочую копию. |
| кандидат | Stateful | Сохранность данных | `tabs` | Возврат из bfcache продолжает со своей рабочей копией, только если запись о пишущей вкладке не менялась. (I5) |

Фикстуры описаны во вкладке «Fixtures» [матрицы](https://github.com/dsc-sgu/mm-frontend/blob/ddda126c5e73ec787362805c286ee081ee26244d/docs/prototypes/test-contract-matrix.html).
