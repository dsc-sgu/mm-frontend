# Выбирать, с чем сравнивать попытку на странице попытки

## Источники

- Страница AnyType «MergeMinds: задания, task-группы, шаблоны и репозитории курса» в «Всё идёт по плану», §20 «Diff попытки»: «Всегда показывать base и target… Базу можно переключать. Показывать commits между состояниями и фильтр: [Все] [Студент] [Преподаватель/платформа]».

## Проблема

Страница попытки всегда сравнивает попытку с одной базой: в шапке «Сравнение с попыткой #N» или «Сравнение с пустой базой» (`src/features/course/features/attempt-review/ui/header.tsx`). Преподаватель не может:

- сравнить попытку №3 с попыткой №1, то есть увидеть всё, что изменилось после первой проверки;
- сравнить попытку с шаблонным репозиторием цепочки заданий;
- увидеть коммиты между базой и попыткой.

## Расхождение с решением

mm-116 (проектирование вертикали «проверка → оценка → результат студента»): «Baseline выбирает backend и описывает его в manifest… Frontend показывает „Сравнение с …“ и адресует материал только `AttemptId`». Этот тикет предлагает по умолчанию оставить базу сравнения от бэкенда и дать преподавателю выбрать другую базу. Для этого контракт должен принимать пару «попытка и база». В [mm-backend PR #172 «Ezhkin-Kot/fixes»](https://github.com/dsc-sgu/mm-backend/pull/172) есть `GET /attempts/diff?id1&id2`, где пару выбирает клиент.

## Что решить

- Какие базы доступны: любая предыдущая попытка того же задания, попытка предыдущего задания в цепочке, шаблон, пустое дерево.
- Что происходит с тредами к строкам при другой базе. Комментарий преподавателя привязан к стороне diff и к строкам относительно базы сравнения. Возможно, с другой базой экран только для чтения.
- Показывать ли список коммитов между базой и попыткой. Фильтр «Студент / платформа» имеет смысл, только если платформа сама коммитит в репозиторий студента. После mm-180 шаблон после открытия курса не меняется, поэтому таких коммитов пока нет.
