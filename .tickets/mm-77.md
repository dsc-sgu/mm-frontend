# Перевести auth flow на fetch и запустить MSW mock backend

## Parent

[Перевести frontend с RAM-моков на fetch и MSW](https://github.com/dsc-sgu/mm-frontend/issues/73)

## What to build

Провести первый сквозной запрос через настоящий HTTP interface: development-приложение запускает MSW, а session/login/register/logout используют те же fetch-клиенты, которые сможет обслуживать реальный backend. Одновременно создать resettable mock backend instance из детерминированного default seed, чтобы следующие slices могли расширять его без прямых imports из frontend features.

## Acceptance criteria

- [ ] MSW browser worker запускается только при явно включённом mock-режиме; без него запросы уходят настроенному backend.
- [ ] Mock backend создаётся как отдельный stateful instance из детерминированного default seed.
- [ ] Session, login, register и logout проходят через HTTP и MSW handlers, а не через прямые вызовы RAM-моков.
- [ ] Session содержит identity и состояние аутентификации, но не course role.
- [ ] Development auth flow остаётся демонстрируемым с включённым MSW.
- [ ] Выключение MSW не требует изменений в auth query/mutation modules.
- [ ] Lint и build проходят.
