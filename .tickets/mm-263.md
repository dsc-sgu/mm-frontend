# Привязка треда к строкам: DiffLine и DiffLineRange вместо четырёх плоских полей

### Делает

Вводит в `review/model` тип привязки треда к строкам и переводит на него всю модель проверки, `attempt-review`, схему ответа бэкенда и мок-бэкенд.

Сейчас комментарий преподавателя привязан к строкам дифф-попытки четырьмя плоскими полями:

```ts
side: ReviewCommentSide;
lineNumber: number;
endSide?: ReviewCommentSide;
endLineNumber?: number;
```

По смыслу это диапазон из двух позиций, но из типа это не видно: при чтении не сразу понятно, что `side` относится к `lineNumber`, а `endSide` к `endLineNumber`. К тому же тип допускает невозможные состояния: `endSide` без `endLineNumber` и наоборот, или конец, совпадающий с началом. Рядом, в `attempt-review/model/line-comment.ts`, живёт вторая форма того же понятия, `AttemptReviewLineRange` (`start`, `side?`, `end`, `endSide?`), и устроена она иначе.

Новая модель:

```ts
/** A line on one side of the Attempt diff. */
export type DiffLine = { side: ReviewCommentSide; lineNumber: number };

/** The lines a root comment is anchored to; a single line has start === end. */
export type DiffLineRange = { start: DiffLine; end: DiffLine };

export type ReviewComment = {
  id: string;
  author: ReviewAuthor;
  filePath: string;
  range: DiffLineRange;
  // ...
};
```

- Связь полей видна из структуры: `range.start.side`, `range.end.lineNumber`.
- Необязательных полей нет. Тред к одной строке — диапазон, у которого начало равно концу. Подписи «К новой строке #2», «К старым строкам #3–5» и «К старой строке #3 → новой строке #5» выбираются сравнением `start` и `end`.
- Вариант `{ kind: 'line', at } | { kind: 'range', start, end }` отклонён: код разбирал бы два случая там, где общий подходит одинаково.

### Форма в ответе бэкенда

Схема в `api/` описывает ту же вложенную форму, что и доменная модель, без перекладывания из плоских полей:

```json
"range": {
  "start": { "side": "additions", "lineNumber": 3 },
  "end": { "side": "additions", "lineNumber": 5 }
}
```

Мок-бэкенд (`src/app/mock-backend/`) хранит и отдаёт эту же форму. Это предложение фронтенда: в #113 вопрос о хранении привязки ещё открыт, и форма вынесена туда на согласование. Если бэкенд её не примет, перекладывание добавится в схему в `api/`, а доменная модель не изменится.

### Где проходит граница с `@pierre/diffs`

`AttemptReviewLineRange` — не доменная форма, а форма выделения из `@pierre/diffs`. Она приходит в `onGutterUtilityClick` (`attempt-review/ui/diff.tsx`) и без изменений уходит в `addLineComment`. Словарь библиотеки должен остаться снаружи модели, переводиться он будет в двух местах:

1. `attempt-review/ui/diff.tsx` → `addLineComment`: выделение библиотеки → `DiffLineRange`. Здесь же решается, что делать, если библиотека не передала `side`.
2. `attempt-review/model/code-view-item.ts`: `DiffLineRange` → аннотации библиотеки.

Значения `'deletions' | 'additions'` тоже пришли из библиотеки (`AnnotationSide` в `@pierre/diffs`). По-доменному это старая и новая версия файла, так и пишет UI. Переименовывать их в этом тикете не нужно: форма контракта ещё открыта в #113.

### Удаляет

- Поля `side`, `lineNumber`, `endSide`, `endLineNumber` из доменных типов.
- `AttemptReviewLineRange` и псевдоним `AttemptReviewCommentSide`, если после перевода он больше не нужен.

### Не входит

- Переименование `'deletions' | 'additions'` в доменные значения: решается вместе с контрактом в #113.

### Контракты

Новых контрактов в матрице нет. Существующие тесты `load-review.test.ts`, `code-view-item.test.ts`, тесты треда к строкам и E2E проверки должны проходить без изменения сценариев: меняется только форма данных в ожиданиях.

### Готово, когда

- `DiffLine` и `DiffLineRange` лежат в `review/model`, и `ReviewComment` использует `range: DiffLineRange`.
- В `src/` нет `endSide`, `endLineNumber` и `AttemptReviewLineRange`. Словарь `@pierre/diffs` встречается только на двух границах выше.
- Схема ответа в `load-review.ts` и мок-бэкенд используют вложенную форму `range: { start, end }`, плоских полей в ответе нет.
- `bun run lint`, `bun run build` и `bun run test` проходят.

### Источники

- Ревью ветки REV2.1 (#221): поля привязки в `review/model/types.ts` читаются как несвязанные, и рядом в `line-comment.ts` живёт вторая форма того же понятия.
