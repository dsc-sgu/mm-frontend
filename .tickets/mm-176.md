# Управлять подгруппами курса и приглашать студентов в нужную подгруппу

## Источники

- mm-42 (спецификация дедлайнов): дедлайн задания может переопределяться для подгруппы (переопределение дедлайна). Чтобы групповые дедлайны было к кому применять, преподаватель должен управлять подгруппами своего курса и составом каждой из них.

## Проблема

На фронтенде нет ни одного места, где преподаватель создаёт подгруппы, распределяет по ним студентов или приглашает студента в курс. Группа в моках списка попыток курса и страницы попытки — это просто строки `group: 'БПИ-231'` и `subgroup: '1'`, которые не берутся ни из какой модели.

## Уже решено

- Подгруппы одного курса плоские. Подгруппа — это отдельная группа студентов этого курса («151-1пп», «151-2пп», «111-1пп», «111-2пп»). Иерархии «группа → подгруппа» внутри курса нет. Глоссарий: `CONTEXT.md`, термин «подгруппа» (Student Group).
- В каждом курсе есть хотя бы одна подгруппа. Новый курс создаётся с одной подгруппой по умолчанию; состояния «в курсе нет подгрупп» нет.
- Студент состоит ровно в одной подгруппе курса. Студентов без подгруппы не бывает.
- _Решено владельцем 2026-10-25:_ ссылка-приглашение для студента ведёт в конкретную подгруппу, а не в курс вообще; студент вступает в курс сразу в эту подгруппу. У нового курса это его единственная подгруппа.
- _Решено владельцем 2026-10-25:_ этот тикет — минимум, без которого курсом нельзя пользоваться (P0). Остальное управление подгруппами вынесено в P1 (раздел «Не входит»).
- _Решено владельцем 2026-10-25:_ преподавателей тоже приглашают по ссылке. Ссылка преподавателя ведёт в курс без подгруппы. Создать её может только тот, кто создал курс.

## Что входит

- Создать и переименовать подгруппу курса.
- Ссылка-приглашение в каждую подгруппу.
- Ссылка-приглашение для преподавателя. Её видит и создаёт только создатель курса.
- Видеть, кто в какой подгруппе.

## Не входит

Перевод студентов между подгруппами, удаление подгруппы с переводом её студентов, список ссылок-приглашений курса и отзыв ссылки — отдельный тикет P1, mm-cc7t9.

## Что решить

- Где это живёт в интерфейсе: отдельный раздел курса «Участники» или настройки курса.

## Факты бэкенда

_Проверено на `mm-backend@ddd9849` (`main`) и в открытом [mm-backend PR #172 «Ezhkin-Kot/fixes»](https://github.com/dsc-sgu/mm-backend/pull/172) (`dd05f5f`)._

- `groups(id, name)` не привязана к курсу. `course_users_groups(user_id, course_id, group_id)` имеет первичный ключ из всех трёх полей, то есть допускает несколько групп у одного студента в одном курсе ([`db/CreateTables.sql` L172-L183](https://github.com/dsc-sgu/mm-backend/blob/ddd98496d1293a3cf9844201e70376b3364fdcc3/db/CreateTables.sql#L172-L183)). Код эти таблицы не читает и не пишет.
- Ссылки-приглашения уже есть ([`internal/api.go` L191-L213](https://github.com/dsc-sgu/mm-backend/blob/ddd98496d1293a3cf9844201e70376b3364fdcc3/internal/api.go#L191-L213)):
  - `POST` и `GET /courses/{course_id}/invites`;
  - `GET /invites/{invite_id}`;
  - `POST /invites/{invite_id}/join`.
- Приглашение хранит `provided_role`, `expires_at` и `is_revoked`, но не группу ([`db/CreateTables.sql` L94-L103](https://github.com/dsc-sgu/mm-backend/blob/ddd98496d1293a3cf9844201e70376b3364fdcc3/db/CreateTables.sql#L94-L103)).
- В mm-backend PR #187 (`14a6abb`) приглашение с любой ролью, в том числе `TEACHER`, может создать любой преподаватель курса (`CreateInvite`, `internal/courses/membership/service.go`). Создатель курса известен: `courses.owner_id`. Ограничить ссылки преподавателя создателем курса — вопрос к бэкенду в mm-113.

_В mm-backend PR #187 (`14a6abb`) перепроверено 2026-10-25:_ всё так же. `groups(id, name)` без курса, первичный ключ `course_users_groups` — `(user_id, course_id, group_id)`, код эти таблицы не трогает, у `invites` нет подгруппы ([`db/CreateTables.sql` L110-L119, L188-L199](https://github.com/dsc-sgu/mm-backend/blob/14a6abb829cfb2d9bce4ea484a367649d1d57f19/db/CreateTables.sql#L110-L199)). API подгрупп нет.

Вопросы к бэкенду — в mm-113: «Модель подгрупп» и комментарий от 2026-10-25 про подгруппу в приглашении.
