# Сортировать Course Attempts по времени отправки и фильтровать по периоду

## Source

- Страница AnyType «Разбор состояния фронтенда MergeMinds на 6.06.2026», №1: «Пока не хватает фильтра на дату или хотя бы сортировки по дате, частый кейс проверять работы, которые давно не проверялись».
- Страница AnyType «Ругаюсь на Moodle»: сортировка по дате последней попытки.

## Проблема

В Course Attempts нет ни сортировки, ни фильтра по времени. Порядок задаёт источник данных: сейчас это порядок, в котором mock их сгенерировал. Teacher не может поднять наверх Attempts, которые дольше всех ждут Review, и не может ограничить список, например, последней неделей.

## Что делает

- Сортировка по времени отправки Attempt: сначала старые (дольше ждут проверки) или сначала новые.
- Фильтр по периоду отправки: «с» и «по».
- Сортировка и период хранятся в search-параметрах маршрута, как остальные фильтры.
- Время подписано часовым поясом, как в [#182](https://github.com/dsc-sgu/mm-frontend/issues/182).

## Что решить

- Сортировка по умолчанию. Вместе с фильтром «Не оценено» естественна очередь проверки: сначала старые.
- Нужна ли сортировка по времени последней Review Revision.
- Ввод дат: тот же контрол, что у Deadline в [#42](https://github.com/dsc-sgu/mm-frontend/issues/42).

## Вопросы к backend

Сортировка и фильтр по периоду на стороне backend, чтобы они работали вместе с пагинацией. Добавить в [«Реестр frontend-вопросов к backend API»](https://github.com/dsc-sgu/mm-frontend/issues/113).
