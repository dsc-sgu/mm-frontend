# Добавить жёсткий срок сдачи (cut-off) для задания

## Источники

- mm-42 (спецификация дедлайнов): в MVP дедлайн только мягкий. Он не закрывает задание, а попытка после него принимается и считается опоздавшей (`CONTEXT.md`, термин «дедлайн»). Жёсткий срок вынесен сюда, в бэклог.

## Проблема

Иногда преподавателю нужен момент, после которого попытки по заданию больше не принимаются: например, конец зачётной недели. В Moodle Assignment это cut-off date рядом с due date. Сейчас такого понятия нет ни на фронтенде, ни на бэкенде: у `tasks` есть только `available_at` и `deadline_at`.

## Почему не сейчас

- Сдача идёт через Git: push в последние секунды и сетевые задержки делают жёсткую границу спорной.
- Жёсткий срок добавляет заданию состояние «закрыто для этого студента». Оно пересекается с доступом студента к заданию и с ещё не выбранным критерием продвижения по заданиям (mm-110 — критерий завершения задания и открытия следующего).

## Что решить

- Задаётся ли жёсткий срок на тех же уровнях, что дедлайн: у задания, в переопределении дедлайна для подгруппы и для студента, с тем же правилом старшинства.
- Должен ли жёсткий срок быть не раньше действующего дедлайна.
- По какому моменту судит бэкенд: по времени push или по времени, когда бэкенд получил попытку.
- Что видит студент до и после жёсткого срока.
- Вопрос к бэкенду добавить в mm-113 (реестр вопросов фронтенда к API бэкенда).
