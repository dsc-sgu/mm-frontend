# ACC1.2: Входить в Course через загрузку по slug с явным 404 и отказом проверки

Часть epic [«Course access»](https://github.com/dsc-sgu/mm-frontend/issues/167). Перед началом прочитать [`docs/agents/remote-data.md`](https://github.com/dsc-sgu/mm-frontend/blob/main/docs/agents/remote-data.md) (обязательно по `AGENTS.md`).

Вход в любой Course route начинается одной загрузкой Course по slug, которая называет роль текущего User. Отказ на уровне Course становится явным состоянием route вместо redirect.

### Делает

**Загрузка Course по slug.** Форма результата — из [#115](https://github.com/dsc-sgu/mm-frontend/issues/115):

```ts
type LoadCourseResult =
  | {
      status: 'found';
      course: { id: CourseId; title: string; shortTitle: string; iconName: CourseIconName; color: CourseColor };
      role: CourseRole;
    }
  | { status: 'course-not-found' }
  | { status: 'not-member' };
```

- `loadCourseBySlug(courseSlug, signal)` на транспортном ядре. Сеть, необъявленный status и невалидный DTO — отказ операции, а не отказ в доступе.
- MSW handler читает Courses и Course Memberships текущего User из состояния ACC1.1. Wire format, включая различие `course-not-found` и `not-member`, — рабочее допущение [#113](https://github.com/dsc-sgu/mm-frontend/issues/113), помеченное в handler.
- `courseContextKeys.bySlug(userId, courseSlug)` стоит вне Course prefix: вход операции — slug.
- Перепроверка — при входе в Course, focus и reconnect. Кроме того, есть точка входа «отказ защищённой операции по доступу»; её первые потребители — операции ACC2.2.

**Course root.**
- Lookup заменяет старую проверку доступа и поиск Course в списке курсов.
- Контекст route содержит `CourseId`, metadata shell (title, shortTitle, иконка, цвет) и `CourseRole`. Списка username Students в нём нет.
- Вложенные routes не загружают Course Page ради identity или роли.

**Route states** по [#111](https://github.com/dsc-sgu/mm-frontend/issues/111):

| Исход | Что видит User | Действие |
|---|---|---|
| `course-not-found`, `not-member`, синтаксически неверный slug | «Страница не найдена» — «Возможно, ссылка устарела или страница больше недоступна.», только общий authenticated shell | «К моим курсам» |
| Сеть, неожиданный ответ, невалидный DTO | «Не удалось проверить доступ», защищённое содержимое не показывается | «Повторить» перезапускает lookup, «К моим курсам» |

- URL не меняется.
- **Пока Course context не подтверждён** для `(UserId, CourseSlug)`, показывается нейтральная загрузка без metadata, breadcrumbs и навигации.
- **Закэшированный context того же User** считается подтверждением: содержимое видно сразу, context перепроверяется в фоне.
- **Shell и содержимое предыдущего Course** под URL нового не показываются никогда.
- **Model.** Отображение внутреннего исхода в категорию route state (ACC-02) покрывает все категории, включая `403` и resource `404`. Их показывают ACC1.3 и ACC2.2.

**Header.**
- Breadcrumbs и навигация строятся из подтверждённого Course context, название — из lookup. Подставного title из slug и выдуманного доступа «по умолчанию» нет. Пока context не подтверждён, их нет.
- Набор пунктов навигации по роли пока прежний, section policy вводит ACC1.3.
- Ссылка Student'а «Репозиторий» использует `Username` из session как locator.

**Роль только из Course.**
- Роль удаляется из типа session и из схемы ответа session.
- Права ответа на комментарии в attempt review берутся из `CourseRole`:
  - Teacher этого Course может отвечать;
  - Student может отвечать на своей Attempt — владение пока гарантирует route;
  - остальные не могут.
- Task Page получает роль из контекста Course.

**Participant-bound routes до ACC2.2.**
- Проверка состава Students у Teacher'а удаляется вместе со списком username.
- Student на чужом Repository или Attempt получает resource `404` внутри Course shell («На страницу курса») по прежнему сравнению username, без redirect.
- Синтаксически неверный username или номер тоже даёт resource `404`.

**Раздел не по роли до ACC1.3** — прежний redirect, но роль берётся из нового контекста.

**Test-only инфраструктура** (первые потребители — контракты этого тикета):
- **Component.** Опция существующего harness рендеринга routes рендерит настоящее дерево routes приложения: memory history, настоящий Header, свежие Router и QueryClient, MSW в Node.
  - В Vitest нет code splitting router plugin, поэтому дерево загружает в jsdom все route-модули, а authenticated layout монтирует worker pool attempt review.
  - Если это мешает, worker подменяется в конфиге тестов или pool переносится на routes review.
- **E2E.** Test-only handler MSW, доступный только в test build и никогда в production; это не глобал на `window`. Он:
  - выбирает мир;
  - задаёт session текущего User;
  - удерживает ответ названной операции, пока тест его не отпустит.

  Выбранный мир и session переживают полную загрузку страницы. Обычный dev-режим по-прежнему сбрасывает состояние при каждой загрузке.

**ESLint.** Модуль старой проверки доступа уходит из списка исключений импортёров RAM-моков.

### Удаляет

- Старую операцию проверки доступа, её ключ и тип результата.
- Поиск Course в списке курсов в Course root.
- Redirect guards уровня Course и redirects на синтаксически неверные locators.
- Роль в session.
- Список username Students в контексте Course и проверку состава Students.
- Подставной title Course и доступ «по умолчанию» в header.
- Глобально-ролевые подсказки в моках («Текущий преподаватель» как текущий User независимо от курса) и захардкоженного Teacher'а как автора reply.

### Не входит

- Section policy, `403` и реакция на смену роли — ACC1.3.
- Владение participant-bound ресурсом по решению backend — ACC2.2.
- Общий Course prefix ключей и очистка кэша при смене session — ACC3.
- Смена slug — DRF1.
- Login UI не закрепляется.
