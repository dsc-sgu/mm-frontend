# Отказ в доступе одинаков для чужого и несуществующего: 404 без тела и один исход

Реализует [ADR 0006](https://github.com/dsc-sgu/mm-frontend/pull/265) «Отказ в доступе не раскрывает существования ни на экране, ни по сети». Перед началом прочитать [`docs/agents/remote-data.md`](https://github.com/dsc-sgu/mm-frontend/blob/main/docs/agents/remote-data.md) (обязательно по `AGENTS.md`).

### Делает

Сейчас экран чужое и несуществующее не различает, а сеть и внутренние исходы — различают. Моки раскрывают это тремя способами:

| Мок | Ответ | Что раскрывает |
|---|---|---|
| курс по slug (`access/api/mock.ts:36,43`) | `404` + `{ status: 'course-not-found' }` / `404` + `{ status: 'not-member' }` | тело |
| локатор попытки и репозиторий (`attempt-review/api/mock.ts:30-32,44`, `repository/api/mock.ts:17-19`) | `403` + `forbidden` / `404` + `not-found` | статус и тело |
| чтения по идентичности (`accessDenial` в `app/mock-backend/participant-access.ts`) | `403` / `404` без тела | статус |

Тикет сводит всё к одному правилу:

- **Курс**: нет курса или нет участия → один исход `not-found`, по сети `404` без тела.
- **Ресурс участника** (попытка, репозиторий, проверка): нет или чужой → один исход `not-found`, `404` без тела. Одинаково для локаторов и для чтений по идентичности.
- **`403` раздела по роли** не меняется: он считается на фронтенде из роли в контексте курса.
- **Перепроверка курса — после любого отказа на ресурсе**, а не только после `forbidden`.
- **Отказ после `found` — потеря доступа**: кэш данных курса удаляется на любом переходе `found → not-found`.

### Модель и API

- `access/api/resource-denial.ts`: `ResourceDenial` = `{ status: 'not-found' }`. `readResourceDenial` превращает в него только `404`. `403` на чтении ресурса становится `unexpected-http-status`: по контракту его больше нет. `isResourceDenial` упростить или убрать.
- `access/api/load-course.ts`: исходы `found` и `not-found`, без `course-not-found` и `not-member`. Отказ — `404` без тела. Тело `{ status: … }` у отказа больше не читается.
- `access/model/route-state.ts`: вместо `course-not-found` и `not-member` — один исход курса.
- `attempt-review/api/load-attempt.ts`, `repository/api/load-repository.ts`: без варианта `forbidden`. Отказ локатора — `404` без тела, как у чтений по идентичности, через тот же `readResourceDenial`.
- `access/api/queries.ts:23`: условие `previous.status === 'found' && result.status === 'not-member'` → любой отказ после `found`. Комментарий «A slug that stops resolving is not one; the Course keeps its CourseId cache» заменить: смена slug того же курса обрабатывается только через ответ `found` с новым slug (ADR 0005, mm-254).

### Перепроверка

Убрать условие `forbidden` в трёх местах:
- `routes/_authenticated/courses/$courseSlug/tasks/$taskId/attempts/$studentUsername/$attemptNumber/route.tsx`: `beforeLoad` ждёт перепроверку после любого отказа локатора;
- `routes/_authenticated/courses/$courseSlug/repositories/$studentUsername/route.tsx`: так же;
- `access/ui/route-state.tsx` (`CourseResourceDenied`): перепроверка в фоне после любого отказа.

Проверить, что `attempt-review/page.tsx` и чтения по идентичности (`load-summary`, `load-material`, `load-student-attempts`, `review/api/load-review.ts`) не опираются на `forbidden` в других местах.

### Мок-бэкенд

- `app/mock-backend/participant-access.ts`: `authorizeStudent` и `resolveAttemptAccess` отдают `not-found` вместо `forbidden` для «не участник курса» и «студент запрашивает чужое». `DENIAL_STATUSES` — без `forbidden`. Комментарий к `accessDenial` поправить: раскрывать нечего ни телом, ни статусом.
- `access/api/mock.ts`: оба отказа курса — `404` без тела.
- Локаторы в `attempt-review/api/mock.ts` и `repository/api/mock.ts` — через `accessDenial`, без тела.

### Удаляет

- Исходы `forbidden`, `course-not-found`, `not-member` из типов, схем и моков ресурса и курса.
- Тела у ответов-отказов.
- Ветвление перепроверки по `forbidden`.

### Не входит

- `403` раздела по роли (`courseSectionAccess`) и `401` без сессии: не меняются.
- `forbidden` в открытии редактора черновика курса (DRF-05): это отказ по роли или брони, а не по существованию. Проверить при реализации и, если он раскрывает существование, вынести в отдельный тикет.
- Различение «эндпоинта нет» и «отказа»: вопрос к бэкенду в mm-113.

### Готово, когда

- По ответу мок-бэкенда нельзя отличить чужое от несуществующего ни статусом, ни телом, ни для курса, ни для ресурса участника.
- В типах, схемах и моках нет `forbidden`, `course-not-found` и `not-member` для курса и ресурсов участника.
- Курс перепроверяется после любого отказа на ресурсе; отказ после `found` удаляет кэш данных курса.
- ACC-04 и ACC-08 переписаны и зелёные, проверка неразличимости добавлена.
- `bun run lint`, `bun run build`, `bun run test` и Playwright проходят.
