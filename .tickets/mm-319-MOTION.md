# MOTION: Соблюдать настройку уменьшения анимаций

## Цель

Применить принятую политику Reduce Motion к существующим анимациям: prefers-reduced-motion не должен ломать навигацию, фокус или завершение переходов. Сохранить нужные состояния интерфейса без обязательной анимации.

## Удаляет или заменяет

Обязательные анимации для пользователя с включённым уменьшением движения.

## Принятое решение и границы

Владелец подтвердил frontend-first подход: существующий API-слой бэкенда заменяется контрактами, определёнными потребностями фронтенда. Модель черновиков блоков, публикации со слиянием и чекпоинтов согласована. Ожидание старого API не блокирует этап. HTTP-формы и исходы операции закрепляются в схемах, MSW и тестах; вопросы о реализации и оставшиеся ограничения фиксируются в mm-113.

Перед реализацией прочитать `docs/agents/remote-data.md`, актуальный `CONTEXT.md` и связанные ADR. Устаревшие положения ADR 0002 и ADR 0004 о брони редактирования курса заменяются решением mm-286; бронь проверки сохраняется. Изменения доменной документации учитывает mm-286.

Новая архитектура не требует переименования каталогов из mm-292 заранее: использовать текущие пути с теми же владельцами поведения. Не выделять отдельное «чистое ядро». Этап выполняется заменой за один шаг без второго временного пути данных.

## Проверяемое поведение

Отдельных контрактов матрицы нет; проверить поведение через интерфейс операции и затронутые существующие сценарии.

Отдельных контрактов матрицы нет; проверять наблюдаемое поведение с prefers-reduced-motion в браузере. Новые анимации в область не входят.

## Готово, когда

- [ ] Реализовано описанное поведение и удалён прежний путь в затронутой зоне.
- [ ] Схемы, моки и тесты используют один контракт; отказ, отмена и неизвестный исход не изображаются успехом.
- [ ] Проходят `bun run lint`, `bun run build` и проверки уровня владельца контракта; браузерные сценарии — в Chromium, Firefox и WebKit.
- [ ] Сохранены применимые общие контракты доступности `A11Y-01` и `A11Y-02`.
