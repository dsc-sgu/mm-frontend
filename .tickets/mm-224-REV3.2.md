# REV3.2: Загружать материал попытки по манифесту изменённых файлов с контролем полноты

Часть эпика mm-218. Перед началом прочитать [`docs/agents/remote-data.md`](https://github.com/dsc-sgu/mm-frontend/blob/main/docs/agents/remote-data.md) (обязательно по `AGENTS.md`).

Материал попытки приходит от бэкенда: атомарный манифест изменённых файлов и содержимое по записям. Преподаватель видит, с чем сравнивается попытка и какие файлы не загрузились, и не может сохранить проверку, пока материал неполон.

### Делает

**Мок-бэкенд.**
- У каждой попытки есть манифест. База сравнения описана в манифесте: попытка (возможно, другого задания той же цепочки заданий), шаблон или пустое дерево.
- Запись манифеста — путь, тип изменения, вид (`text | binary | too-large | unsupported`) и размеры.
- Содержимое текстовой записи — полный старый и новый текст.
- `world:review`, Саша, попытка №2: 3 текстовые записи, binary и too-large, база сравнения — попытка №1.
- База сравнения, манифест и полнота содержимого — рабочие допущения mm-113, помеченные в обработчиках MSW.
- Профиль `fail:entry`: содержимое записи падает N раз или всегда. Канал только для тестов умеет включать его для E2E.

**Загрузка.**
- Сначала атомарный манифест, затем содержимое по записям. Транспорт может группировать записи.
- Автоматический повтор ограничен для каждой записи. «Повторить» перезапрашивает только упавшие.
- Содержимое неизменяемо и кэшируется по `AttemptId` и записи.

**Полнота** — чистая функция от манифеста и статусов записей: все загружены → `complete`; есть упавшие → `incomplete { count }`. Нетекстовые записи помечены «не отображается» и полноту не блокируют.

**Интерфейс.**
- Шапка: «Сравнение с попыткой #N», «Сравнение с шаблоном» или «Сравнение с пустой базой».
- Упавшие записи перечислены по именам с окончательной ошибкой и «Повторить».
- Пока материал неполон, сохранение недоступно с причиной «материал неполон (N)». Поля проверки можно редактировать.

### Удаляет

- Вычисление изменённых файлов на клиенте из двух снимков.
- Временную операцию материала из REV2.1.
- `baselineAttemptNumber`, выведенный клиентом.

### Не входит

- Выбор базы сравнения преподавателем — бэклог, mm-196.
- Показ файла целиком — бэклог, mm-195.
- Потоковая передача материала: она заменит только способ доставки.

### Загрузка страницы

После [PR #239](https://github.com/dsc-sgu/mm-frontend/pull/239) чтения страницы попытки стартуют из `loader` маршрута через `attemptPageQueries` / `prefetchAttemptPage`, а ссылки на попытку предзагружают маршрут по намерению (раздел «Загрузка данных страницы» в `docs/agents/remote-data.md`). Манифест и содержимое по записям ложатся на эту схему так:

- **Манифест — независимое чтение.** Его вход (`AttemptId`) известен из контекста маршрута, поэтому манифест входит в `attemptPageQueries` вместо временной операции материала и запускается и при навигации, и при предзагрузке.
- **Содержимое записей — зависимые чтения.** Их входы известны только из манифеста, поэтому их нет в `attemptPageQueries`. Их запускает страница по манифесту (или `loader` после манифеста) — **только при настоящей навигации, никогда при предзагрузке по наведению**: наведение не должно тянуть полные тексты файлов.
- **Переключение попытки** отменяет незавершённые запросы содержимого предыдущей попытки; REV-38 остаётся в силе.
- **Отказ в доступе** у манифеста и содержимого — объявленный исход `ResourceDenial`, как у остальных чтений по `AttemptId`; сбой содержимого записи — отказ этой записи с «Повторить».
- **Ленивые зависимости.** Операции, которые запускает `loader`, попадают в основной бандл; парсер diff импортируется динамически внутри операции (как сейчас в `load-material.ts`).

Потоковая передача по-прежнему не входит. Когда она появится: поток не открывается при предзагрузке; отказ в начале потока — объявленный исход; обрыв посреди потока — сбой записи с «Повторить».

### Форма базы сравнения в модели

База сравнения описывается в модели вариантами (ADT по `AGENTS.md`), а не полем `baselineAttemptNumber: AttemptNumber | null`, как во временной операции материала из REV2.1. Поле `number | null` не различает два случая, когда номера попытки нет, поэтому если бэкенд выберет шаблон, шапка неверно покажет «Сравнение с пустой базой».

```ts
type Baseline =
  | { kind: 'attempt'; attemptId: AttemptId; attemptNumber: AttemptNumber; taskId: string }
  | { kind: 'template' }
  | { kind: 'empty' };
```

- Варианты взаимоисключающие. Не заменять их опциональным номером и булевым флагом.
- Базой сравнения может быть попытка предыдущего задания той же цепочки заданий: у студента один репозиторий на цепочку, и первая попытка следующего задания продолжает код предыдущего (решение фронтенда в mm-113, правило бэкенда пока открыто). Поэтому в варианте `attempt` есть задание: одного номера попытки мало. Шапка должна показывать, что это попытка предыдущего задания цепочки, а не только «Сравнение с попыткой #N».
- Текст «Сравнение с …» шапка выбирает через `switch` по `kind`, без проверки номера на truthy.
- DTO манифеста приводится к этому типу на границе доверия. Что именно бэкенд передаёт для варианта `attempt`, остаётся рабочим допущением mm-113.
