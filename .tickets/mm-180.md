# Спроектировать настройку Task и Task Groups

## Question

Как Teacher настраивает Task и Task Groups? Нужно решить:

- какие свойства есть у Task и где настраивается каждое;
- как устроены Task Groups и их шаблонные репозитории;
- что из этого можно менять после открытия Course;
- как настройка делится между боковой панелью на Course Page, страницей Task и отдельными экранами, например экраном дедлайнов.

## Зачем сейчас

Дедлайны — часть настройки Task: в чеклисте страницы «Фронтенд MergeMinds» в AnyType они стоят в разделе «Задание». Спецификация дедлайнов готова в mm-42. Прототипировать экран дедлайнов отдельно от настройки Task странно, поэтому общий прототип ждёт этот тикет.

## Уже решено, не переоткрывать

- Прототип боковой панели mm-101 влит в общий прототип mm-181; mm-41 — реализация панели в продукте, ждёт mm-181.
- Модель дедлайнов: mm-42, в `CONTEXT.md` — Deadline, Deadline Override, Effective Deadline.
- Student Groups плоские, у каждого Student ровно одна группа: mm-176.
- Жёсткий срок сдачи — backlog mm-177.
- Спецификация mm-100:
  - Task редактируется прямо из просмотра Course, в боковой панели (mm-41, прототип mm-101);
  - есть «Создать ещё» (mm-106);
  - после открытия Course меняются только безопасные метаданные Task.
- Страница AnyType «Как устроена платформа»:
  - Task надстраивается над блоком Course Page;
  - Task Group — набор Task в одном репозитории; на каждую Task Group каждый Student получает свой репозиторий из шаблонного репозитория группы;
  - внутри Task Group Task идут строго по порядку, сами Task Groups выполняются параллельно;
  - после открытия Course меняются только метаданные Task: название, условие, дедлайн.

## Что обсудить

- Полный набор свойств Task:
  - название, условие, вложения;
  - максимальная Grade, максимум Attempts;
  - маски путей решения;
  - время открытия, дедлайн;
  - аннотация Task Summary (mm-129);
  - варианты задания (mm-124);
  - командная Task (participant в AnyType).
- Какие свойства можно менять после открытия Course. `maxGrade` после открытия фиксируется.
- Где настраивается каждое свойство:
  - боковая панель mm-41;
  - страница Task (mm-32, mm-33);
  - список Task (mm-40);
  - экран дедлайнов (mm-42).
- Task Groups: создание, переименование, удаление, порядок Task внутри группы, шаблонный репозиторий. Как Task попадает в группу и как группы видны Teacher'у.
- Доступность Task:
  - по времени (`available_at` на backend);
  - по prerequisite внутри Task Group (критерий отложен, mm-110);
  - для отдельных Student Groups. Встреча 03.02 в AnyType: «задание может быть доступно для одной подгруппы, но недоступно для другой».
- Пресеты настроек и какие настройки переносит «Создать ещё».
- Ввод даты и времени с клавиатуры одним компактным контролом. Страница AnyType «Ругаюсь на Moodle»: «23:59» не листанием.
- Применение правок Task: отдельно от Course Draft Snapshot или вместе с ним. См. mm-107 и вопрос №2 на странице AnyType «Открытые вопросы».
- Переписать mm-41 по итогам этого тикета и прототипа mm-181 или заменить его тикетами будущей спецификации настройки Task.

### Применение правок Task

- **Требование frontend — контракт в mm-129** (уточнено 13.10.2026). Модель данных выбирает backend.
  - У опубликованной Task свой lifecycle, отдельный от Course Page: её правка — отдельная атомарная публикация Task с проверкой версии (D), без Course Editing Lease и без изменения Course Draft Snapshot.
  - Создание и удаление Task, а вместе с ними появление и исчезновение Task Groups, публикуются вместе с Course Draft Snapshot.
  - Если backend оставит Task подтипом блока, правки пойдут через Course Draft Snapshot (A).

  Поведение [«Ezhkin-Kot/fixes»](https://github.com/dsc-sgu/mm-backend/pull/172) — решение backend-команды, оспоренное в mm-129, а не довод.
- **Расписание** (Deadline, Deadline Overrides, Task Opening Time) опубликованной Task применяется отдельно, вне публикации.
- **Расписание новой Task** до публикации — часть Course Draft Snapshot вместе с её свойствами: самой Task ещё нет, применять его отдельно не к чему. После публикации у него тот же отдельный lifecycle.
- **mm-181** сравнивает A и D переключателем `?taskApply=course|task` на семи сценариях, включая правку из режима просмотра. `?taskApply=contract` показывает поведение по контракту mm-129: D для опубликованных Tasks, а новые Tasks — в черновике. Так прототип станет доводом для mm-129.

### Task Reference и создание Task

- У каждой Task ровно одна Task Reference. Task без неё не бывает.
- Task создаётся только вставкой Task Reference в редакторе Course Page (slash-меню или панель вставки). Сразу после этого открывается панель новой Task.
- **До открытия** удаление Task Reference удаляет Task:
  - подтверждение называет Task;
  - удаление вступает в силу при публикации, а Ctrl+Z до неё возвращает ту же Task.
- **После открытия** Task Reference можно только перемещать.
- **Копию Task Reference вставить нельзя;** «вырезать и вставить» — это перемещение.

### Ключи

- **Два поля:** у Task — название и Task Key, у Task Group — название и Task Group Key. В wire-контракте просим `title` + `key`.
- **Ключ меняется только пока Course `draft`.**
  - Это ограничение объёма MVP, а не инвариант: потом можно разрешить смену, оставив старый ключ синонимом.
  - Инвариант: ключ, который могли использовать Students, никогда не начинает означать другую Task.
  - Identity Task и Task Group на ключе не держится.
- **Формат:** `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`.
  - Регистр не различается, ключ хранится в нижнем регистре.
  - Task Key уникален в Task Group, Task Group Key — в Course.
  - Пока Teacher не ввёл ключ, предлагается транслит названия.

### Свойства Task в MVP

| Свойство | Обязательно | По умолчанию | После открытия Course |
|---|---|---|---|
| Название | да | — | меняется |
| Условие | нет (при открытии — предупреждение, mm-188) | — | меняется |
| Вложения, аннотация Task Summary | нет | — | меняются |
| Task Key | да | транслит названия | заморожен |
| Task Group и место в ней | да | см. Task Groups | заморожены |
| Максимальная Grade | да | нет: Teacher вводит сам | заморожена |
| Маски путей | нет: пусто — любые файлы | — | меняются |
| Task Opening Time | нет: пусто — время не сдерживает | — | меняется |
| Deadline уровня Task | нет | без срока | меняется (mm-42) |

**После открытия Course:**
- Task не создаются и не удаляются.
- Новая маска действует на следующие сдачи. Уже отправленные Attempts показываются по прежним маскам.
- Если перенести Task Opening Time на более позднее время, у Students, которым Task уже открыта, доступ не пропадает. Панель предупреждает: «уже открыта N Students».

**Вне MVP:**
- максимум Attempts;
- варианты (mm-124);
- командные Task (mm-185);
- cut-off (mm-177);
- штраф за опоздание;
- пресеты: их заменяет «Создать ещё»;
- зависимости вне порядка группы (mm-110);
- доступность для отдельных Student Groups (mm-186).

### Task Groups

- **Существует только вместе со своими Task.**
  - Создаётся в поле Task Group панели вместе с первой Task.
  - Исчезает, когда из неё ушла последняя Task. Это происходит при публикации; если у группы есть шаблон, перед этим предупреждение.
- **Управление — в разделе группы под полем Task Group в панели:**
  - название;
  - Task Group Key;
  - адрес шаблона и его состояние;
  - список Task группы, порядок меняется перетаскиванием.

  Нужен ли отдельный обзор всех групп, решает mm-190.
- **Новая Task по умолчанию** попадает в свою новую группу, а «Создать ещё» переносит группу предыдущей Task. Это предварительно, окончательно решает mm-190.
- **Перенос в другую группу** — только в `draft`:
  - Task встаёт в конец новой группы;
  - если её Task Key уже занят, у поля ошибка с предложением свободного ключа.
- **Порядок явный:** новая Task встаёт в конец группы, переставлять можно только в `draft`. Сортировка по `name` в mm-172 — расхождение (mm-113).
- **Шаблонный репозиторий:**
  - один на группу, наполняется через git push;
  - загрузки архива в MVP нет. В mm-172 есть только ZIP: требование push записано в mm-113. Если backend откажется, вернёмся к архиву, но тогда загрузка должна заменять шаблон целиком;
  - пустой шаблон допустим;
  - после открытия Course шаблон не меняется.
- **После открытия у группы меняется только название.**

### Время открытия

- Тот же контрол, что у дедлайна (mm-42): ввод с клавиатуры, часовой пояс браузера с подписью.
- Время по умолчанию 00:00. Пустое значение — Task открыта сразу.
- Если время открытия позже Deadline или чьего-то Effective Deadline, это предупреждение, а не запрет.

### «Создать ещё»

- **Переносит,** оставляя видимым и редактируемым: Task Group, максимальную Grade, Deadline уровня Task, Task Opening Time.
- **Не переносит:**
  - переопределения сроков;
  - маски: к ним вернётся mm-191, маска с подстановкой Task Key переносится безопасно.
- **Очищает:** название, условие, вложения, аннотацию. Task Key предлагается заново.

### Где что настраивается

| Что | Панель Task | Экран сроков (mm-181) | Обзор Task Groups |

Панель одна и та же: из просмотра Course, из режима редактирования и со страницы Task.
