# ACC4: Реагировать на отказ в доступе от любого чтения по стабильным идентичностям

Часть эпика mm-167. Перед началом прочитать [`docs/agents/remote-data.md`](https://github.com/dsc-sgu/mm-frontend/blob/main/docs/agents/remote-data.md) (обязательно по `AGENTS.md`).

## Проблема

Отказ в доступе к ресурсу участника курса сейчас обрабатывается только при разрешении локатора в `beforeLoad` (попытка, репозиторий). Права проверяются при каждом запросе, поэтому отказ может прийти от любого последующего чтения по `CourseId`/`AttemptId`/`UserId`: при первой загрузке, при фоновой перезагрузке, при фокусе вкладки. Без общей реакции такая страница показывает техническую ошибку вместо `404` или оставляет на экране содержимое, к которому доступа уже нет. Это противоречит эпику: подтверждённая потеря участия в курсе сразу заменяет содержимое на `404` курса.

Сейчас дыра закрыта только на странице попытки ([PR #239](https://github.com/dsc-sgu/mm-frontend/pull/239)): там это первые HTTP-чтения по стабильным идентичностям. Остальные чтения после локатора (страница курса, задание, список попыток курса, содержимое репозитория) ещё идут в RAM-моки и получат ту же дыру при переводе на HTTP.

## Что уже есть (из PR #239)

- `access/api/resource-denial.ts`: `ResourceDenial` (`forbidden` | `not-found`) — объявленный исход чтения; `readResourceDenial(context)` классифицирует `403`/`404` без тела.
- `access/ui/route-state.tsx`: `CourseResourceDenied` — показывает `404` ресурса внутри оболочки курса и на `forbidden` вызывает `recheckCourseContextAfterAccessDenial`, чтобы маршрут курса закрылся при потере участия в курсе или смене роли.
- Страница попытки подключает это вручную: отказ любого из четырёх чтений заменяет страницу, в том числе после фоновой перезагрузки.

## Делает

- Реакция на `ResourceDenial` подключается централизованно на уровне оболочки курса, а не вручную на каждой странице. Способ — на выбор реализации (граница в маршруте курса, общий хук над результатами запросов под `courseKeys.byId`, …), но с сохранением правил `remote-data.md`: отказ — объявленный исход в разрешённых данных, а не ошибка TanStack Query.
- Страница попытки переходит на общий механизм.
- Правило в `docs/agents/remote-data.md`: каждое чтение ресурса участника курса по стабильным идентичностям объявляет `ResourceDenial`; новая страница получает реакцию без ручного подключения.
- Курсовые чтения по `CourseId` (страница курса, задание, список попыток курса, содержимое репозитория) подключаются при своём переводе на HTTP. Тикеты этих переводов (ATT1 и др.) блокируются этим тикетом.

## Контракты

| Слой | Сценарий | Ожидание |
|---|---|---|
| Component | Чтение отвечает `403` после того, как локатор ответил `found`, и участие в курсе потеряно | `404` курса с «К моим курсам», защищённого содержимого нет |
| Component | Чтение отвечает `404` при живом участии в курсе | `404` ресурса внутри оболочки курса |
| Component | Фоновая перезагрузка уже открытой страницы получает отказ | содержимое и несохранённые правки исчезают |
| Boundary | `403`/`404` без тела | объявленный исход; `401`/`5xx` — отказ операции |

## Готово, когда

- `bun run lint` и `bun run build` проходят, контракты выше зелёные.
- Ни одна страница не подключает реакцию на отказ вручную.
- Правило записано в `remote-data.md`.

Сделано в ветке `mm-218-wave0.5`, коммит `feat(access): react to a denied read from the Course shell (mm-243)`, поверх mm-266.

Маршрут курса через `access/hooks/use-resource-denial.ts` замечает отказ в любом чтении под `courseKeys.byId(courseId)`, которое наблюдает смонтированная страница: первая загрузка, фоновая перезагрузка, возврат фокуса. Страница вместе с несохранёнными правками заменяется на `404` ресурса, курс перепроверяется, подтверждённая потеря участия закрывает курс. Ручная проводка на странице попытки и `CourseResourceDenied` удалены. Правило — в `docs/agents/remote-data.md`, раздел «Отказ в доступе к ресурсу участника».

Что проверить по «Готово, когда»:
- контракты в `access/resource-denial-routes.test.tsx` (пробная страница без своей обработки отказа): `404` при живом участии — «На страницу курса»; отказ после `found` с потерей участия — «К моим курсам»; отказ при фоновой перезагрузке убирает содержимое и черновик; повторный заход читает страницу заново; отказ локатора в кэше не закрывает следующую страницу;
