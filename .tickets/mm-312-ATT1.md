# ATT1: Загружать полный список попыток курса через общую операцию API

## Цель

LoadCourseAttemptsInput использует CourseId и нормализованные фильтры по TaskId/UserId/status. Атомарно валидировать полный список, каталоги заданий и студентов всего курса, totalAttemptsCount. Сортировка submittedAt DESC, AttemptId для равного времени; одна строка — одна неизменяемая попытка, включая историю. Ключи под [course, courseId, …]. Мок использует канонические попытки и проверки.

## Удаляет или заменяет

RAM-агрегаты списка и идентификацию по slug/username; данные diff и рабочую копию проверки в строках.

## Принятое решение и границы

Владелец подтвердил frontend-first подход: существующий API-слой бэкенда заменяется контрактами, определёнными потребностями фронтенда. Модель черновиков блоков, публикации со слиянием и чекпоинтов согласована. Ожидание старого API не блокирует этап. HTTP-формы и исходы операции закрепляются в схемах, MSW и тестах; вопросы о реализации и оставшиеся ограничения фиксируются в mm-113.

Перед реализацией прочитать `docs/agents/remote-data.md`, актуальный `CONTEXT.md` и связанные ADR. Устаревшие положения ADR 0002 и ADR 0004 о брони редактирования курса заменяются решением mm-286; бронь проверки сохраняется. Изменения доменной документации учитывает mm-286.

Новая архитектура не требует переименования каталогов из mm-292 заранее: использовать текущие пути с теми же владельцами поведения. Не выделять отдельное «чистое ядро». Этап выполняется заменой за один шаг без второго временного пути данных.

## Проверяемое поведение

- `ATT-01`: `normalizeFilters`: порядок и дубликаты id не меняют ключ; статус `any | submitted | graded`.
- `ATT-02`: `loadCourseAttempts` атомарна: один невалидный элемент отклоняет всю операцию; частичного списка нет.
- `ATT-03`: Операция и ключи используют `CourseId`, `TaskId`, `UserId`; slug и username в идентификацию не входят.
- `ATT-04`: UI сохраняет порядок операции (`submittedAt DESC` + `AttemptId`) и не пересортировывает; одна строка — одна попытка, исторические включены.

Без пагинации и ручного пересортировывания UI. Пользователь в DTO — части ФИО и стабильный id по mm-269. Не переносить в этап всю переработку раскладки ATT4.

### 2026-10-31T19:20:01Z · t3m8ch

Реализовано в ветке `mm-312-course-attempts`, коммиты `ca2345d`, `3a0a0f4`.

Список читает `GET /api/v1/courses/:courseId/attempts` через общую HTTP-операцию с атомарной валидацией. Фильтры передаются параметрами `tasks`, `students`, `status` (`any`, `submitted`, `graded`), ключ нормализован по стабильным id. Ответ включает историю попыток, полные каталоги курса и `totalAttemptsCount` до фильтрации; порядок — время отправки по убыванию, затем AttemptId по возрастанию. Мок читает канонические попытки и опубликованные проверки. Удалены RAM-агрегат и статистика diff из строк. Добавлены предзагрузка, явный первый отказ чтения и повтор загрузки.

Проверено: 16 тестов операции/оценок и контракт предзагрузки маршрута; ESLint изменённых файлов. Ревью стандартов и требований выполнено двумя агентами, замечания исправлены. Полные lint/build/test и браузерная проверка запущены, но процессы завершились SIGTERM в окружении; при ограничении памяти tsc сообщает нехватку памяти.
