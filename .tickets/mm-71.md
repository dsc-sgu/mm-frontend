`knip` нашёл три импортируемых, но не объявленных пакета:

### Конкурирующие библиотеки и проектные стандарты

#### Валидация: Valibot, не Zod

Valibot уже образует сквозной контракт: schema types, runtime parsing ответа session, route-parameter guards, page-edit validation и React Hook Form resolvers. Zod не используется. Стандарт: новые frontend-схемы пишутся на Valibot; исключение возможно только по отдельному архитектурному решению, а не локально в feature.

#### Radix packaging: один `radix-ui`

Сейчас одновременно используются aggregate package `radix-ui` (7 wrappers, один из них — недостижимый `form.tsx`) и три отдельных package: `@radix-ui/react-avatar`, `@radix-ui/react-dropdown-menu`, `@radix-ui/react-slot` (по одному live wrapper на каждый). Это одна библиотека в двух packaging-конвенциях, а не разные UI frameworks.

Стандарт: генерировать/обновлять shadcn components только CLI и использовать его текущую aggregate-конвенцию `radix-ui`. В будущем cutover мигрировать `avatar.tsx`, `dropdown-menu.tsx`, `button.tsx`, затем удалить три отдельных зависимости. Риск низко-средний: API локализован wrapper-файлами, но нужны build и визуальные smoke checks меню, avatar fallback и `asChild` у Button.

#### Rich text: не унифицировать Plate и TipTap

Фреймворки обслуживают разные persisted contracts:

- Plate: 9 прямых packages, 36 импортов в 15 файлах (примерно 4 810 строк файлов поверхности). Это структурированный редактор страницы курса: `CourseContentBlockItem[]`, собственная сериализация/десериализация, ranked blocks, nested lists, custom course nodes, block selection, slash menu и top-level DnD.
- TipTap: 5 packages, 6 импортов в 2 framework-facing файлах (примерно 322 строки). Компонент переиспользуется для итогового отзыва, line comments и replies; persisted contract — sanitized HTML.

Замена одного другим сейчас смешала бы два разных формата хранения и заставила бы мигрировать либо course block schema, либо сохранённый HTML, плюс keyboard/focus/selection behavior. Сокращение числа packages этого риска не окупает.

Стандарт:

- Plate — только для структурированного course-page content;
- TipTap — для компактного HTML prose в review/comments;
- новые editor use cases выбирают framework по persisted content model, а не по желанию иметь одну библиотеку;
- общий seam должен задавать формат, sanitization и behavioral contract, но не делать фиктивный универсальный editor API.

До characterization/specification критичных editor behaviors межфреймворковую замену не начинать.

### Остальные кандидаты

- `immutable` реально используется в трёх hooks для persistent Set/Map selection и grading state. Это не unused dependency и не конкурент Zustand/TanStack Query: области состояния разные. Возможную замену на native Set/Map оценивать только внутри рефакторинга attempts; сейчас не приоритет.
- `axios` реально используется только auth client; `fetch`-клиента в source нет. Это не текущая конкуренция, но одиночный transport без общего mock/real seam. Выбор Axios против Fetch, DTO validation и cache invalidation нужно вынести в отдельное решение.
- `clsx` и `tailwind-merge` совместно реализуют `cn()` и дополняют друг друга.
- `eslint-config-prettier` объявлен, но не подключён в `eslint.config.js`; сейчас он лишь optional peer для `eslint-plugin-prettier`. Это configuration debt, не runtime dependency. При текущем решении проверять Prettier через ESLint минимальный безопасный шаг — подключить flat config последним; если lint и format позже разделяются, удалить `eslint-plugin-prettier` и `eslint-config-prettier` парой.
- `knip` отдельно нашёл три недостижимых source-файла (`attempts/model/grading.ts`, `attempts/ui/score-field.tsx`, `shadcn/components/ui/form.tsx`). Их удаление — source cleanup вне границы этого тикета; уникальных production dependencies они не удерживают.

### Вход для [«Ранжировать зоны рефакторинга по риску и отдаче»](https://github.com/dsc-sgu/mm-frontend/issues/67)

1. **Dependency hygiene до модульного рефакторинга**: удалить `zod`/`next-themes`, исправить три unlisted imports, нормализовать Radix packaging и решить Prettier config. Высокая locality и отдача, низкий регрессионный риск; это подготовительный cutover, не отдельная продуктовая зона.
2. **Course page editor**: самая широкая и глубоко связанная dependency surface. Высокая сложность и регрессионный риск; рефакторить только после behavioral contracts. Не ставить «единый rich-text framework» целью.
3. **Transport/API seam**: Axios локален, остальные feature APIs пока mock-only; средняя cross-feature отдача, но решение зависит от доменных контрактов, DTO validation и cache policy.
4. **Attempt selection/grading collections**: `immutable` локализован; потенциальное упрощение есть, но отдача ниже editor/API seams. Рассматривать вместе с state redesign, не отдельной dependency-чисткой.
5. **TipTap review-text editor**: малая framework-facing поверхность и ясный HTML seam. Оставить как есть, пока конкретная спецификация review behavior не выявит дефект.

_Термины обновлены в [«Спроектировать Review → Grade → Student result vertical»](https://github.com/dsc-sgu/mm-frontend/issues/116): workbench → Course Attempts, Review workspace → Review editor / Attempt page, review editor (rich-text) → review-text editor._

## Решение владельца: унифицировать редакторы на Plate

Предыдущее предложение сохранять Plate и TipTap параллельно отменяется. Frontend ещё не находится в production, поэтому стоимость обратной совместимости и миграции существующих пользовательских данных не является ограничением.

Проектный стандарт:

- Plate — единственный rich-text editor framework;
- `attempt-review` переводится с TipTap на отдельный минимальный Plate profile для overall feedback, line comments и replies;
- после полного cutover удаляются `@tiptap/react`, `@tiptap/starter-kit`, `@tiptap/extension-image`, `@tiptap/extension-link`, `@tiptap/extension-placeholder`;
- общий framework не означает общий plugin set или фиктивный универсальный editor component: course-page и review сохраняют разные behavior profiles;
- до реализации нужно отдельно выбрать persisted contract review-текста: сохранить HTML на API boundary с Plate serialization/deserialization либо перевести review data model на структурированное представление. Отсутствие production снимает migration-risk, но не решает этот контракт автоматически.

Риск теперь принимается осознанно: основные проверки cutover — HTML/content round-trip, sanitization, links/images/lists, readonly rendering, autofocus, blur semantics и submit/cancel keyboard shortcuts. Реализация остаётся вне planning-only границы текущей wayfinder-карты.

## Уточнение: оставить `tailwind-merge`, удалить `clsx`

Предыдущее утверждение, что обе зависимости необходимы, скорректировано после проверки фактического API.

`tailwind-merge@3.4.0` уже принимает strings, falsy values и вложенные arrays через собственный `twJoin`; его реализация прямо основана на `clsx`. Отличие: она не поддерживает object-map syntax вида `{ active: condition }`.

AST-проверка всех 287 вызовов `cn()` в `src` не нашла ни одного object argument. Текущие callers используют строки, arrays/falsy conditional values и `className`, то есть полностью покрываются `tailwind-merge`.

Решение для будущего dependency cleanup:

```ts
import { twMerge, type ClassNameValue } from 'tailwind-merge';

export function cn(...inputs: ClassNameValue[]) {
  return twMerge(...inputs);
}
```

После clean cutover удалить `clsx`. Не расширять `cn()` object-map API без отдельной реальной потребности. Это сохраняет разрешение конфликтов Tailwind (`px-2 px-4` → `px-4`) и убирает лишний промежуточный `clsx` pass.

## Решение владельца: `prettierRecommended`

Для интеграции Prettier с ESLint выбран официальный flat preset:

```ts
import prettierRecommended from 'eslint-plugin-prettier/recommended';

export default defineConfig([
  // project configs
  prettierRecommended,
]);
```

Preset должен находиться последним в config array. При clean cutover он заменяет ручной import/registration `eslint-plugin-prettier` и ручное правило `prettier/prettier`.

Dependency policy:

- оставить `eslint-plugin-prettier`;
- оставить `eslint-config-prettier`, поскольку preset действительно использует его для отключения конфликтующих ESLint rules;
- оставить `prettier` и `prettier-plugin-tailwindcss` с текущей `.prettierrc`;
- после cutover `eslint-config-prettier` больше не считается неиспользуемой dependency.

Ожидаемый контракт: `bun run lint` продолжает проверять форматирование как ESLint errors, а `bun run format` остаётся явной исправляющей командой.
