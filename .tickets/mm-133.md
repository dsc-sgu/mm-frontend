# Преобразовывать вставленный Markdown в редакторе страницы курса

## Контекст

Редактор страницы курса преобразует Markdown только при наборе: правила ввода (input rules) Plate превращают `#`, `>`, `- `, `1. `, три обратных апострофа, `**`, `*`, `` ` `` и `[t](url)` в блоки и форматирование текста (marks). Вставленный `text/plain` с Markdown-разметкой остаётся обычным текстом; ссылкой становится только вставленный URL. При проектировании mm-120 (матрица тестовых контрактов критических вертикалей, Q15) решено вставку Markdown пока не тестировать и не менять, а преобразование вынести сюда как новую функцию.

## Делает

Преобразует Markdown из буфера обмена в блоки и форматирование профиля страницы курса через ту же границу доверия, что и вставку HTML по mm-109 (формат хранения текста проверки при переходе на Plate) и mm-119 (шов структурированного документа страницы курса): разобранный Markdown проходит конвертер и нормализатор, у неподдерживаемого сохраняется текст.

## Готово, когда

- [ ] Markdown из `text/plain` превращается только в узлы профиля страницы курса; у неподдерживаемого (таблицы, картинки, сноски) сохраняется текст.
- [ ] Сырой HTML внутри Markdown не исполняется и не становится разметкой; ссылки проходят те же правила схем, что ввод и вставка HTML.
- [ ] Нумерация списков согласована с mm-74 (контракт нумерации списков редактора), включая список, который начинается не с `1.`.
- [ ] Обычный текст и фрагменты вроде `a * b * c` или `snake_case` не превращаются в форматирование.
- [ ] Определено, что брать, когда в буфере есть и `text/html`, и `text/plain` (например, VS Code кладёт оба).
- [ ] Внутри блока кода вставка остаётся буквальной; есть способ вставить Markdown буквально и вне блока кода.
- [ ] Парсер Markdown прошёл аудит по решению mm-71 (аудит зависимостей и конкурирующих библиотек).
- [ ] Есть тесты вставки в настоящем браузере: Chromium, Firefox и WebKit.

## Зависит от

- Этапа 3 «Профиль без потерь» из mm-119 (граница доверия при вставке).
