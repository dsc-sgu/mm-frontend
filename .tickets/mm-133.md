# Преобразовывать вставленный Markdown в редакторе Course Page

## Контекст

Редактор Course Page преобразует Markdown только при наборе: input rules Plate превращают `#`, `>`, `- `, `1. `, три backtick, `**`, `*`, `` ` `` и `[t](url)` в блоки и marks. Вставленный text/plain с Markdown-разметкой остаётся обычным текстом; ссылкой становится только вставленный URL. При проектировании mm-120 «Спроектировать матрицу тестовых контрактов критических вертикалей» (Q15) решено вставку Markdown пока не тестировать и не менять, а преобразование вынести сюда как новую функцию.

## What to build

Преобразовывать Markdown из буфера обмена в блоки и marks профиля Course Page через ту же trust seam, что и paste HTML по mm-109 «Выбрать persisted contract review-текста при переходе на Plate» и mm-119 «Спроектировать structured-document seam Course Page»: разобранный Markdown проходит converter и normalizer, неподдерживаемое сохраняет текст.

## Acceptance criteria

- [ ] Markdown из text/plain превращается только в узлы профиля Course Page; неподдерживаемое (таблицы, картинки, footnotes) сохраняет текст.
- [ ] Сырой HTML внутри Markdown не исполняется и не становится разметкой; ссылки проходят те же правила схем, что ввод и paste HTML.
- [ ] Нумерация списков согласована с mm-74 «Зафиксировать контракт нумерации списков редактора», включая список, который начинается не с `1.`.
- [ ] Обычный текст и фрагменты вроде `a * b * c` или `snake_case` не превращаются в форматирование.
- [ ] Определён источник, когда в буфере есть и text/html, и text/plain (например, VS Code кладёт оба).
- [ ] Внутри code block вставка остаётся буквальной; есть способ вставить Markdown буквально и вне code block.
- [ ] Markdown parser проходит аудит по решению mm-71 «Провести аудит зависимостей и конкурирующих библиотек».
- [ ] Real-browser тесты paste в Chromium, Firefox и WebKit.
