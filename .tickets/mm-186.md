# Доступность заданий для отдельных подгрупп

## Источники

- mm-180 (проектирование настройки заданий и цепочек заданий), Q8: вынесено в бэклог.
- Страница AnyType «Обсуждение MergeMinds 03.02.2026»: «задание может быть доступно для одной подгруппы, но недоступно для другой».

## Проблема

Время открытия у задания одно на всех (`available_at`), поэтому задание открывается всем студентам курса одновременно. Подгруппе с лабораторной в четверг может понадобиться получить задание позже, чем подгруппе со вторника. А какой-то подгруппе задание, возможно, вообще не нужно.

## Почему не сейчас

- Подгруппам с занятиями в разные дни уже помогают групповые переопределения дедлайнов (mm-42).
- Ещё одно измерение в матрице экрана сроков утяжелит прототип mm-181.
- Сценарий подтверждён только заметкой перед встречей 03.02.

## Что решить

- Что именно нужно:
  - своё время открытия для подгруппы;
  - исключение подгруппы из задания целиком.
- Модель держать совместимой с формой переопределения дедлайна: значение для подгруппы заменяет значение задания, «не задано» означает наследование. Нужен ли уровень отдельного студента?
- Как это сочетается:
  - с доступом студента к заданию: однажды открытое задание не закрывается;
  - с порядком заданий в цепочке;
  - с критерием открытия следующего задания (mm-110).
- Что видит студент, которому задание ещё не открыто, и подгруппа, исключённая из задания.
- Вопрос к бэкенду добавить в реестр вопросов фронтенда к API бэкенда mm-113.

## Связи

- mm-42 — та же форма переопределений для дедлайнов.
- mm-176 — подгруппы.
