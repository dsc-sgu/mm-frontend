# Доступность Task для отдельных Student Groups

## Source

- mm-180 «Спроектировать настройку Task и Task Groups», Q8: вынесено в backlog.
- Страница AnyType «Обсуждение MergeMinds 03.02.2026»: «задание может быть доступно для одной подгруппы, но недоступно для другой».

## Проблема

Время открытия у Task одно на всех (`available_at`), поэтому Task открывается всем Students Course одновременно. Подгруппе с лабораторной в четверг может понадобиться получить Task позже, чем подгруппе со вторника. А некоторой Student Group Task, возможно, вообще не нужна.

## Почему не сейчас

- Подгруппам с занятиями в разные дни уже помогают групповые Deadline Overrides (mm-42).
- Ещё одно измерение в матрице экрана сроков утяжелит прототип mm-181.
- Сценарий подтверждён только заметкой перед встречей 03.02.

## Что решить

- Что именно нужно:
  - своё время открытия для Student Group;
  - исключение Student Group из Task целиком.
- Модель держать совместимой с формой Deadline Override: значение для Student Group заменяет значение Task, «не задано» означает наследование. Нужен ли уровень отдельного Student?
- Как это сочетается:
  - со Student Task Access: однажды открытая Task не закрывается;
  - с порядком Task в Task Group;
  - с критерием открытия следующей Task (mm-110).
- Что видит Student, которому Task ещё не открыта, и Student Group, исключённая из Task.
- Вопрос к backend добавить в mm-113 «Реестр frontend-вопросов к backend API».
