# Перевести student task и attempt history flow на общий mock backend

## Parent

mm-73 «Перевести frontend с RAM-моков на fetch и MSW»

## What to build

Перевести student task flow на общий mock backend: студент открывает задание, видит собственную детерминированную историю попыток и отмечает обновления попытки просмотренными через HTTP mutation. Tasks и attempts должны стать общими каноническими сущностями, пригодными для последующих teacher и review slices.

## Acceptance criteria

- [ ] Task page и student attempt history загружаются через fetch и MSW.
- [ ] Backend строит task representation из канонических task, membership и attempt данных.
- [ ] Студент видит только историю, относящуюся к его identity и текущему курсу.
- [ ] Mutation «обновления просмотрены» изменяет backend state и сохраняется после refetch.
- [ ] Повторное чтение не генерирует новые случайные attempts или attention states.
- [ ] Task feature больше не импортирует собственный stateful RAM-мок.
- [ ] Lint и build проходят.
