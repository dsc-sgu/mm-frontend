# Единые имена схем DTO и типов исходов операций API

## Зачем

Суффикс `Dto` у схем в `api/` ставится непоследовательно, и никакое правило его не определяет. `CoursesDtoSchema` получил суффикс, хотя фронтенд отдаёт его выход как `CourseSummary[]` без маппинга. А `ReviewResultSchema`, `FoundCourseSchema` и `AttemptSummarySchema` суффикса не получили. По имени нельзя понять, описывает схема контракт API или доменное значение: `ReviewRevisionSchema` из `model/` вложена в `ReviewResultSchema` из `api/`, и имена у них устроены одинаково.

Типы объявленных исходов операций названы тоже по-разному: восемь `Load…Result` и два `…Outcome` в auth.

## Решение

1. **Каждая схема Valibot в `src/features/**/api/` называется `…DtoSchema`.** По `docs/agents/remote-data.md` всё, что проверяется на границе API, — это DTO («внешний payload → runtime validation → DTO → domain model»). Суффикс называет роль схемы, а не то, совпадает ли её форма с доменной моделью прямо сейчас. Сейчас многие формы совпадают только потому, что контракт API придуман на фронтенде (mm-113). Когда бэкенд пришлёт свою форму, появится маппинг, а имя схемы останется прежним.
   Доменные схемы в `model/` (`CourseIdSchema`, `GradeSchema`, `ReviewRevisionSchema`…) суффикса не получают.
   Правило касается и фрагментов DTO (`AuthorSchema`, `SideSchema`, `CountSchema`), и схем тел запросов в MSW-обработчиках внутри `api/`.
2. **Тип объявленного исхода операции называется `<Операция>Result`**, где `<Операция>` — имя функции операции в PascalCase: `loadReview` → `LoadReviewResult`. Так уже названо большинство типов, поэтому переименовывать нужно только два.

## Не входит

- `src/app/mock-backend/test-control.ts`: это тестовый канал, а не контракт API.
- Типы результатов в `model/`, которые не являются исходами удалённых операций: `ReviewResult`, `GradeInputResult`, `HighlightCodeResult`, `CourseAttemptsListResult`, `CourseAccessOutcome`.
- Изменение формы контракта API или имён вариантов `status`.

## Готово, когда

- [ ] Все схемы из таблицы переименованы. Других схем без суффикса `Dto` в `src/features/**/api/` нет: проверить и файлы, которые появились после этого тикета.
- [ ] `SessionOutcome` и `LoginOutcome` переименованы.
- [ ] В раздел «Valibot schemas» в `AGENTS.md` добавлено правило именования: `…DtoSchema` в `api/`, без суффикса в `model/`, `<Операция>Result` для типа объявленного исхода. Рядом с правилом 8 в `docs/agents/remote-data.md` добавлена ссылка на это правило.
- [ ] ESLint `@typescript-eslint/naming-convention` для `src/features/**/api/**/*.ts` (кроме `*.test.ts`) требует суффикс `DtoSchema` у переменных, имя которых оканчивается на `Schema`.
- [ ] `bun run lint`, `bun run build` и тесты проходят.
