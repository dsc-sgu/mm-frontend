# Epic: Основа — CI, зависимости, транспортное ядро и тестовые слои

Epic группы «Основа» из решения [«Определить последовательность подготовки и выполнения рефакторинга»](https://github.com/dsc-sgu/mm-frontend/issues/69#issuecomment-6108811160). Slices — sub-issues этого epic, порядок задают нативные блокировки.

### Результат

После Основы:

- каждый PR проверяют lint, build, Vitest и Playwright в Chromium, Firefox и WebKit;
- в manifest нет неиспользуемых и необъявленных зависимостей, Radix подключён одним пакетом, Prettier — через `prettierRecommended`;
- HTTP идёт через одно транспортное ядро на Fetch, auth — его первый потребитель; MSW работает в dev по флагу и в Node;
- ESLint запрещает Axios, прямой `fetch` и импорт моков, кроме явного списка исключений;
- клавиши определяет один keyboard module;
- текущий редактор Course Page защищён characterization DOC-14 и DOC-18, Plate обновлён под этой защитой;
- TanStack Query и Router обновлены.

### Правила slices

Из [#69](https://github.com/dsc-sgu/mm-frontend/issues/69#issuecomment-6108811160):

- **Один slice — один PR**, clean cutover.
- **Контракты матрицы**, чей слой-владелец появляется в slice, пишутся в том же PR.
- **Slice готов**, когда проходят lint и build, а все его контракты зелёные в Chromium, Firefox и WebKit. Slice без контрактов матрицы проверяется lint, build и уже существующими тестами.
- **Слой тестов появляется с первым настоящим потребителем.** PR «только инфраструктура» не бывает. PR, который вводит слой, сразу добавляет его job в CI.
- **Обновление версий** ставится прямо перед slice, чей код оно задевает. TipTap, Axios и Immutable не обновляются: их удаляют.

Контракты slice — фильтр по slice в [матрице тестовых контрактов](https://github.com/dsc-sgu/mm-frontend/blob/ddda126c5e73ec787362805c286ee081ee26244d/docs/prototypes/test-contract-matrix.html) (ветка `prototype/test-contract-matrix`, commit `ddda126`). В Основе они есть только у K (TR-01…TR-07) и CH (DOC-14, DOC-18).
