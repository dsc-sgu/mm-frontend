# DRF3: Синхронизировать рабочую копию по блокам в фоне

## Цель

Планировщик 1 с после изменения / максимум 5 с и немедленно перед публикацией или уходом. В полёте один пакет, base — последний подтверждённый ответ, операции несут version. После первого move опубликованного блока перечитать новую версию черновика. При неизвестном исходе перечитать и построить план заново; ограниченный повтор, явное «Повторить», индикатор синхронизации. Перезагрузка восстанавливает подтверждённые сервером черновики.

## Удаляет или заменяет

Синхронизацию только перед публикацией и повтор пакета вслепую при неизвестном исходе.

## Принятое решение и границы

Владелец подтвердил frontend-first подход: существующий API-слой бэкенда заменяется контрактами, определёнными потребностями фронтенда. Модель черновиков блоков, публикации со слиянием и чекпоинтов согласована. Ожидание старого API не блокирует этап. HTTP-формы и исходы операции закрепляются в схемах, MSW и тестах; вопросы о реализации и оставшиеся ограничения фиксируются в mm-113.

Перед реализацией прочитать `docs/agents/remote-data.md`, актуальный `CONTEXT.md` и связанные ADR. Устаревшие положения ADR 0002 и ADR 0004 о брони редактирования курса заменяются решением mm-286; бронь проверки сохраняется. Изменения доменной документации учитывает mm-286.

Новая архитектура не требует переименования каталогов из mm-292 заранее: использовать текущие пути с теми же владельцами поведения. Не выделять отдельное «чистое ядро». Этап выполняется заменой за один шаг без второго временного пути данных.

## Проверяемое поведение

- `DRF-14`: Планировщик: после ~1 с бездействия; не реже раза в 5 с при непрерывном наборе; сразу при уходе и публикации; в полёте один пакет; правки копятся; `base` обновляется по каждому подтверждению сервера.
- `DRF-15`: Потерянный ответ на создание блока → черновик перечитывается → новая `base` → новый план; блок не создаётся дважды.
- `DRF-16`: Ожидаемый отказ операции черновика → пакет остановлен, `sync-rejected { reason }`, рабочая копия цела, следующая правка строит новый план.
- `DRF-17`: Сопоставление локальных и серверных id: после подтверждения создания следующее изменение адресует серверный id.
- `DRF-18`: Индикатор «Сохранено» / «Сохранение…» / «Не сохранено · Повторить».
- `DRF-E2`: Сеть пропала во время правки → «Не сохранено · Повторить», локальные правки на месте; после подтверждённой синхронизации → «Сохранено»; перезагрузка восстанавливает все подтверждённые сервером черновики. Восстановление ещё не отправленных локальных правок относится к mm-123.

Версия черновика при записи по принятой модели не растёт: не обещать защиту от второго устройства или от уже отправленного запроса без отдельного контракта бэкенда.

## Готово, когда

- [ ] Реализовано описанное поведение и удалён прежний путь в затронутой зоне.
- [ ] Схемы, моки и тесты используют один контракт; отказ, отмена и неизвестный исход не изображаются успехом.
- [ ] Проходят `bun run lint`, `bun run build` и проверки уровня владельца контракта; браузерные сценарии — в Chromium, Firefox и WebKit.
- [ ] Сохранены применимые общие контракты доступности `A11Y-01` и `A11Y-02`.
