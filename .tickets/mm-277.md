# Создавать курс с панели управления

## Проблема

Преподавателю негде создать курс. На панели управления (`src/routes/_authenticated/index.tsx`) есть только «Мои курсы». Пустое состояние говорит: «Вы пока не состоите ни в одном курсе. Когда курсы появятся, они отобразятся здесь», — и не подсказывает, что делать дальше. Без курса систему нельзя начать использовать. mm-178 определяет согласованный сценарий; этот тикет реализует его.

Бэкенд создание уже умеет: `POST /courses` с полями `name`, `displayName` и необязательным `disciplineID` в `main` и в mm-backend PR #187 (`internal/courses/repo.go`, `CreateCourse`). Создатель становится владельцем и первым преподавателем курса.

## Что делает

Вертикаль: форма, операция на Fetch через `runHttpOperation`, MSW-handler в мок-бэкенде, тесты.

- На панели управления есть кнопка «Создать курс». В пустом состоянии «Мои курсы» она тоже есть, рядом с подсказкой для студента: «Чтобы вступить в курс, откройте ссылку-приглашение от преподавателя».
- Форма содержит четыре поля, выбранные в mm-178: название (`title`), короткое название (`shortTitle`), адрес (`slug`) и описание (`description`). Все четыре обязательны; текстовые поля проверяются после удаления крайних пробелов. Короткое название не генерируется автоматически. Ошибка «Адрес недоступен» показывается у поля адреса; одинаковые названия разрешены.
- После создания курс сразу появляется в «Моих курсах», и открывается его страница в режиме редактирования.
- Курс создаётся в подготовке с подгруппой «Подгруппа 1»; создатель получает роль преподавателя. Короткое название и описание сохраняются из обязательных полей формы, цвет `blue`, иконка `book-open`.

## Подтверждённые решения

Итог mm-178 подтверждён пользователем 2026-10-31; в тот же день явно уточнена обязательность короткого названия и описания; полная спецификация и проверяемые случаи находятся в разделе «Итоговая спецификация создания курса» того тикета.

- Любой вошедший пользователь; диалог из «Моих курсов», обязательные название, короткое название, адрес и описание, без дисциплины и обязательного мастера.
- Предложение адреса транслитерацией с ручной правкой, пустое поле при невозможности преобразования. Любое непустое название допустимо, включая эмодзи.
- Предварительная проверка адреса с дебаунсом; её сбой не блокирует отправку валидной формы. Конфликт проверяется и при создании.
- Ожидание до 15 секунд, затем разрешено закрытие при неизвестном исходе; поля заморожены до выяснения результата, нового создания нет.
- Безопасный повтор по кнопке с тем же ключом; поздний успех после закрытия — уведомление со ссылкой без смены страницы.
- Форма и команда только в памяти до перезагрузки, без зависимости от mm-273.
- Требования к атомарности и идемпотентности переданы в mm-113; прежний API не ограничивает дизайн.

## Зависит от

## Интеграционные предпосылки и образцы

API проектирует фронтенд; отсутствие операции в прежнем API бэкенда не блокирует этот тикет. Перед реализацией прочитать `docs/agents/remote-data.md`. Образцы ниже проверены в `origin/main` на `045ea6d`; брать свежий `origin/main`, а не старый локальный checkout. Новые операции — Fetch через `runHttpOperation`, URL через `apiPath`, DTO проверяются до кэша; MSW хранит данные в общем `mockBackend`, а не в новом RAM-хранилище.

**Открытые блокеры рефакторинга не нужны:** создание курса — новая операция, которая может использовать уже готовый транспорт и список курсов. Не ждать DOC1/DRF2, mm-259 или полного выделения оболочки: достаточный результат создания — стабильный `id` и подтверждённый `slug`, затем перечитывание списка/контекста. Не возвращать целиком старый `CoursePage` или копию `Teacher` без `id` ради перехода.

**Образцы:** `src/features/auth/api/login.ts` — операция записи с объявленными исходами; `src/features/course/api/load-courses.ts` — валидация ответа; `src/features/course/api/queries.ts` — `coursesKeys`/`courseKeys`; `src/features/course/api/mock.ts` и `src/app/mock-backend/state.ts` — общий HTTP-мок. Вход разместить на существующей панели `src/routes/_authenticated/index.tsx`. Конфликт адреса — отдельный исход новой операции, а не ошибка успеха HTTP.

**Не копировать:** `saveCoursePage` и `COURSE_PAGE_STORE` из `page/api/mock.ts`, хранение slug в поле идентичности, старые поля `userID`/`avatarURL` в новые DTO. Создание курса, участие создателя и подгруппа по умолчанию — единый согласованный результат контракта. Не добавлять автоматический повтор создания без гарантии идемпотентности. После успеха дождаться нужной инвалидации `coursesKeys` и контекста перед переходом. Решения по полям и поведению подтверждены в mm-178; дополнительных блокеров рефакторинга они не вводят.

Проверено по `origin/main` (`045ea6d`). Наличие решения в спецификации или рабочей ветке не означает, что его реализация уже доступна в `main`. Перед реализацией перечитать `docs/agents/remote-data.md` и проверить актуальность указанных путей.
