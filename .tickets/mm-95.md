# Восстанавливаться после lease loss и snapshot conflicts

## Parent

mm-78 «Перевести course dashboard и редактирование курса на общий mock backend»

## What to build

Сохранить работу и дать понятное восстановление, когда lease потерян, другой преподаватель опубликовал новую версию или optimistic publication завершилась конфликтом.

Использовать [backend research](https://github.com/dsc-sgu/mm-frontend/blob/a25a8ed9f8c485f5aaad5ba0beba4f7909a9cf63/docs/research/backend-snapshots.md).

## Acceptance criteria

- [ ] Heartbeat failure переводит editor в явное lease-loss state и останавливает опасные mutations.
- [ ] Повторный lock различает restored, stale_conflict и lock другого holder.
- [ ] Stale draft доступен для просмотра и копирования, но не публикуется как актуальный.
- [ ] 409 conflict не затирает опубликованную версию или сохранённый draft.
- [ ] Пользователь может безопасно начать новый draft после решения по stale state.
- [ ] Reconnect/retry не создаёт параллельные editing sessions.
- [ ] Lint и build проходят.

Отдельный дублирующий issue не нужен: этот issue уже владеет таким recovery flow.

## Уточнения из mm-118, комментарий от 2026-10-09T22:31:46Z «Спроектировать lifecycle Course Page Working Copy»

Дополняет уточнение MVP для `stale_conflict` выше. Покрывается slice 2 «Сессия черновика» (базовая потеря lease) и slice 4 «Полный протокол Course Editing Lease»; полноценный read-only recovery stale черновика остаётся здесь как следующий этап.

- `interrupted` наступает только при явном ответе backend, что lease не мой. Working Copy остаётся видимой только для чтения, при уходе — предупреждение.
- Повторное взятие lease: `restored` и черновик равен базе → продолжаем без потерь; `restored`, но черновик изменился (например, в другой вкладке того же Teacher'а) → явный выбор «Взять версию с сервера» или «Перезаписать черновик моей версией»; `stale_conflict` → `stale`; `423` → только чтение.
- `409` при публикации ведёт в `stale`. Автоматического merge нет.

Каноническим источником является решение по ссылке выше. Окончательную нарезку на implementation-тикеты определит mm-69 «Определить последовательность подготовки и выполнения рефакторинга».
