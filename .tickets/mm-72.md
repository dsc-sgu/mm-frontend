# Разобрать низкоуровневые browser- и scheduling-механизмы

## Question

Какие низкоуровневые browser-, scheduling- и platform-механизмы используются в реализованном frontend (например, `queueMicrotask`, ручные timers, DOM globals, worker integration и polyfills), какой пользовательский или технический контракт требует каждый из них и что из этого следует сохранить с явным обоснованием, а что — отрефакторить за более ясную seam? Аудит должен отличить необходимые platform contracts от случайных workaround и подготовить ограниченный список решений для ранжирования рисков, не выполняя сам рефакторинг.

## Решение: platform contracts и целевые seams

Аудит охватил browser globals, scheduling, Worker/WASM, polyfills и build/runtime assumptions реализованного frontend. Решение не меняет production code и не превращает каждый platform call в abstraction.

### Поддерживаемая платформа

- Реализованный frontend — **online browser-only Vite SPA** на modern Baseline Widely Available. SSR/prerender, offline/PWA, Service Worker и legacy bundle/polyfill layer не входят в контракт.
- Все уже адаптивные экраны должны полноценно работать на телефоне. **Course Page editor** пока официально desktop-only; его mobile adaptation не добавляется этим решением.
- Системный `prefers-reduced-motion` должен отключать или успокаивать необязательное движение, сохраняя читаемое состояние загрузки.
- Регрессионный контракт описывает наблюдаемый результат — focus восстановлен, нужный block/file видим, loader не мерцает — а не конкретный `queueMicrotask`, один animation frame или текущие значения задержек.

### Что сохраняем как необходимую platform integration

- Feature-local `requestAnimationFrame`, `ResizeObserver`, `MutationObserver`, media-query subscriptions и короткие UI timers, когда они владеют конкретным layout/focus/feedback contract и корректно чистятся. Общий `BrowserPlatform` или `Scheduler` module не создаём: он был бы shallow pass-through над несвязанными механизмами.
- `useMediaQuery`, DOMPurify sanitizer, TanStack Query mutation/cache ordering и library-owned overlay/virtualization lifecycles остаются своими существующими interfaces.
- Runtime source of truth темы остаётся классом на `<html>`, а pre-React bootstrap сохраняет no-flash behavior. Storage synchronization, validation и unavailable-storage policy остаются в mm-97 «Исследовать React abstraction для persistent browser preferences».
- Production contract review-lock updates — stream/subscription, а не timer. Текущий `setInterval(4500)` является только mock adapter и должен исчезнуть при реализации mm-98 «Согласовать SSE protocol для realtime-обновлений Review и lease».
- Mock API `setTimeout` не является продуктовым scheduling contract: latency/failure profiles переходят в уже согласованный MSW transport layer.

### Точечные seams для рефакторинга

1. **Diff Worker readiness**
   - Worker pool монтируется только на readonly/editable attempt-review routes, а не на всём authenticated subtree.
   - Worker + WASM являются обязательной capability для highlighted diff. Interface состояния: `loading | ready | failed`; при отказе показывается явная ошибка с retry. Main-thread/plain fallback не требуется; бесконечный loader недопустим.
   - Текущие caps `1 worker / cache 10` и `3 / 100`, а также touch/viewport heuristic не являются зафиксированным контрактом: это tuning, который следует подтвердить измерениями на поддерживаемых desktop/mobile devices.

2. **Course Page editor DOM/Plate coordination**
   - Необходим один сфокусированный module вокруг editor-scoped geometry, selector/data-attribute contract и focus handoff.
   - Document-global queries должны быть ограничены корнем конкретного editor. Keyboard drag возвращает focus, structural operations фокусируют результирующий block, mobile review сначала закрывает drawer и затем scroll-ит к file — именно эти outcomes сохраняются.
   - `queueMicrotask`, one-frame guards и private-looking `editor.meta._forceFocus` считаются upgrade-sensitive implementation/workaround, а не contract. Их надо локализовать и проверить против поддерживаемых Plate/Pierre interfaces; scheduled work получает явное lifecycle ownership.

3. **Keyboard semantics**
   - Три расходящихся `navigator.platform`/`userAgent` реализации сводятся в один focused module. Shortcut behavior выводится прежде всего из `KeyboardEvent`; platform detection используется только для пользовательских labels.

4. **Clipboard acquisition**
   - Clipboard-assisted link suggestions автоматически читаются только в Chromium-family.
   - Firefox и Safari не получают auto-read; ручной ввод и обычный paste event остаются доступны.
   - Permission/unavailable handling принадлежит этому feature-local interface; generic clipboard platform layer не нужен.

### Явные cleanups и cutovers

- Native `window.prompt` для link/image в review-text editor не сохраняется. При уже выбранном TipTap → Plate cutover его заменяет controlled dialog/popover с editor-owned validation, error и focus behavior.
- Неиспользуемый DEV `window.__TANSTACK_QUERY_CLIENT__` не является контрактом и может быть удалён.
- Неиспользуемый `next-themes` не становится вторым theme approach; его можно удалить, если отдельное storage research не выберет его осознанно.
- Слабый дублированный `Math.random` fallback для content IDs не канонизируется. Кто владеет persistent block identity — client или backend — намеренно отложено до frontend/backend Course Snapshot contract как неприоритетный вопрос; текущая карта не фиксирует backend API.

### `@pierre/diffs` и две Shiki

Причина текущего дублирования установлена:

- установленная `@pierre/diffs` 1.2.7 жёстко зависит от `shiki ^3.0.0`, поэтому lock содержит вложенную Shiki 3.23.0 рядом с app-owned Shiki 4.0.2;
- актуальная `@pierre/diffs` 1.4.2 уже допускает `shiki ^3.0.0 || ^4.0.0` и `@shikijs/transformers ^3.0.0 || ^4.0.0`.

Стратегия: сначала отдельным implementation task обновить Pierre до latest, пройти [официальную migration guide 1.4](https://github.com/pierrecomputer/pierre/releases/tag/diffs-v1.4.0), проверить package dedupe, build и реальный review flow. Patch допустим только для воспроизведённой несовместимости, оставшейся после обновления; заранее патчить 1.2.7 не нужно.

Primary evidence: [manifest 1.2.7](https://registry.npmjs.org/@pierre/diffs/1.2.7), [latest manifest](https://registry.npmjs.org/@pierre/diffs/latest), [release 1.4.2](https://github.com/pierrecomputer/pierre/releases/tag/diffs-v1.4.2).

### Ограниченный список для последующего risk ranking

Средний риск: неподтверждённые Worker resource caps, duplicated keyboard detection, clipboard UA policy, transiently poisoned Shiki Promise caches, отсутствие reduced-motion policy.

Низкий риск / оставить локально: layout RAF/observer modules с cleanup, loader/copy-feedback tuning, standard media-query/virtualization/DOMPurify integration.
