# DOC1: Ввести документ страницы курса v1 и общее отображение для чтения

## Цель

В page-document ввести собственные типы и схемы блоков v1, нормализацию, правила списков и дерево отображения. Блок задания хранит только taskId. Порядок — порядок массива, BlockId стабилен; элементы списка — отдельные блоки. Адаптер Plate переводится на v1 в том же этапе. Общие ссылки и форматирование принадлежат course; общий rich-text не импортирует дочерний документ. Содержимое спойлера — данные одного блока. Чтения HTTP остаются этапу READ.

## Удаляет или заменяет

CourseListBlock/courseListId, id у inline-узлов, rank и sortRankedContent в модели, linkType, resources.assignments в документе, caption в ресурсах, dirty-compare.ts и старый course/ui/content-block.tsx.

## Принятое решение и границы

Владелец подтвердил frontend-first подход: существующий API-слой бэкенда заменяется контрактами, определёнными потребностями фронтенда. Модель черновиков блоков, публикации со слиянием и чекпоинтов согласована. Ожидание старого API не блокирует этап. HTTP-формы и исходы операции закрепляются в схемах, MSW и тестах; вопросы о реализации и оставшиеся ограничения фиксируются в mm-113.

Перед реализацией прочитать `docs/agents/remote-data.md`, актуальный `CONTEXT.md` и связанные ADR. Устаревшие положения ADR 0002 и ADR 0004 о брони редактирования курса заменяются решением mm-286; бронь проверки сохраняется. Изменения доменной документации учитывает mm-286.

Новая архитектура не требует переименования каталогов из mm-292 заранее: использовать текущие пути с теми же владельцами поведения. Не выделять отдельное «чистое ядро». Этап выполняется заменой за один шаг без второго временного пути данных.

## Проверяемое поведение

- `DOC-02`: Канонизация идемпотентна: слияние фрагментов с одинаковыми marks, удаление пустых, marks как упорядоченное множество, перенос строки `\n`.
- `DOC-03`: Схема: неизвестный тип, неизвестная version, невалидный `data` → блок-заглушка в режиме чтения и `unsupported-content` в редакторе; молчаливых преобразований нет.
- `DOC-04`: Правила 1–7 из #74 на функции группировки: последовательность пунктов списка → дерево `ol/ul` и номера.
- `DOC-05`: Нормализация indent: отсутствующий, нечисловой, бесконечный или < 1 → 1; дробные округляются; первый пункт — уровень 1; шаг не больше +1. Одна функция для загрузки, `normalizeNode` и рендерера.
- `DOC-06`: Дерево рендера: списки внутри спойлера нумеруются независимо; спойлер в спойлере и блок задания в спойлере отклоняются схемой.
- `DOC-07`: Саммари задания: `open`, `locked { prerequisite }`, `unavailable`; у преподавателя — без состояния доступа.
- `DOC-10`: Режим чтения показывает «Блок не удалось показать» на месте невалидного блока, остальная страница видна.
- `DOC-12`: Семантический DOM режима чтения: сгруппированные `<ol>/<ul>`, соседние `<li>`, вложенный список внутри родительского `<li>`.
- `DOC-13`: Блок задания: студент видит `open`, `locked` или заглушку, содержимое закрытого задания не раскрыто; преподаватель видит блок без состояния доступа.

Невалидный блок в чтении даёт «Блок не удалось показать», остальная страница доступна; редактор отклоняет неподдерживаемый документ с unsupported-content. Характеризационные DOC-14 и DOC-18 сохраняются. fast-check подключается с первым настоящим потребителем; полный round-trip принадлежит DOC3.
