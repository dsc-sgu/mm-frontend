# Согласовать transport mapping attemptNumber и backend attempt UUID

## Parent

mm-63 «Согласовать карту реализованной frontend-системы»

## What to build

Согласовать frontend/backend identity contract попытки: пользователь и маршрут обращаются к attemptNumber, backend может хранить внутренний UUID, а transport однозначно связывает эти значения без раскрытия случайной формы незамерженной реализации.

Учитывать [Attempt, Task, Git API](https://github.com/dsc-sgu/mm-backend/pull/159), [refactor: reworked based on design doc](https://github.com/dsc-sgu/mm-backend/pull/164) и [backend research](https://github.com/dsc-sgu/mm-frontend/blob/a25a8ed9f8c485f5aaad5ba0beba4f7909a9cf63/docs/research/backend-snapshots.md).

## Acceptance criteria

- [ ] Зафиксировано, где API использует attemptNumber, а где внутренний UUID.
- [ ] Определён способ разрешить course + task + student + attemptNumber в одну backend attempt entity.
- [ ] Определено, возвращается ли UUID в DTO и нужен ли он frontend consumers.
- [ ] List, review и diff endpoints используют согласованную identity semantics.
- [ ] Решение согласовано с backend owners и записано в доступном из обоих репозиториев месте.
- [ ] MSW contract может воспроизвести решение без зависимости от незамерженного branch shape.
