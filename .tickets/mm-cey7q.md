# Спецификация: настройка задания

## Проблема

В `main` преподаватель не может создать задание. В слэш-меню редактора страницы курса нет пункта «Задание», а блок задания умеет только ссылаться на уже существующее задание (`page-edit/ui/plate/nodes.tsx`). Как настраивать задание, цепочки, сроки и маски путей, исследуют прототипы mm-181 → mm-190 → mm-191 в `prototype/sandbox`. Но после прототипов нет ни одного тикета, который превращает их вердикты в реализацию. mm-41, mm-106 и mm-107 написаны до прототипов и, по плану чистки тикетов, согласованному с владельцем, заменяются этой спецификацией.

Открытый mm-backend PR #187 (не влит и не согласован, модель — mm-34k14) предлагает модель:
- задание — блок `task` в черновике автора;
- `PATCH /tasks/{taskId}` с версией блока: правка уходит в черновик, если он есть, иначе публикуется сразу;
- цепочка создаётся с первым заданием и исчезает с последним, `PATCH /task-groups/{id}` её переименовывает;
- шаблон цепочки — ZIP (`POST /task-groups/{id}/template`).

## Что делает

Спецификация в форме эпика, по образцу mm-167 и mm-218: тело эпика — это спецификация, этапы режутся через /to-tickets.

- Сводит вердикты mm-181, mm-190 и mm-191 и отзывы mm-249, mm-250.
- Минимальный путь для первого семестра: создать задание в цепочке, задать ключ задания, название, условие, максимальную оценку, время открытия и дедлайн, опубликовать.
- Этапы по порядку:
  1. **Правка опубликованного задания из панели**: панель задания, её поля, валидация, обработчики MSW, транспорт. `PATCH /tasks` без своего черновика блока задания публикуется сразу, поэтому этап DRF2 не ждёт. Пока создавать задания нельзя, этот этап виден только на моках.
  2. **Создание задания** блоком в черновике страницы курса и публикация вместе со страницей. Ждёт DRF2.
  3. Маски путей.
  4. Шаблонный репозиторий. Ждёт `git push` в шаблон на бэкенде.
  5. Переопределения дедлайнов (mm-42). Ждут [тикет бэкенда mm-backend#190](https://github.com/dsc-sgu/mm-backend/issues/190) и подгрупп (mm-176).
  6. «Создать ещё» (mm-106).
- Вертикали: обработчики MSW по контракту mm-backend PR #187 (владелец принял его рабочим допущением мок-бэкенда, mm-34k14, «Что решить», пункт 1), плюс настоящий транспорт.
- Шаблонный репозиторий наполняется через `git push`, загрузки архива нет. Фронтенд показывает адрес шаблона и команду для push. Пока бэкенд не дал push в шаблон, это блокер для первого семестра: без него шаблоны пустые.

## Что решить

- **Граница с mm-34k14.** _Решено владельцем 2026-10-25:_
  - черновики блоков страницы курса — в эпике Course editing, нарезка в mm-34k14: DOC1, READ, DRF1–DRF5, HIST, MARK. Эпик владеет сессией черновиков: открыть (`?draft=true`), править, опубликовать, «Отменить все мои черновики», фоновая синхронизация, конфликт блока, вкладки, история публикаций;
  - всё о задании — в этой спецификации: панель задания и её поля, `PATCH /tasks` («в черновик» или сразу), цепочки заданий, маски путей, шаблонный репозиторий, сроки и переопределения дедлайнов;
  - шов — DRF2: панели нужно знать, есть ли у меня черновик блока задания. Правка опубликованного задания из панели от DRF2 не зависит и идёт первым этапом; создание задания блоком в черновике — следующий этап, он ждёт DRF2 (раздел «Что делает»).
- **Решения mm-34k14, от которых зависит спецификация,** все приняты: блок задания и данные блока (пункт 3) — в документе страницы курса у блока задания только `taskId`, настройки задания меняет панель через `PATCH /tasks`; расписание (пункт 8) — правка опубликованного задания без своего черновика его блока публикуется сразу, откат к чекпоинту возвращает сроки; MVP конфликта блока (пункт 4) — только «Отменить все мои черновики» с копированием своего текста.
- Что из mm-41, mm-106 и mm-107 переносится, а что закрывается.
- **Шаблонный репозиторий.** _Решено владельцем 2026-10-25:_ держимся mm-180, шаблон наполняется через `git push`, ZIP в MVP нет. В PR #187 git по SSH уже есть, но путь `<курс>/<цепочка>` всегда ведёт в личный репозиторий участника (`pkg/git/git.go`, `ResolveRepo`), шаблон по SSH недоступен. Просьба к бэкенду — в mm-113, пункт «Шаблонный репозиторий цепочки заданий».
