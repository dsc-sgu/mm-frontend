# Создавать следующее задание через «Создать ещё»

## Делает

Даёт преподавателю после создания задания сразу начать следующее действием «Создать ещё», не закрывая рабочий контекст курса. Новое задание создаётся рядом с предыдущим, а повторяемые настройки остаются видимыми и редактируемыми, чтобы ускорение не спрятало ошибочно скопированный дедлайн или оценку.

## Готово, когда

- [ ] При добавлении нового блока задания открывается тот же редактор в боковой панели, что сделан в mm-41.
- [ ] После успешного создания доступно явное действие «Создать ещё».
- [ ] «Создать ещё» создаёт следующий блок задания сразу после только что созданного и сохраняет контекст этого места курса.
- [ ] Название и условие следующего задания очищаются.
- [ ] Дедлайн и максимальная оценка переносятся видимыми редактируемыми значениями; пользователь может изменить их до применения.
- [ ] Ни одно перенесённое значение не спрятано в свёрнутом разделе или в неявной предустановке.
- [ ] Отмена второго задания не удаляет и не откатывает уже созданное первое.
- [ ] Успешное создание обновляет документ курса и доступность отдельной страницы нового задания через один согласованный слой моков и запросов.
- [ ] Серия из нескольких заданий сохраняет правильный порядок блоков и уникальную идентичность каждого задания.
- [ ] Сценарий не добавляет смену цепочки заданий или шаблонного репозитория после открытия курса.
- [ ] Мок не моделирует конкурирующий черновик курса или конфликты публикации.
- [ ] Последовательность «создать → создать ещё → изменить перенесённые настройки → применить» проверена в настоящем приложении.

По итогам mm-180, комментарий от 2026-10-13T04:22:18Z «Спроектировать настройку Task и Task Groups» «Создать ещё» переносит больше, чем сказано здесь:

- **переносит:** Task Group, максимальную Grade, Deadline уровня Task, Task Opening Time;
- **не переносит:** переопределения сроков и маски путей;
- **очищает:** название, условие, вложения и аннотацию; Task Key предлагается заново.

Этот тикет заменит тикет спецификации «Настройка Task и Task Groups», которую пишут после цепочки прототипов mm-181 → mm-190 → mm-191.

### 2026-10-24T22:02:15Z · t3m8ch

К критерию «Моковая реализация не моделирует конкурирующий черновик курса или конфликты публикации». В открытом mm-backend PR #187 новое задание всегда создаётся в черновике блока автора: строка задания появляется сразу, студенты её не видят до публикации, а отмена черновиков её удаляет. «Создать ещё» тогда — несколько новых черновиков блоков, публикуемых одной кнопкой. Ключ задания проверяется только в виде курса автора, поэтому два преподавателя могут завести одинаковые ключи в одной цепочке (вопрос 10 комментария mm-113 про PR #187). Тикет заменит спецификация «Настройка задания» (mm-cey7q), модель — mm-34k14.
