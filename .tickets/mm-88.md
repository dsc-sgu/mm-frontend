# Согласовать frontend/backend contract редактирования course snapshots

## Parent

[Перевести course dashboard и редактирование курса на общий mock backend](https://github.com/dsc-sgu/mm-frontend/issues/78)

## What to build

Согласовать с backend owners transport и lifecycle contract persistent course snapshots до реализации MSW handlers и frontend clients. Основной источник фактов — [Backend snapshots, drafts, attempts, and frontend integration](https://github.com/dsc-sgu/mm-frontend/blob/a25a8ed9f8c485f5aaad5ba0beba4f7909a9cf63/docs/research/backend-snapshots.md).

## Acceptance criteria

- [ ] Зафиксировано сопоставление route slug и backend course UUID.
- [ ] Разделены course metadata, snapshot metadata, snapshot content и user preferences.
- [ ] Зафиксировано представление существующих frontend content blocks и resources в backend contract.
- [ ] Определены atomic mutations, autosave acknowledgement и допустимый debounce/coalescing.
- [ ] Определены semantics для new, restored, stale_conflict, 423 и 409.
- [ ] Согласована безопасная cancel semantics с проверкой session-bound lease.
- [ ] Решение записано в устойчивом документе или ADR и согласовано frontend/backend owners.
- [ ] Последующие MSW tickets могут реализовать contract без продуктовых догадок.

## Blocked by

- None (can start immediately).

## Уточнения из [«Спроектировать lifecycle Course Page Working Copy»](https://github.com/dsc-sgu/mm-frontend/issues/118#issuecomment-6090347912)

Frontend-сторона контракта выбрана, открытые вопросы к backend перенесены в [«Реестр frontend-вопросов к backend API»](https://github.com/dsc-sgu/mm-frontend/issues/113).

- Course Draft Snapshot личный: не больше одного на Teacher'а и Course. Course Editing Lease — один редактирующий Teacher на Course.
- Presentation metadata, resources, content и ссылки на Task входят в черновик и публикуются вместе с ним. Slug меняется отдельной мгновенной операцией вне черновика. Свойства Task в Course Page Working Copy не входят.
- Синхронизация фоновая и по состоянию: frontend строит операции блоков, metadata и resources сравнением Working Copy с последним подтверждённым состоянием черновика. При неизвестном исходе черновик перечитывается, idempotency keys операциям черновика не нужны (ADR 0002 в [PR #127](https://github.com/dsc-sgu/mm-frontend/pull/127)).
- Неизвестный исход публикации сверяется по id активного snapshot Course.
- Lease работает по протоколу Review Lease с клиентским `leaseId`.

Каноническим источником является решение по ссылке выше. Окончательную нарезку на implementation-тикеты определит [«Определить последовательность подготовки и выполнения рефакторинга»](https://github.com/dsc-sgu/mm-frontend/issues/69).

### 2026-10-11T12:04:04Z · t3m8ch

По решению [«Определить последовательность подготовки и выполнения рефакторинга»](https://github.com/dsc-sgu/mm-frontend/issues/69#issuecomment-6108811160) согласования с backend больше не блокируют frontend slices. Slices идут против MSW с рабочими допущениями из [«Реестр frontend-вопросов к backend API»](https://github.com/dsc-sgu/mm-frontend/issues/113), помеченными в handlers. Если ответ backend окажется другим, это отдельный тикет-исправление. Родительская цепочка «Перевести frontend с RAM-моков на fetch и MSW» закрыта как заменённая.
